# 小程序空状态与提示组件统一设计

## 目标

统一小程序中的空状态与上下文提示，让页面先说明当前状态，再引导用户执行该身份、该页面下最有价值的下一步；规则说明只在实际相关时出现。

## 组件边界

### AppEmpty

- 基于 Wot UI `wd-empty`。
- 支持语义图标、标题、说明、主要操作和紧凑模式。
- 只负责渲染，由页面传入文案和操作；组件不推断用户身份或业务路由。
- 列表、瀑布流、异步内容等通用容器透传空状态属性与操作事件。

### AppNotice

- 负责信息、提醒、警告和错误四类上下文说明。
- 支持图标、标题、正文、操作按钮与紧凑模式。
- 页面负责判断展示条件，避免无条件展示与当前状态无关的规则。

## 内容规则

1. 标题描述事实，例如“还没有收藏房源”，避免只写“暂无内容”。
2. 说明解释用户为什么会看到该状态，或完成主任务需要的前置条件。
3. 主操作必须对应当前页面和当前身份最有价值的下一步。
4. 空状态不重复展示规则提示；规则仅在相关数据或风险真实存在时出现。
5. 加载、错误、权限不足和业务空数据保持不同语义，不混用空状态。

## 收藏页

- 无收藏时使用 `no-collection` 图标，标题为“还没有收藏房源”，说明收藏用途，主操作为“去找房”。
- “去找房”切换至首页。
- 仅当收藏列表中存在已下架房源时显示“下架房源说明”，并说明可直接取消收藏。
- 没有下架房源时不展示额外提示。

## 全页面检查范围

- 检查 `AppEmpty`、`wd-empty`、`empty-text` 的所有使用位置。
- 检查页面内重复实现的 `notice`、`note`、`tip` 提示块。
- 优先替换列表级、页面级状态；媒体占位、字段空值和局部内容占位不强制使用页面空状态组件。
- 不纳入 Toast、表单字段校验和普通接口错误提示。

## 验证

- 为组件属性、事件和收藏页条件展示补充测试。
- 运行相关单测、全量前端测试、ESLint、`vue-tsc --noEmit` 和微信小程序构建。
- 在微信开发者工具中检查租客、中介与房东主要空状态的视觉层级和操作可达性。
