# 房源详情资料卡片重设计

## 目标

重新设计管理端房源详情页的资料卡片，提升信息层级和扫读效率。房源标签合并到资料卡片，不再占用右侧独立卡片；资料字段按业务语义分组，替代当前连续的边框表格。

本次仅调整房源详情页的只读展示，不修改后端接口、数据模型、编辑抽屉、顶部房源摘要、带看记录、租约记录和位置周边功能。

## 最终布局

资料卡片标题由“资料”调整为“房源资料”，卡片内部按以下顺序展示：

1. **对外描述**：直接展示描述正文，不再显示“房源介绍”标题；无内容时显示“暂无对外房源描述”。
2. **内部备注**：紧跟房源介绍，以一行弱化文字展示“内部备注：内容”，不再使用独立背景面板或嵌套容器；无内容时显示“暂无内部备注”。
3. **房源标签**：紧跟内部备注，不显示“房源标签”标题，直接展示可换行标签组。房源自身标签继续使用紫色，继承自楼栋的标签使用中性色；无标签时显示“暂无标签”。
4. **字段分组**：不显示“房源字段”总标题，直接进入业务分组网格，不再使用 `Descriptions` 边框表格。

资料卡片不重复放置编辑按钮，继续使用顶部摘要区现有的“编辑资料”入口。

## 字段分组

### 归属信息

归属信息占满整行，包含：

- 项目
- 楼栋 / 房号
- 房东
- 楼栋地址

项目、楼栋、房号和房东继续使用现有实体预览组件，保留可点击查看关联对象的交互。

### 房源属性

房源属性占满整行，在同一个网格中展示标准户型字段和房源 `extra` 中的动态字段。标准字段包括：

- 卫 / 厨 / 阳台
- 套内面积
- 朝向
- 装修

动态字段紧跟标准字段，沿用现有字段名格式化和值格式化逻辑。数组继续显示为标签，对象继续以格式化 JSON 展示；长文本、对象或较长数组占满分组宽度。没有动态字段时仅展示标准字段。

## 状态处理

资料卡片不展示 `is_active` 对应的“档案状态”。该字段与房态、发布状态属于不同维度，且停用时顶部摘要区已显示“已停用”，在资料卡中重复展示会增加理解成本。

顶部现有的房态和发布状态展示保持不变。

## 页面整体调整

- 删除右侧独立的“房源标签”卡片。
- 右侧继续只展示“位置与周边”卡片。
- 左侧资料、带看记录和租约记录的排列保持不变。
- 归属信息和房源属性分别占满整行，分组内部使用两列字段网格。
- 窄屏下所有分组退化为单列，标签和字段值允许自然换行。

## 视觉规则

- 仅保留资料卡片这一层主要容器。
- 字段分组使用主题色派生的 1px 轻量边框、圆角和内边距建立层级，保持卡片背景色，不嵌套新的 Ant Design `Card`。
- 分组标题使用次要文字色，字段标签弱化，字段值保持主要文字色。
- 内部备注使用弱化文字色，不使用大面积灰色背景。
- 标签与备注之间保持紧凑间距，使“介绍 → 备注 → 标签”形成连续阅读流。
- 样式继续使用 `antd-style` 和主题 token，避免写死主题相关颜色。

## 数据与异常状态

本次不增加请求。资料介绍、备注、标签、关联实体和扩展字段继续来自现有房源详情响应。

- 关联对象缺失时沿用当前占位逻辑，例如无房东显示“待补房东”。
- 介绍、备注、标签为空时显示明确的弱化占位内容。
- 加载失败、无效房源和跨组织访问状态保持现有行为。

## 验收范围

- 房源标签位于资料卡片内，并紧跟内部备注。
- 资料卡片内不显示“房源介绍”“房源标签”“房源字段”三个重复标题。
- 页面不再出现独立“房源标签”卡片。
- 内部备注不再使用独立背景面板。
- 资料字段按“归属信息、房源属性”分组展示，标准户型字段与动态扩展字段位于同一个分组。
- 资料卡片不再展示“档案状态”。
- 项目、楼栋、房号和房东的实体预览交互保持可用。
- 无介绍、无备注、无标签和无扩展字段时布局正常。
- 桌面端和窄屏下均不存在字段溢出或不可读的嵌套布局。

## 验证方式

- 更新房源详情页现有组件测试，验证介绍、备注、标签和字段分组的顺序。
- 验证标签位于“房源资料”卡片内，且不存在独立标签卡片。
- 验证资料卡片中不出现“档案状态”。
- 验证自身标签与继承标签仍使用不同视觉样式。
- 运行房源详情页相关 Vitest，并执行 TypeScript 检查或管理端 lint。
