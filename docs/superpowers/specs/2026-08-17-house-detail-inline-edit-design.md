# 房源详情页原位编辑设计

## 背景

管理端房源详情页目前使用展示态页面承载房源摘要、房源资料、带看记录和租约记录，修改房源时需要点击右上角“编辑资料”，进入包含基础资料、展示说明和媒体资料的完整抽屉。

完整抽屉适合批量维护房源，但修改挂牌租金、面积、楼层等单个高频字段时路径偏长。房源运营人员希望在详情页中将鼠标移到字段上后看到编辑图标，点击后直接在原文字附近完成修改，同时继续保留完整编辑抽屉处理低频和复杂资料。

## 目标

- 桌面端为指定高频字段提供可发现、低干扰的原位编辑入口。
- 简单文本和数字字段直接替换原文字，复杂选择字段使用紧邻字段的紧凑编辑区。
- 支持鼠标、键盘、明确按钮和点击外部等常用保存方式。
- 每次只提交被修改字段的最小 PATCH 参数，成功后同步刷新页面所有相关展示。
- 保存失败时保留用户草稿并在字段附近提供可操作的错误反馈。
- 保留现有“编辑资料”抽屉，继续承载完整资料维护。

## 非目标

- 触屏设备本期不提供原位编辑；手机和平板继续使用完整编辑抽屉。
- 不将描述、标签、内部备注、媒体、自定义字段、房态、楼栋、卫、厨、阳台纳入首版原位编辑。
- 不删除或降低现有“编辑资料”按钮的可见性。
- 不修改房源后端模型、更新接口、OpenAPI 生成文件、依赖或多语言文件。
- 不将本功能抽象为全站通用编辑框架；首版组件保持为房源详情页面私有能力。

## 已选方案

采用按字段复杂度混合的原位编辑方式：

- 房号、租金、押金、面积、楼层等简单字段在原文字位置直接切换为输入控件。
- 房东、户型、朝向、装修等需要搜索、组合输入或选择选项的字段，在原字段内展开紧邻文字的紧凑编辑区。
- 桌面端默认不显示编辑图标；鼠标 Hover 或键盘聚焦字段时才显示铅笔图标。
- 不使用统一浮层编辑卡，避免遮挡内容；也不强求所有复杂控件塞入原文字宽度，避免布局挤压。

## 字段范围与权威编辑位置

同一业务字段只提供一个原位编辑入口。其他重复展示只消费更新后的房源缓存，不出现第二个编辑图标。

| 展示区域 | 字段 | PATCH 参数 | 编辑器 | 清空规则 | 保存后的同步展示 |
| --- | --- | --- | --- | --- | --- |
| 顶部摘要 | 挂牌租金 | `asking_rent` | 带人民币语义的数字输入 | 允许，发送 `null` | 顶部租金与其他消费房源缓存的区域 |
| 顶部摘要 | 押金 | `deposit_amount` | 带人民币语义的数字输入 | 允许，发送 `null` | 顶部押金 |
| 顶部摘要 | 户型 | `bedrooms`、`living_rooms` | “室”“厅”两个非负整数输入 | 两项分别允许清空 | 顶部户型；继续通过共享格式化逻辑展示“单间”等文本 |
| 顶部摘要 | 建筑面积 | `area` | 带 `㎡` 后缀的数字输入 | 允许，发送 `null` | 顶部面积 |
| 顶部摘要 | 楼层 | `floor` | 整数输入 | 允许，发送 `null` | 顶部楼层 |
| 房源资料 / 归属信息 | 房号 | `room_number` | 单行文本输入 | 不允许清空 | “楼栋 / 房号”字段与页面标题中的房号 |
| 房源资料 / 归属信息 | 房东 | `landlord_id` | 可搜索、可清空的房东选择器 | 允许，发送 `null` | 房东信息及发布完整性判断 |
| 房源资料 / 房源属性 | 朝向 | `orientation` | 可清空枚举选择器 | 允许，发送 `null` | 朝向文本及映射标签 |
| 房源资料 / 房源属性 | 装修 | `decoration` | 可清空枚举选择器 | 允许，发送 `null` | 装修文本及映射标签 |

页面标题包含项目、楼栋和房号。标题中的房号只随 `room_number` 保存结果更新，不提供第二个编辑入口。楼栋链接、房源预览入口与编辑按钮保持各自独立的点击目标。

“卫 / 厨 / 阳台”继续通过完整编辑抽屉修改，不随顶部“户型”编辑器提交。

## 交互状态

每个字段具有以下状态：

```text
展示态 → Hover/聚焦态 → 编辑态 → 保存中 → 保存成功 → 展示态
                                 ↘ 保存失败 → 编辑态
                                 ↘ 取消 → 展示态
```

### 展示与进入编辑

- 仅在支持 Hover 且具有精确指针的桌面环境启用原位编辑。
- 鼠标移入字段或键盘 `Tab` 聚焦字段时显示铅笔图标。
- 点击字段文字、字段容器或铅笔图标均可进入编辑态；字段内已有链接时，链接仍执行预览或导航，编辑图标使用独立点击目标。
- 进入编辑态时根据当前服务端值初始化草稿并自动聚焦主要控件。
- 任意时刻最多只有一个字段处于编辑态。

### 保存与取消

- `Enter`、点击勾号或点击编辑器外部触发保存。
- `Esc` 或点击叉号取消编辑，丢弃草稿并恢复当前缓存值。
- 点击另一个可编辑字段时，先保存当前字段；保存成功后打开目标字段。
- 当前字段校验失败或接口保存失败时，不打开目标字段。
- 多控件的户型编辑器在任意子控件中按 `Enter` 都提交室、厅两个值。
- 下拉选择器内部的选项点击、搜索和清空不视为点击编辑器外部。
- 打开完整“编辑资料”抽屉前先结束当前原位编辑；存在合法改动时先保存，无改动时直接关闭原位编辑。

### 保存反馈

- 保存中禁用当前编辑器、勾号和其他原位编辑入口，并显示局部加载状态。
- 不做乐观更新；接口成功后才将服务端响应写入 React Query 缓存。
- 成功后关闭编辑器，并在字段旁短暂显示绿色勾号。
- 原位编辑不连续弹出全局“房源已更新”消息；完整编辑抽屉仍保留现有成功提示。

## 组件边界

新增页面私有的 `InlineEditableField` 组件，职责限定为单个字段的通用交互外壳：

- 展示态、Hover/聚焦态、编辑态、保存中与失败态的切换。
- 草稿初始化、焦点管理、键盘事件、外部点击、勾号和叉号。
- 局部加载、成功标记和错误信息展示。
- 调用由页面传入的校验与提交函数，不理解房源字段名称或 API 参数。

组件接口需要表达以下能力：

```text
字段标识
当前展示内容
当前原始值
编辑器渲染函数
草稿校验与规范化函数
提交函数
是否为当前活动字段
是否禁用
可访问性标签
```

房源详情页负责业务层逻辑：

- 维护唯一的 `activeInlineField`。
- 为各字段选择输入框、数字框、组合编辑器或选择器。
- 将空字符串转换为 `null`，将数字草稿转换为接口需要的数值。
- 组装最小 PATCH 参数。
- 复用已有枚举数据；仅在打开房东编辑器时按需加载房东列表。
- 协调原位编辑与完整编辑抽屉的互斥关系。

现有页面已经通过 `houseApi.patchHouse(houseId, payload)` 更新房源。实现时将“执行 PATCH 并更新房源缓存”的部分收敛为共享能力，再分别由完整抽屉和原位编辑配置不同的成功反馈，避免每次原位保存都触发现有全局提示。

## 数据流

```mermaid
flowchart LR
    A["Hover 或键盘聚焦字段"] --> B["显示编辑图标"]
    B --> C["点击进入编辑态"]
    C --> D["初始化字段草稿"]
    D --> E["用户修改并触发保存"]
    E --> F["前端校验与值规范化"]
    F -->|失败| G["字段下显示错误并保留草稿"]
    F -->|通过| H["PATCH /api/house/houses/{id}/"]
    H -->|失败| G
    H -->|成功| I["写入 React Query 房源缓存"]
    I --> J["页面所有相关展示同步刷新"]
    J --> K["短暂成功标记后回到展示态"]
```

每次请求只提交当前字段所需参数。例如：

```json
{ "area": "42.00" }
```

户型作为一个编辑单元，同时提交两个字段：

```json
{ "bedrooms": 1, "living_rooms": 0 }
```

接口返回完整 `HouseOut` 后直接更新现有详情查询缓存，因此页面标题、摘要、发布完整性判断和其他依赖房源数据的组件使用同一份服务端结果。

## 校验与规范化

| 字段 | 前端规则 |
| --- | --- |
| 房号 | 去除首尾空格后必填，最大 64 个字符 |
| 挂牌租金 | 可空；非空时为大于等于 0、最多两位小数的十进制数 |
| 押金 | 可空；非空时为大于等于 0、最多两位小数的十进制数 |
| 建筑面积 | 可空；非空时为大于等于 0、最多两位小数的十进制数 |
| 楼层 | 可空；非空时为整数，允许负数以表达地下楼层 |
| 室 | 可空；非空时为非负整数 |
| 厅 | 可空；非空时为非负整数 |
| 房东 | 只能提交当前组织可选择的房东 ID，允许清空 |
| 朝向 | 只能提交页面枚举中的合法值，允许清空 |
| 装修 | 只能提交页面枚举中的合法值，允许清空 |

未修改的草稿不发送请求，直接退出编辑态。可空字段清空时显式发送 `null`，不发送空字符串。

户型保存后的展示必须继续复用 `housePrimaryLayoutText`：当 `bedrooms === 1` 且 `living_rooms === 0` 时显示“单间”；当两者均为空时使用现有空值展示；不得在原位编辑组件中复制一套户型格式化规则。

## 错误处理

- 客户端校验失败时不发送请求，在当前字段下显示明确错误并保持焦点。
- 接口失败时编辑器保持打开，草稿不丢失，缓存和展示值不被覆盖。
- 优先展示接口返回的业务错误；无法提取具体信息时显示“保存失败，请稍后重试”。
- 当接口返回可识别的同楼栋房号重复错误时，保持房号编辑器打开并提示用户更换房号；无法识别具体原因时使用通用保存失败提示。
- 房东列表加载失败时保留当前房东展示，并在编辑区提供重试入口；不自动将房东清空。
- 枚举加载失败时朝向和装修保持只读，不展示不可用的空选择器。
- 保存过程中禁止再次提交或切换字段，避免乱序响应覆盖较新的值。
- 用户在保存中打开完整编辑抽屉时，等待当前请求结束；成功后打开抽屉，失败时停留在当前字段。

## 触屏、权限与可访问性

- 使用“支持 Hover 且为精确指针”作为启用条件。触屏环境不展示原位编辑图标，也不通过点击文字进入编辑。
- 手机和平板始终保留右上角“编辑资料”按钮，使用现有完整抽屉。
- 不引入新的权限模型。原位编辑入口与现有“编辑资料”能力保持一致；无编辑能力时字段保持纯展示，后端接口继续作为最终权限边界。
- 字段容器或编辑按钮可以通过 `Tab` 聚焦；聚焦样式与 Hover 状态同等清晰。
- 编辑按钮提供具体 `aria-label`，例如“编辑挂牌租金”“编辑房东”。
- 进入编辑态后焦点落到主要输入控件；保存或取消后焦点返回原字段。
- 错误文本与当前编辑器建立可访问性关联，并通过合适的 live region 告知保存失败。
- 图标不是唯一状态提示；编辑态、加载态、失败态和成功态同时使用边框、文字或状态标记表达。

## 与现有页面的关系

- “编辑资料”按钮、抽屉标签页、媒体即时保存和发布/下架流程保持不变。
- 打开抽屉后不显示任何原位编辑器，避免同时存在两套草稿。
- 房源详情现有 React Query 查询键继续作为房源详情的唯一缓存来源。
- 原位保存成功后仍失效或更新收藏列表等现有相关缓存，不能绕过当前 `patchHouse` 成功后的关联刷新行为。
- 房东选择继续使用当前组织下有效且具有房东角色的联系人。
- 本功能不改变楼栋地址、项目、楼栋和房态的编辑入口。

## 测试策略

### `InlineEditableField` 组件测试

- 默认展示态不显示编辑图标；Hover 和键盘聚焦后显示。
- 点击文字或图标进入编辑态并聚焦控件。
- `Enter`、勾号和点击外部触发保存。
- `Esc` 和叉号取消，恢复当前值且不调用提交函数。
- 未修改时退出编辑不发请求。
- 校验失败或提交失败时保留草稿并显示错误。
- 保存中禁用重复提交和字段切换。
- 保存或取消后焦点返回原字段。

### 房源详情集成测试

- 桌面环境渲染 9 个指定原位编辑入口，未纳入范围的字段不出现入口。
- 挂牌租金、押金、建筑面积、楼层和房号提交正确的单字段 PATCH 参数。
- 户型同时提交 `bedrooms` 与 `living_rooms`，保存 `1 / 0` 后展示“单间”，保存 `1 / 1` 后不展示“单间”。
- 房东选择器按需加载选项并提交 `landlord_id`；清空时提交 `null`。
- 朝向和装修使用现有枚举值并正确更新映射文本。
- 房号保存后页面标题和“楼栋 / 房号”字段同步更新。
- 同时只能打开一个原位编辑器；点击新字段时先完成当前字段保存。
- 服务端失败时页面仍展示旧缓存值，当前编辑器保留草稿。
- 打开“编辑资料”抽屉时正确结束当前原位编辑，抽屉原有保存行为不回归。
- 触屏环境不渲染原位编辑入口，完整编辑按钮仍可用。

无需新增后端测试，因为本功能不改变后端接口或模型。实现阶段应运行房源详情相关 Vitest；如共享更新逻辑发生调整，需要同时覆盖抽屉保存和关联缓存刷新行为。

## 验收标准

- 桌面用户将鼠标移到指定字段时才看到编辑图标，页面默认展示保持简洁。
- 用户能够在原字段附近完成 9 个指定编辑单元的修改，无需打开完整抽屉。
- `Enter`、勾号、点击外部、`Esc` 和叉号行为符合设计，且任意时刻只有一个编辑器活动。
- 保存成功后所有重复展示使用服务端返回值同步更新，不需要刷新页面。
- 保存失败不会覆盖旧展示值或丢失用户草稿。
- 触屏设备不出现原位编辑入口，现有完整编辑流程可正常使用。
- 原有房源详情、完整编辑抽屉、媒体编辑、发布判断、收藏关联缓存及户型“单间”展示规则不发生回归。
