# 管理端单元测试提速与精简设计

## 目标

将管理端默认 Vitest 套件从约 6 分 33 秒压缩到可在日常开发中快速反馈的范围，同时保留对关键租赁业务流程、权限边界、URL 状态和请求载荷的回归保护。

## 基线与根因

2026-09-05 的完整运行共执行 133 个测试文件、874 条用例，墙钟耗时 393.23 秒。测试逻辑累计耗时 1337.01 秒，说明已启用并行，但少量超大页面级测试文件仍决定了收尾时间：

- `domain-list-pages.test.tsx`：153 条用例，约 390 秒；在单一文件内覆盖多个列表页面和大量相近状态。
- `houses/detail.test.tsx`：45 条用例，约 314 秒；重复渲染包含真实表单、抽屉和远程选项的详情页。
- `houses/new.test.tsx`：21 条用例，约 118 秒；多个测试重复执行四步建档向导。
- `notification-dispatches/index.test.tsx`：10 条用例，约 74 秒；每例均重复完整表格与编辑器初始化。

这些套件同时包含关键交互断言与低价值的文案、布局、历史实现痕迹和相近状态组合断言。后者会重复触发页面初始化和异步轮询，却不能有效扩大业务风险覆盖。

## 方案

1. 保留页面级测试中的最短关键路径：创建或更新、权限与禁用状态、URL 参数读写、关键的失败/恢复分支，以及最终 API 请求载荷。
2. 删除只验证静态文案、元素摆放、旧文案不存在、以及由同一状态机已覆盖的重复参数组合。对参数白名单/黑名单继续使用单个参数化测试，而不为每个展示分支重复渲染页面。
3. 将能脱离页面渲染验证的纯规则（如 URL 归一化、字段载荷转换、发布条件）放在现有的逻辑测试文件中；不新增快照测试，也不以降低全局超时掩盖问题。
4. 对保留的重型页面测试抽取本文件内的渲染与导航辅助函数，复用等待条件，并在测试中 mock 与断言无关的重型子组件或异步数据源。页面自身的用户可见行为仍通过 Testing Library 验证。
5. 本次不修改业务代码、生成 API 客户端、依赖版本或默认测试超时。现有 17 条失败用例将作为精简后的验证基线分别复现；仅移除明确属于低价值覆盖的失败测试，不借由删除掩盖关键行为回归。

## 验收标准

- 被保留的测试涵盖租赁列表、房源新建、房源详情和通知分发的关键业务路径。
- 删除的测试均满足“仅展示细节、重复状态组合或历史文案”至少一项，并且不承担唯一的请求载荷、权限、URL 状态或错误恢复验证。
- 受改动文件的测试可独立执行，完整套件的实际墙钟耗时明显低于当前基线；最终报告提供新的用例数量、耗时以及通过/失败明细。
- 不修改产品运行时代码与 package 文件。
