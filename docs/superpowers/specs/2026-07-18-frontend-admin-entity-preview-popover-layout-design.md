# 管理端实体悬浮预览布局优化设计

## 背景

管理端现有 `EntityPreview` 已统一房源、小区、楼栋、联系人、租约和带看等实体的悬停预览、详情跳转、异步加载和错误隔离。当前六类成功态面板普遍采用固定 `330px` 或 `340px` 宽度的纵向 `Space + Descriptions` 布局，图片、标题、状态和字段依次向下堆叠。

该结构能承载基础信息，但存在以下问题：

- 不同面板宽度、间距和信息层级不一致。
- Skeleton 固定为 `320px`，加载前后会发生宽度变化。
- 有图和无图时媒体区域直接出现或消失，卡片高度与视觉重心不稳定。
- 单列 `Descriptions` 对完整信息的空间利用率较低，长卡片容易超出视口。
- 房源预览内嵌楼栋预览，可能形成嵌套 Popover，增加跳动和遮挡风险。
- 同一 Panel 同时供 Popover 与只读 Drawer 使用，缺少明确的展示场景契约。

本次设计只优化悬浮 Popover 的布局。只读 Drawer 的成功态布局暂不调整。

## 目标

- 悬浮卡尽可能完整地展示现有详情接口已经提供的信息，减少为了确认基础资料而进入详情页的次数。
- 图片类实体与纯信息类实体采用不同宽度，兼顾信息完整度和屏幕占用。
- 六类实体共享稳定的视觉骨架，同时保留各实体独立决定字段和内容组织的能力。
- 消除加载、无图和长文本造成的明显布局跳变。
- 保持现有数据请求、缓存、悬停延迟、键盘操作和详情导航行为。

## 非目标

- 不调整只读 Drawer 的视觉布局。
- 不新增或修改后端接口。
- 不向业务列表传入详情快照、请求函数或预览字段。
- 不要求六类实体使用完全相同的字段集合。
- 不把悬浮卡改造成可编辑界面。

## 选定方向

采用“顶部媒体分区卡”：

- 图片类实体先展示完整宽度的媒体区，再展示身份摘要、核心信息和补充信息。
- 纯信息类实体省略媒体区，以头像或业务身份摘要开场，再进入分区内容。
- 短字段使用两列事实网格，长字段使用单列标签和值，兼顾信息密度与可读性。
- 卡片底部提供“点击查看详情”的非按钮式提示，整体现有链接仍是详情入口。

近似宽度：

| 实体 | 类型 | Popover 宽度 |
| --- | --- | --- |
| 房源 | 图片实体 | `460px` |
| 小区 | 图片实体 | `460px` |
| 楼栋 | 图片实体 | `460px` |
| 联系人 | 信息实体 | `390px` |
| 租约 | 信息实体 | `390px` |
| 带看 | 信息实体 | `390px` |

宽度是桌面端目标值。Popover 仍需受可用视口宽度约束，避免在窄窗口中溢出。

## 组件结构

### 展示场景契约

扩展 `EntityPreviewPanelProps`：

```ts
interface EntityPreviewPanelProps {
  id: number;
  variant: 'popover' | 'drawer';
}
```

- `EntityPreview` 向注册面板传入 `variant="popover"`。
- `EntityPreviewDetailDrawer` 向注册面板传入 `variant="drawer"`。
- 本次仅新增或调整 `popover` 成功态布局；`drawer` 继续使用现有成功态结构。

显式场景参数避免继续让固定宽度面板隐式适配两种差异很大的宿主，也为后续独立优化 Drawer 留出稳定接口。

### 注册表宽度

实体注册表增加 `popoverWidth`，由公共内核在 Panel 加载前确定容器宽度：

```ts
house: {
  Panel: lazy(() =>
    import('./entities/house/HousePreviewPanel').then(
      ({ HousePreviewPanel }) => ({ default: HousePreviewPanel }),
    ),
  ),
  getHref: (id) => `/property-rental/houses/${id}`,
  popoverWidth: 460,
}
```

注册表负责声明展示能力和导航信息，不负责业务字段和请求。Skeleton、错误态和成功态都读取同一个目标宽度，避免加载前后跳变。

### 公共视觉骨架

新增公共成功态骨架，建议拆分为以下小组件：

- `EntityPreviewCardShell`：负责目标宽度、最大高度、滚动区域和底部详情提示。
- `EntityPreviewMedia`：负责封面、无图占位和媒体加载失败降级。
- `EntityPreviewHeader`：负责主标题、副标题、状态和核心金额区域。
- `EntityPreviewSection`：负责分区标题和内容间距。
- `EntityPreviewFactGrid`：负责两列短字段。
- `EntityPreviewFieldList`：负责地址、配套、备注等长字段。

这些组件只表达布局和视觉语义，不导入任何业务接口、实体类型或字段转换函数。实体 Panel 继续决定是否使用媒体区、展示哪些字段以及字段顺序。

## 布局规则

### 图片实体

房源、小区和楼栋采用以下顺序：

1. 等高顶部媒体区。
2. 主标题、副标题、状态和核心金额或业务标签。
3. “核心信息”分区，两列展示短字段。
4. “补充信息”分区，单列展示长字段。
5. 底部详情提示。

媒体缺失或加载失败时仍保留等高占位，显示实体类型图标和“暂无图片”，避免卡片整体上移。

### 信息实体

联系人、租约和带看采用以下顺序：

1. 头像、房源标题或客户身份等摘要区。
2. 状态、金额和关键业务标签。
3. “核心信息”分区。
4. 可选的“补充信息”分区。
5. 底部详情提示。

联系人头像使用姓名首字作为稳定占位，不引入新的头像数据依赖。

### 长内容与视口

- 地址、配套和备注允许正常换行，不使用单行省略隐藏关键信息。
- 图片实体媒体区的桌面端目标高度为 `148px`。
- 卡片最大高度为 `min(640px, calc(100vh - 32px))`；超过后只让核心信息和补充信息区域滚动，媒体、摘要和底部提示保持在滚动区之外。
- 顶部摘要和底部提示保持可辨识，不因长备注无限拉长整个 Popover。
- Popover 实际宽度为注册宽度与 `calc(100vw - 32px)` 的较小值；可用宽度不足 `520px` 时，内容网格退化为单列。

## 各实体字段组织

本次只重组现有详情数据，不要求新增接口字段。

### 房源

- 媒体：房源封面或无图占位。
- 摘要：房源名称、地址、租金、房态和发布状态。
- 核心信息：户型、面积、所属楼栋、房东。
- 补充信息：接口已经提供且适合预览的配套、标签或备注；字段缺失时不制造空白行。

### 小区

- 媒体：小区封面或无图占位。
- 摘要：展示名称、物业类型和启停状态。
- 核心信息：省、市、区等区域信息。
- 补充信息：详细地址。

### 楼栋

- 媒体：楼栋封面或无图占位，兼容当前工作区正在增加的楼栋图片能力。
- 摘要：楼栋名称和启停状态。
- 核心信息：所属小区、楼层、地下层数和建成年份。
- 补充信息：电梯情况和详细地址。

### 联系人

- 摘要：姓名首字头像、姓名、手机号和启停状态。
- 核心信息：角色。
- 补充信息：邮箱和备注。

### 租约

- 摘要：房源、租客、月租和租约状态。
- 核心信息：租期、押金和付款日。
- 补充信息：合同文件数量。

### 带看

- 摘要：客户、房源、带看状态和签约状态。
- 核心信息：联系人和预约时间。
- 补充信息：实际带看时间和备注。

## 交互与数据流

交互链路保持不变：

```text
业务页面实体文字
  → EntityPreview 控制 hover / focus
  → 200ms 后打开 Popover
  → 按注册表宽度渲染稳定 Skeleton
  → 延迟加载实体 Panel，传入 id + popover variant
  → Panel 使用现有详情接口和 React Query 查询键
  → 成功后渲染分区卡
  → 点击原实体链接进入详情承载页
```

继续保留：

- 查询键 `['entity-preview', orgSlug, entityType, id]`。
- `staleTime` 一分钟和 `gcTime` 十分钟。
- 仅打开时挂载 Panel，关闭后卸载 Panel 但保留查询缓存。
- hover、focus、Escape、无有效 ID 时退化为普通文本。
- 错误边界只隔离当前实体预览。

Popover 成功态内不再嵌套其他实体的 Popover。关联实体可以显示为普通文本或普通详情链接；Drawer 场景暂时保持现有行为。

## 加载与错误状态

- Skeleton 根据注册表中的 `popoverWidth` 渲染，并模拟媒体区、摘要区和字段区，降低内容出现时的视觉跳变。
- 403、404、通用失败和重试状态继承相同目标宽度。
- 媒体请求失败只降级媒体占位，不使整个详情请求进入错误态。
- 工作区或组织未就绪时继续遵循现有 Query `enabled` 条件。

## 测试范围

遵循最小必要测试原则：

- 公共内核测试注册表宽度传递、`variant="popover"` 和稳定 Skeleton。
- Drawer 测试 `variant="drawer"`，锁定本次不改变其场景契约。
- 每个实体面板测试 Popover 成功态的关键字段和场景宽度。
- 图片实体覆盖有图、无图和图片加载失败的占位行为。
- 长内容覆盖换行和最大高度滚动容器。
- 房源 Popover 覆盖关联楼栋不再创建嵌套 Popover。
- 保留现有 403、404、网络错误和重试测试。

## 验收标准

- 六类实体悬浮卡均使用统一的顶部摘要和分区视觉语言。
- 房源、小区和楼栋目标宽度约为 `460px`；联系人、租约和带看约为 `390px`。
- Skeleton、错误态和成功态打开过程中没有明显横向跳动。
- 图片缺失不会改变卡片基本结构。
- 当前预览字段尽可能完整呈现，长文本可通过卡片内部滚动查看。
- Popover 内不出现第二层实体 Popover。
- 只读 Drawer 的成功态布局不因本次改动发生视觉变化。
- 现有请求、缓存、悬停延迟、键盘操作和详情导航行为保持可用。
