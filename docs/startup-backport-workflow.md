# 回灌 `startup` 分支流程

本文用于说明如何把 `main` 中已经验证为“通用能力”的改动，安全地回灌到 `startup` 模板分支。

## 核心原则

`startup` 不是 `main` 的镜像分支。  
回灌时不要直接把 `main` 整体合并到 `startup`，而是只同步那些确认适合未来新项目复用的改动。

推荐原则：

- 不使用 `git merge main`
- 优先使用 `git cherry-pick`
- 宁可少回灌，也不要把业务污染带进模板

## 什么改动适合回灌

通常适合回灌到 `startup` 的改动包括：

- 通用基础设施优化
- 认证、权限、组织、多租户等底层能力增强
- 通用页面壳子、基础 UI 骨架
- 测试基建、开发体验、工程配置改进
- 对未来大多数项目都成立的抽象或默认实现

通常不适合回灌的改动包括：

- 当前项目业务流程
- 当前项目品牌、文案、导航结构
- 客户特有逻辑与第三方对接
- 临时兼容逻辑
- 只对当前项目成立的数据结构设计

## 回灌前判断

在准备回灌前，先问三个问题：

1. 明天新开一个项目，这个改动还需要吗？
2. 去掉当前项目背景之后，这个改动还成立吗？
3. 这个改动会不会给模板带来额外业务包袱？

只要有一个答案是否定的，就先不要回灌。

## 标准流程

### 1. 在 `main` 上确认候选提交

先在 `main` 中找出真正要回灌的提交，尽量确保这些提交只包含“通用能力”。

建议命令：

```bash
git log --oneline
```

如果通用能力和业务代码混在同一个提交里，优先先在 `main` 整理提交边界，再回灌。

### 2. 进入 `startup` worktree

推荐直接在 `startup` 专用 worktree 中操作：

```bash
cd /Users/lan/Project/django/linkcloud-space/.worktrees/startup
git status --short --branch
git pull origin startup
```

开始前要求：

- 当前位于 `startup` 分支
- 工作区干净
- 已拉取远程最新 `startup`

### 3. 挑选提交回灌

使用 `cherry-pick` 把 `main` 中确认通用的提交带过来：

```bash
git cherry-pick <commit_sha>
```

如果有多个独立提交：

```bash
git cherry-pick <sha1> <sha2> <sha3>
```

不推荐一上来就挑一大串提交。更稳的做法是一次挑一个或一组强相关提交。

### 4. 处理冲突

如果发生冲突：

- 先按“模板优先保持纯净”的原则处理
- 业务特有代码不要为了省事一起带进来
- 必要时在 `startup` 上做一次轻量清理提交

处理完成后继续：

```bash
git add <resolved_files>
git cherry-pick --continue
```

### 5. 做模板纯净性检查

回灌完成后，重点检查这些内容是否被误带入：

- 当前项目名称
- 当前项目品牌文案
- 当前项目导航和页面入口
- 客户特有配置
- 与当前项目强绑定的接口或模型

建议命令：

```bash
git diff origin/startup
```

如果发现混入了项目专属内容，先在 `startup` 修干净，再进入下一步。

### 6. 运行基础验证

至少执行：

```bash
just test
just lint
```

如果这次回灌影响了启动链路、配置链路或前端壳子，再补充：

```bash
just start
```

验证目标不是证明“当前项目功能正常”，而是证明“模板分支仍然是可启动、可开发、可复用的”。

### 7. 推送远程

确认无误后推送：

```bash
git push origin startup
```

## 推荐提交习惯

为了让以后回灌更轻松，建议在 `main` 上开发时就保持以下习惯：

- 通用能力和业务定制分开提交
- 一个提交只解决一类问题
- 提交信息尽量清楚表达用途

这样后续回灌时，你基本只需要挑选通用提交，而不用二次拆分。

## 不推荐的做法

- 不要直接 `merge main` 到 `startup`
- 不要把“可能以后有用”的业务代码顺手带进去
- 不要在未验证前就推送 `startup`
- 不要在 `startup` 上做大规模无关重构

## 回灌完成的标志

满足以下条件后，可以认为一次回灌完成：

- 目标提交已进入 `startup`
- 模板纯净性检查通过
- 基础验证通过
- 已推送到远程 `startup`
