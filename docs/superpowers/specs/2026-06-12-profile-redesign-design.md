# 个人中心重设计方案

## 背景

当前后台个人中心混合了承载导航、状态总览、资料编辑和安全入口的多种职责，导致用户进入页面后需要先判断“这里到底是入口页、工作台还是表单页”。这会放大认知成本，也让“修改个人资料”这条最常见路径变得不够直接。

本次重设计不继承此前的导航和排版思路，重新把个人中心定义为一张以资料维护为主的编辑页。

## 目标

1. 让用户打开个人中心后立即进入“个人资料页”的心智，而不是进入一个设置导航页。
2. 让基础资料维护形成单条、顺滑、从上到下的编辑路径。
3. 让安全设置、修改密码、消息提醒保留为独立二级页，但在主页上有清晰入口。
4. 降低视觉噪音，减少无意义的卡片、统计块、目录块和伪工作台结构。

## 非目标

1. 不在本轮重做安全设置内部的具体业务流程。
2. 不改变后端用户资料接口与安全接口的职责边界。
3. 不把所有账户相关功能强行塞进同一张超长表单。

## 用户体验定义

新版个人中心更像“资料编辑页”，而不是“账户工作台”或“多标签设置中心”。

用户进入 `/profile` 时，默认看到的是自己的资料头部和一张连续长页。页面的主流程只有一个：查看并维护基础资料。页面底部再提供通向安全设置、修改密码和消息提醒的入口，让用户在需要时进入专项页面。

## 页面结构

`/profile` 采用单列长页面，从上到下分为五段。

### 1. 资料头部

用于确认“这是我的资料页”。包含：

- 头像
- 姓名
- 邮箱
- 手机号状态
- 主动作按钮 `编辑资料`

这一段只提供身份确认和主动作，不承载目录、统计面板或模块导航。

### 2. 公开资料

放用户最常修改的资料：

- 头像
- 姓
- 名

这是整页最靠前的可编辑区块，优先服务“我来改个人资料”的主任务。

### 3. 联系与身份信息

放用户会频繁查看但不一定能编辑的信息：

- 邮箱
- 手机号
- 用户名
- 认证状态

这一段以查看和确认状态为主，避免让用户误以为这些绑定信息都能直接编辑。

### 4. 系统偏好

放和日常使用相关的轻量偏好项：

- 时区

它仍在主长页中，但视觉上比公开资料更轻，强调“使用偏好”而不是“身份字段”。

### 5. 账户相关入口

主资料页底部只保留三个专项入口卡片：

- 安全设置
- 修改密码
- 新消息提醒

每张卡片展示一句状态摘要和一个进入按钮，用来引导用户进入二级页，而不是在主资料页继续展开复杂配置。

## 交互模型

### 查看态与编辑态

`/profile` 默认进入整页查看态。

查看态下：

- 可编辑字段按资料信息展示，不渲染为输入框。
- 页面顶部只有一个主按钮 `编辑资料`。
- 联系与身份信息保持稳定、可扫描的展示样式。

点击 `编辑资料` 后，页面进入整页编辑态。

编辑态下：

- 公开资料区切换为可编辑输入态。
- 系统偏好区切换为可编辑输入态。
- 头像上传和移除操作出现。
- 联系与身份信息继续保持只读。
- 页面底部出现 `取消` 和 `保存资料`。

不采用每个区块分别编辑、分别保存的模式，避免页面出现多套不同的状态机。

### 保存方式

主资料页采用一次编辑、一次保存的模式。

- 用户修改任一可编辑字段后，页面进入脏状态。
- 点击 `取消`，恢复到最近一次成功保存的数据。
- 点击 `保存资料`，统一提交可编辑字段。
- 保存成功后返回查看态，并同步更新头部摘要。
- 保存失败后保留编辑态，把错误贴在字段附近或保存区上方。

不采用自动保存，也不采用区块级即时保存。

## 视觉与排版原则

整体气质应当是安静、克制、偏编辑器式的个人资料页，而不是工作台、仪表盘或营销化卡片墙。

### 页面节奏

- 单列为主，局部双列为辅。
- 桌面端优先保证垂直阅读节奏。
- 移动端全部自然收为单列。

### 章节组织

每个章节遵循同一节奏：

- 标题
- 一句用途说明
- 内容区域
- 必要时补充局部提示

这让用户在滚动时感觉自己是在整理一份个人资料，而不是在切换多种功能面板。

### 视觉克制点

- 不使用左侧目录卡或 tab 列表作为主结构。
- 不使用统计卡、功能总览卡作为主入口。
- 不在主页面堆叠多个抢注意力的主按钮。
- 不把所有模块做成同等权重的并列面板。

## 路由关系

新版结构建议明确拆分成以下路径：

- `/profile`：个人资料主页，单列长页，默认入口。
- `/profile/security`：安全设置独立页。
- `/profile/password`：修改密码独立页。
- `/profile/notifications`：消息提醒独立页。

主页面底部入口卡直接跳转到对应二级页。

如果当前系统存在 `?tab=` 或其它 query 方式的旧入口，实现时应保留兼容跳转，但兼容仅作为过渡，不应再成为新的主交互结构。

## 数据与职责边界

### `/profile`

只负责当前用户基础资料的读取、展示和提交，包括：

- 头像
- 姓名
- 时区
- 账号绑定信息展示

### `/profile/security`

只负责：

- MFA / TOTP
- 恢复码
- Passkey
- 第三方账号绑定

### `/profile/password`

只负责密码修改。

### `/profile/notifications`

只负责通知偏好配置。

这样每个页面只有一种清晰职责，避免主页既是资料页又承担安全入口逻辑。

## 错误处理

### 主资料页

- 字段级错误显示在字段附近。
- 整体保存失败显示在保存区上方。
- 头像上传失败显示在头像区域附近。
- 失败后保留编辑态，不强制用户重新进入编辑流程。

### 二级页

保持各自已有的业务错误处理逻辑，但视觉反馈风格应统一：

- 表单型页面以字段和局部错误为主。
- 操作型页面以局部告警和动作状态为主。

## 实现建议

1. 优先重构 `/profile` 主页面结构，把它从导航页转成资料页。
2. 保留安全设置、密码、通知三个现有页面的业务能力，仅调整其入口关系和视觉节奏。
3. 把旧的 tab / section 查询参数改成兼容跳转，不再作为主状态来源。
4. 让组件边界围绕“资料页章节”和“专项设置页”划分，而不是围绕“tab 内容块”划分。

## 测试策略

### 单元测试

1. `/profile` 默认渲染查看态。
2. 点击 `编辑资料` 后进入编辑态。
3. 点击 `取消` 后恢复最近一次保存的数据。
4. 底部三个入口跳转到各自二级页。
5. 子页仍可独立渲染和工作。

### 类型与集成检查

1. 路由改造后的类型检查通过。
2. 主资料页和二级页的 props / emits 契约稳定。

### E2E 建议

至少覆盖一条主路径：

1. 登录。
2. 进入 `/profile`。
3. 点击 `编辑资料`。
4. 修改基础资料并保存成功。
5. 再进入一个二级页，例如 `/profile/password`，确认专项流程仍然可用。

## 风险与应对

### 风险 1：主页过长

应对：主页面只保留基础资料相关内容，不把安全和通知复杂配置继续内联展开。

### 风险 2：旧链接失效

应对：对旧 query 入口做兼容跳转，避免已有书签或站内链接直接失效。

### 风险 3：用户误判哪些字段可编辑

应对：通过查看态与编辑态切换，以及“联系与身份信息”区块的只读语义，明确区分“可编辑资料”和“绑定信息”。

## 结论

本次重设计将个人中心重新定义为“个人资料主页 + 三个专项设置页”的结构。

核心变化不是样式微调，而是把入口逻辑、页面职责和编辑流程重新校准：

- `基本设置` 成为真正的长页资料编辑体验。
- `安全设置 / 修改密码 / 新消息提醒` 保持独立页面。
- 个人中心首页不再承担目录页或工作台职责。

这能让页面更符合用户直觉，也更容易在后续迭代中维持清晰边界。
