# 小程序地图找房体验改造设计

**日期：** 2026-09-19  
**状态：** 已确认，待实施

## 1. 目标

在不修改现有公开房源地图 API、不引入新依赖的前提下，将微信小程序与 H5 的地图找房改造成稳定、连续、可恢复的找房工作台。

本次改造同时解决两个问题：

- **丝滑：** 拖动、缩放、筛选和钻取过程中地图不闪空、不反复跳中心、不因重复请求抖动；旧结果在新结果返回前继续可见。
- **实用：** 用户能快速理解当前结果层级，按城市、区域、小区、楼栋逐级找房，选择楼栋后直接浏览房源，并能从空结果或定位失败中恢复。

## 2. 范围与边界

### 本次包含

- 微信原生地图与 H5 高德地图采用一致的视野、请求和选择状态。
- 重构视野事件、请求调度、结果缓存、标记 ID、标记选择和相机更新逻辑。
- 优化顶部搜索与附近筛选、更新状态、地图控制区、空结果提示和底部结果层。
- 拆分地图页中过度集中的状态与视图职责。
- 补充领域单测、页面结构测试和微信开发者工具验收。

### 本次不包含

- 不修改 Django API、OpenAPI 生成文件和数据库空间查询。
- 不新增地图供应商、瓦片服务、WebSocket 或 Redis 地图缓存。
- 不新增多语言文件、`package.json` 或锁文件改动。
- 不建设跨业务通用地图框架，只抽取当前地图找房需要的边界。

## 3. 方案选择

### 方案 A：局部润色

只调整样式、加载动画和现有防抖。改动小，但旧标记闪烁、重复视野请求、程序化相机事件回流和页面职责过重仍然存在。

### 方案 B：现有接口上的交互与状态重构

保留 API，通过明确的地图会话状态、视野请求调度、短期缓存、稳定标记映射和底部结果层提升体验。风险和收益平衡，能够在微信与 H5 同时落地。

### 方案 C：后端地图聚合体系重构

引入瓦片、服务端缓存或新的聚合协议。长期扩展性更强，但会扩大到后端、部署与数据协议，不适合作为本轮体验改造。

**采用方案 B。**

## 4. 页面体验

### 4.1 首屏

- 首次进入时显示轻量地图骨架，地图初始化与地区初始化并行准备；只有首次请求使用阻塞式加载层。
- 第一批标记成功后只自动适配一次视野。之后的筛选、搜索和用户拖动不会被后台结果强制拉回。
- 无有效适配点时不向微信地图传空 `include-points`，也不调用 H5 的 `setFitView`。

### 4.2 顶部工具区

- 第一行保留地区、页面标题、关键词输入和搜索操作。
- 第二行保留“附近”入口；开启附近后以紧凑半径选项展示，不扩大顶部遮挡面积。
- 当前房源数、标记数和层级摘要使用轻量信息条展示；刷新时只在摘要中显示“更新中”，不覆盖地图。
- 搜索词继续采用“输入草稿 + 明确提交”，输入过程不发请求。

### 4.3 地图移动与缩放

- 拖动或缩放开始后，不清空旧标记和已选结果。
- 只在交互结束后调度一次请求；连续 `regionchange` 合并为最后一次，目标延迟为 `240–360ms`。
- 视野边界、缩放级别和筛选条件归一化为请求键。与最后一次成功请求相同的键不重复请求。
- 同一会话保留最近 8 个成功视野结果。返回刚浏览过的区域时先同步恢复缓存，再按需要静默刷新。
- 程序化相机移动与用户拖动分开记录。标记钻取、定位、恢复全览引发的视野事件不得形成重复请求或相机回弹。
- 请求期间地图保持可操作；旧结果在新结果成功后一次性替换。失败时继续保留旧结果。

### 4.4 标记与层级钻取

- 标记 ID 根据业务 `key` 稳定映射，不再使用当前数组下标作为长期身份。
- 城市、区域、小区标记点击后进入下一级：更新中心和目标缩放，并在相机稳定后加载新层级。
- 楼栋标记点击后进入楼栋选择状态并打开底部结果层，不额外触发无关的全量地图适配。
- 选中态通过尺寸、颜色和文字共同表达；地图标记与底部结果层共享同一个 `selectedMarkerKey`。
- H5 标记采用按 `key` 增删改的差量更新，不在每次响应后清空并重新创建全部标记。

### 4.5 底部结果层

- 未选中楼栋时不长期占据地图，只保留地图摘要和控制按钮。
- 选中楼栋后出现底部结果层，首屏展示楼栋名称、地址、房源数量、最低租金和导航入口。
- 房源卡横向浏览，保留现有收藏和进入详情能力；加载房源期间保留楼栋摘要，不显示全屏加载。
- 点击地图空白处收起结果层但保留当前视野。
- 当前选中楼栋在视野静默刷新后仍存在时保持选中；确实离开结果范围时才收起，并显示一次轻量提示。

### 4.6 空结果与恢复

- 当前视野为空时在地图下方展示非阻塞式提示，不覆盖缩放、拖动和定位。
- 提供“查看全城”和“清除筛选”恢复操作；附近模式下同时允许退出附近范围。
- 搜索无结果时保留搜索前视野，不跳到默认城市中心。
- 首次加载失败使用可重试错误卡；后续刷新失败只使用 toast，并保留上一次成功结果。

## 5. 前端架构

### 5.1 地图页面

`src/pages-housing/map/index.vue` 继续负责页面组装和跨组件状态，但不再直接承载全部请求、相机和标记计算细节。

### 5.2 地图会话 composable

新增当前业务专用的地图会话模块，职责包括：

- 当前相机、用户视野和程序化移动状态；
- 请求键生成、延迟调度、并发失效和最近结果缓存；
- 首次适配、恢复全览、定位和层级钻取意图；
- 选中对象在结果更新后的保留或失效判断。

模块只依赖纯数据和回调，不直接依赖具体地图 SDK，便于单测。

### 5.3 领域工具

`src/domain/house-map.ts` 负责：

- 坐标清洗和安全适配点；
- 稳定标记 ID；
- 视野归一化与请求键；
- 缩放级别约束；
- 可缓存结果的最小数据结构。

这些函数保持纯函数，不访问 `uni`、Vue Store 或网络。

### 5.4 平台地图组件

- 微信小程序继续使用原生 `<map>`，页面只向其传递有效标记、圆形范围和可选适配点。
- `HouseH5Map.vue` 继续管理高德实例，但改为差量同步标记、显式区分 `fit`、`pan` 和用户视野事件。
- 两端都向页面发出统一的视野结构，不把 SDK 对象泄漏到页面层。

### 5.5 结果层组件

将楼栋摘要与房源横向列表拆成独立组件。组件只接收选中标记、房源列表和加载状态，并发出导航、收藏、打开房源和关闭事件。

## 6. 数据流

1. 页面初始化地区与筛选状态。
2. 地图会话生成首个查询意图并调用 `getPublicHouseMap`。
3. 成功结果写入最近结果缓存，更新标记，并在首屏执行一次安全适配。
4. 用户移动地图时只更新候选视野；交互结束后由会话模块合并事件并生成请求键。
5. 命中缓存时立即恢复结果；需要刷新时在后台请求，旧标记继续显示。
6. 新响应只有在请求 ID 和请求键均仍为当前目标时才能提交。
7. 点击分组标记产生程序化相机意图；相机稳定后请求下一级结果。
8. 点击楼栋标记加载该楼栋公开房源，地图结果请求和楼栋房源请求各自维护竞态 ID。

## 7. 错误处理

- 地图 SDK 初始化失败：地图区域展示原因和重试。
- 首次地图接口失败：展示阻塞式错误卡和重试。
- 后续视野刷新失败：保留旧结果并提示“当前视野更新失败”。
- 楼栋房源加载失败：保留楼栋摘要，结果层展示局部重试或空状态。
- 定位被拒绝：不改变当前地图和筛选，提供前往设置入口。
- 无效坐标：在领域边界过滤，不传入地图 SDK，不让单个异常标记破坏整页。

## 8. 性能与体验验收

- 连续拖动期间不发地图结果请求，结束后只产生一个最终视野请求。
- 相同筛选和相同归一化视野不重复请求。
- 后续刷新期间旧标记持续可见，页面不出现全屏加载闪烁。
- 返回最近浏览过的区域时缓存结果立即恢复。
- 首屏适配后，后台刷新不会自动拉回用户视野。
- H5 更新结果时复用未变化标记，不全量销毁重建。
- 微信地图在零标记、无效坐标和视野切换为空时不出现 `fitBounds` 异常。
- 选择楼栋后能在底部结果层完成浏览、收藏、导航和进入详情。
- 空视野、搜索无结果、定位失败和刷新失败都有明确恢复路径。

## 9. 测试

### 领域单测

- 空点集、无效坐标和有效适配点。
- 稳定标记 ID 在排序变化后保持不变。
- 视野归一化与请求键去重。
- 最近结果缓存容量、覆盖和读取顺序。
- 程序化移动与用户移动产生不同的请求调度结果。

### 页面与组件测试

- 首屏只适配一次。
- 拖动结束后合并请求，旧标记在刷新期间保留。
- 过期响应不会覆盖新视野。
- 分组标记钻取，楼栋标记打开结果层。
- 结果更新时选中楼栋保留或正确失效。
- 空结果恢复操作和后续刷新错误处理。

### 人工验收

- 微信开发者工具：快速拖动、连续缩放、反复进入空区域、返回全城、开启附近、切换半径、拒绝定位权限。
- H5：重复上述流程，并观察高德标记是否闪烁、重复创建或相机回弹。
- 调试器不得出现地图 SDK 异常、未处理 Promise 或请求风暴。
