# 经营分析数据与交互完整性优化设计

日期：2026-08-30
状态：设计已确认，待实施

## 1. 背景

经营分析页面已经完成基础视觉优化和来源注册表改造，但仍存在几类影响可信度与可用性的问题：当前“转化漏斗”实际使用行为次数而非同一访客链路；房源排行固定请求前 20 条且后端在分页前构建完整结果；前端允许选择超过后端限制的时间范围；筛选条件无法通过 URL 恢复；错误提示把所有失败都归因于权限；公开采集的限流按请求而非事件数量计算。

本设计在不引入线索系统、不改变现有分析事件模型主体结构的前提下，完成数据口径纠正、分页性能、交互恢复能力和来源完整性优化。

## 2. 已确认决策

- 不把当前数据包装成访客级真实转化漏斗。
- 将“转化漏斗”改为“业务行为路径”，明确标注“按行为次数统计”。
- 路径阶段继续使用浏览房源、发起咨询、预约带看、生成租约四类既有事件。
- 房源排行提供真实分页，并将明细加载范围收窄到当前页。
- 日期范围前端与后端统一限制为最多 366 个自然日。
- 日期、来源、页码和每页数量写入 URL，刷新和复制链接后可恢复。
- 各数据模块独立显示加载、空、错误和重试状态。
- 增加手动刷新和最后更新时间，不增加自动轮询。
- 来源定义继续由后端注册表统一维护，并增加数据库约束。
- 公开采集必须携带匿名标识或会话标识，限流按事件数量计算。
- 不修改多语言文件、依赖或生成的 OpenAPI 客户端。

## 3. 目标

- 页面展示的指标名称与实际统计口径一致，不产生伪造的访客转化结论。
- 用户能够查看全部房源排行，而不是只能看到固定的前 20 条。
- 大规模房源数据下，排行榜只加载当前页的指标明细和房源展示信息。
- 筛选状态可刷新、可复制，并在非法 URL 参数下安全回退。
- 单个接口失败不遮蔽其他已成功的数据模块。
- 来源值在采集服务、查询接口和数据库层保持一致。
- 降低批量公开事件绕过请求级限流的风险。

## 4. 非目标

- 不建设访客、咨询、客户、带看和租约之间的线索归因模型。
- 不回填历史访客级转化数据。
- 不新增自动刷新、导出报表或来源占比图。
- 不根据当前日期范围动态隐藏没有数据的来源。
- 不调整事件定义、事件保留天数或每日汇总维度。
- 不改造小程序或 H5 的页面视觉。

## 5. 业务行为路径

### 5.1 统计口径

阶段定义保持为：

```text
浏览房源 = house.view 事件次数
发起咨询 = house.phone_click + house.online_consult_click 事件次数
预约带看 = viewing.requested 事件次数
生成租约 = lease.created 事件次数
```

每个阶段展示行为次数。第二阶段开始展示“相对上一步”的事件次数比例：

```text
当前阶段次数 / 上一步次数 * 100%
```

比例文字不再强制截断为 100%。如果后一步事件次数高于前一步，应如实显示实际比例，避免掩盖数据异常或线下补录行为。

如果上一步次数为 0，比例显示为 `—`，不使用 0% 或无穷大制造错误结论。

### 5.2 视觉表达

- 标题固定为“业务行为路径”。
- 模块辅助说明固定为“按行为次数统计”。
- 增加说明提示：该模块反映行为量级，不代表同一访客的连续转化。
- 每个阶段的条形长度按“当前阶段次数 / 当前路径最大阶段次数”计算，仅用于比较行为量级。
- 比例标签独立显示真实的相对上一步比例；超过 100% 时使用警示语义并保留完整数值。
- 空数据时保持与趋势模块等高。

## 6. 房源排行与分页性能

### 6.1 前端分页

- 默认 `page=1`、`page_size=20`。
- 表格显示分页器、总数、快速切换页码和每页数量。
- 每页数量允许 `20 / 50 / 100`。
- 日期或来源变化时重置为第一页。
- 排名序号使用 `(page - 1) * page_size + index + 1`，跨页连续。

### 6.2 后端两阶段计算

现有逻辑会构建所有目标的总数、事件明细、访客数和展示对象后再分页。改造后分两阶段执行：

1. 仅聚合所有目标的总行为数，用于排序和计算总目标数。
2. 根据请求页码截取目标 ID。
3. 仅针对当前页目标 ID 聚合事件明细和可用的访客数。
4. 仅加载当前页房源及关联楼栋信息。

`apps.analytics.api` 增加仅供排行榜使用的分页器子类，通过 Ninja `pass_parameter` 将规范化后的 `page/page_size` 传入服务层。路由仍遵循项目约定，使用 `response=list[...]` 和项目分页器输出 `{items, total, page, page_size}`。

页面超出最后一页时，前端在收到空页且 `total > 0` 后回到有效的最后一页，不显示永久空表。

## 7. 日期范围与 URL 状态

### 7.1 URL 参数

使用以下参数：

```text
start_date=YYYY-MM-DD
end_date=YYYY-MM-DD
source=h5
page=2
page_size=50
```

规则：

- 默认近 30 天时省略 `start_date` 和 `end_date`。
- 全部来源时省略 `source`。
- 第一页时省略 `page`。
- 每页 20 条时省略 `page_size`。
- 更新参数时保留页面上与分析无关的其他查询参数。
- 初次进入页面时从 URL 初始化状态；非法日期、未来日期、倒序范围、超过 366 天、未知来源、非法页码和非法每页数量均安全回退到默认值。
- 来源参数在来源定义接口成功后校验；不在前端重新维护一份来源白名单。

### 7.2 日期组件限制

- 结束日期不能晚于今天。
- 开始日期和结束日期最多相差 365 天，即包含首尾共 366 个自然日。
- 用户选择超限范围时不发送请求，保留原范围并显示明确提示。
- 后端继续保留相同校验，不能只依赖前端。

## 8. 加载、错误与刷新

### 8.1 模块边界

- 概览指标和业务行为路径依赖概览接口，共享加载与错误状态。
- 趋势模块只依赖趋势接口。
- 房源排行只依赖排行接口。
- 来源筛选只依赖来源定义接口。

任一接口失败时，其他成功模块继续正常展示。错误区域显示“加载失败”和“重新加载”，不再把所有错误归因为权限问题。

来源接口失败时，下拉框显示失败状态和可读说明；用户仍可查看“全部来源”的已有分析数据。

### 8.2 手动刷新

- 筛选区增加刷新按钮。
- 点击后同时刷新概览、趋势和排行榜，不重复请求稳定的来源定义。
- 刷新期间按钮显示加载状态，已展示的数据不清空。
- 三类核心数据都至少成功过一次后，页面取三者成功更新时间中的最早值，格式为“更新于 HH:mm:ss”，确保该时间点之前所有模块都已成功更新。
- 没有任何成功响应前不显示伪造更新时间。

### 8.3 历史访客说明

当范围包含无法跨日去重的历史汇总数据时：

- 独立访客继续显示 `—`。
- 指标卡和排行榜访客列提供说明：“历史汇总无法跨日去重，因此不提供区间访客数”。
- 页面顶部保留简短范围提示。

## 9. 来源完整性

### 9.1 应用与数据库约束

- `AnalyticsEvent.source` 使用 `AnalyticsSource.choices`。
- 增加数据库检查约束，只允许后端注册表中的来源值。
- `AnalyticsDailyMetric.source` 允许注册来源值以及用于全来源汇总的空字符串。
- 新迁移在添加约束前检查已有来源；发现未知值时以明确错误中止，不擅自删除或映射历史数据。
- 查询接口继续拒绝未知来源并返回 `422`。

### 9.2 来源定义缓存

来源列表是稳定元数据，前端 React Query 使用 10 分钟 `staleTime`。查询键继续包含当前组织，保证组织切换和权限上下文正确。

## 10. 公开采集基础防护

- 公开采集事件必须至少提供 `anonymous_id` 或 `session_id`，否则该事件拒绝入库。
- 请求仍限制最多 50 个事件。
- IP 限流从“每分钟请求数”改为“每分钟提交事件数”，批量请求按批次内事件数量累计。
- 新设置使用 `ANALYTICS_PUBLIC_EVENT_RATE_LIMIT_PER_MINUTE=120`，明确表达每分钟事件数，并同步测试。
- 非公开来源、服务端专用事件、未知属性、异常时间和无效目标继续使用现有校验。
- 本次不引入验证码、设备指纹、外部风控服务或原始 IP 持久化。

## 11. 前端代码整理

- 将 URL 解析与同步提取为页面同目录的纯函数文件，便于独立测试。
- 将来源定义查询设置稳定缓存时间。
- 修复趋势标签映射每次渲染都创建新 `Map`、导致 `useMemo` 失效的问题。
- 保持页面现有视觉结构和等高规则，不进行无关样式重构。
- 继续使用 Ant Design token、现有 `styles.ts` 和项目组件。

## 12. 测试与验收

### 12.1 后端

- 来源定义接口返回注册来源且不包含未启用的管理端来源。
- 事件模型和每日汇总模型拒绝未知来源。
- 公开事件缺少匿名标识和会话标识时拒绝入库。
- 批量事件按事件数量触发限流。
- 日期范围超过 366 天继续返回 `422`。
- 排行榜分页总数、页码、每页数量和跨页内容正确。
- 排行榜当前页只加载当前页目标的展示对象和指标明细。
- 历史与原始数据混合时排序和总数保持正确。

### 12.2 前端

- 从 URL 恢复日期、来源和分页状态。
- 非法 URL 参数回退默认值。
- 日期和来源变化后页码重置。
- 超过 366 天的范围不会触发分析请求。
- 业务行为路径显示行为次数口径和未截断比例。
- 排行榜跨页排名连续。
- 单个模块失败时其他模块仍展示，并可单独重试。
- 手动刷新触发三类数据重新请求并更新成功时间。
- 来源加载失败时页面仍能以全部来源展示数据。
- 窄屏下筛选区、刷新区域和排行榜分页不横向溢出。

## 13. 兼容与发布

- 概览、趋势和来源接口保持现有响应结构。
- 排行榜继续保持 `{items, total, page, page_size}` 响应结构，前端调用方无需适配新包络。
- 现有事件和每日汇总数据无需重算。
- 数据库约束迁移不修改已有合法数据。
- 未知历史来源必须先由人工确认和修复后才能完成迁移，避免静默数据损失。
- 不执行 Git 提交、依赖升级或生成代码更新。
