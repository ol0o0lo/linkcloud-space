# 房源地图任务型侧栏优化设计

**日期：** 2026-09-05
**状态：** 已实施

## 背景

当前房源地图已经具备小区与楼栋分级标点、当前视野查询、房态筛选、结果面板、楼栋信息窗、待定位入口、浏览器定位、适配结果和 URL 状态恢复等能力。实际浏览器验收表明，主要问题已经不是缺少功能，而是搜索、统计、结果面板、地图信息窗和地图控制同时争夺注意力；选中楼栋后，侧栏与信息窗还会重复展示同一组信息和操作。

本设计延续 `2026-08-22-rental-map-overlay-result-panel-design.md` 已落地的地图内嵌结果面板，但重新定义它的产品职责：从“地图结果列表”调整为“发现并处理空置或招租房源的任务型侧栏”。本设计取代该文档中“完整楼栋信息窗”“收起后仅显示图标”“不展示层级提示”等交互结论，其余地图数据、定位模型和组织隔离约束继续沿用现有实现。

## 目标

- 让用户优先发现空置或招租房源，并快速进入现有房源处理流程。
- 建立单一操作中心，消除侧栏与地图信息窗的内容和操作重复。
- 保留小区到楼栋的浏览上下文，使自动缩放和层级切换可理解、可返回。
- 在桌面端保持地图主画布，在窄屏下通过底部抽屉保留可用地图面积。
- 明确加载、更新、空结果、局部失败和待定位任务的反馈。
- 首版复用现有接口、路由和生成服务，不增加新的后端数据结构。

## 非目标

- 不在地图内实现房源编辑、房态修改、发布招租或其他完整业务表单。
- 不新增多房态同时筛选接口；首版继续使用单个 `house_status`。
- 不改变房源、小区、楼栋的定位模型、坐标校验或组织隔离。
- 不重做全局管理端导航、主题或设计系统。
- 不引入通用地图框架、复杂状态库或新的品牌视觉语言。

## 方案选择

采用“地图主画布 + 任务型侧栏”。地图负责空间定位和选中对象，侧栏负责筛选、排序、上下文、详情与处理入口，房源列表继续承担实际处理工作。

未采用以下方案：

- 地图内直接处理：操作步骤更少，但会重复建设房源列表的表单、权限和错误处理。
- 仅做视觉整理：改动较小，但无法解决信息重复和钻取上下文丢失。

## 核心用户流程

```text
进入房源地图
  -> 默认查看空置房源
  -> 搜索或切换为空置、招租、全部
  -> 在小区结果中选择范围
  -> 查看该小区的待处理楼栋
  -> 选择楼栋并查看任务详情
  -> 跳转到已按楼栋和房态筛选的房源列表处理
```

地图标点和侧栏列表是同一选择状态的两个入口。无论从哪一处选择楼栋，都进入同一个侧栏详情，不再打开完整地图信息窗。

## 页面布局

### 顶部任务工具栏

地图内部只保留一条稳定工具栏：

- 左侧为小区、楼栋或地址搜索。
- 中部为 `空置`、`招租`、`全部` 三个快捷房态，默认选中 `空置`。
- 右侧为当前任务摘要，例如“13 套空置 · 6 栋”。摘要只突出当前房态指标，不同时平铺全部房态和待定位数量。
- 搜索和房态是业务操作；浏览器定位、查看全部结果和地图缩放放在地图右侧控制区。

桌面端工具栏保持单行。窄屏下搜索占一整行，房态与摘要位于第二行。

### 桌面任务侧栏

- 宽度约 `360px`，最大不超过当前地图结果面板的 `390px` 上限。
- 位于工具栏下方，底部与地图保持 `12px` 间距。
- 列表、钻取和详情使用同一个侧栏容器切换，不叠加第二个 Drawer 或 Card。
- 收起后显示带文字的任务摘要入口，例如“空置 13 套”，不再只显示含义不明确的展开图标。
- 展开或收起时继续校正地图有效可视区域的中心，避免选中标点被侧栏遮挡。

### 地图控制区

- 保留“定位附近”、地图缩放和比例尺。
- “适配当前结果”改为“查看全部结果”。
- 业务统计、待定位数量和详情操作不进入地图控制区。

## 侧栏状态

### 1. 结果列表

标题直接表达当前任务，例如“空置房源 · 6 栋”或“招租房源 · 4 栋”。

结果项展示：

- 小区或楼栋名称；
- 地址；
- 当前房态数量，例如“空置 6 套”；
- 必要的“楼栋中心”“独立楼栋”等辅助标签。

结果按当前房态数量倒序排列，再按名称和 ID 稳定排序。当前接口已经返回各房态数量，首版在前端排序。

### 2. 小区钻取

选择小区后，侧栏顶部显示可返回的上下文，例如：

```text
全部结果 / 荔湾里
2 栋 · 2 套空置
```

下方只展示该小区的楼栋，地图同步移动到小区并进入楼栋显示层级。返回“全部结果”时恢复钻取前的地图视野、结果列表和滚动位置。

### 3. 楼栋任务详情

选择楼栋后，侧栏切换为详情，包含：

- 楼栋名称、小区和地址；
- 当前任务指标，例如“1 套空置”；
- 全部有效房源的房态构成，作为次要信息；
- 唯一主操作“查看 1 套空置房源”或“查看 2 套招租房源”；
- 次级入口“楼栋详情”和“编辑位置”；
- 返回楼栋列表的入口。

主操作跳转现有房源列表，并携带 `building_id` 与列表页实际消费的 `status`；地图自身仍使用 `house_status`。楼栋详情和编辑位置继续携带完整 `return_to`。

点击地图空白处关闭楼栋详情并返回原列表，但保留搜索、房态、小区范围和当前地图视野。

### 4. 待定位任务

待定位楼栋不属于可显示地图结果。它以独立任务入口固定在侧栏底部，例如“1 栋楼栋待定位”，进入现有楼栋资料编辑流程。待定位请求失败不阻塞已定位结果。

## 地图标点

标点按地图显示层级逐步增加信息，不再使用大面积、内容重复的完整气泡：

- 聚合点：圆形，显示项目数和当前房态数量。
- 小区点：紧凑圆角标签，显示小区名和当前房态数量。
- 楼栋点：定位针与短标签，显示楼栋名和当前房态数量。
- 选中点：使用主色填充、加粗描边和适度尺寸变化，同时由侧栏详情和文字表达选中状态，不能只依赖颜色。

完整 `AMap.InfoWindow` 不再作为楼栋详情和操作容器。若高德地图需要保留悬浮信息，只允许展示名称和当前房态数量，不提供业务操作。

地图标点需要具备可访问名称，并支持 Tab、Enter 和 Space；侧栏列表仍是完整的键盘操作入口。

## 交互规则

### 搜索

- 输入过程中不改变业务筛选和地图视野。
- 用户按回车或点击搜索后才提交关键词。
- 提交前记录当前地图视野。首次关键词搜索不携带地图边界，在当前组织范围内搜索；找到结果后只自动适配一次视野。
- 搜索无结果时保留提交前的地图视野，不自动跳到组织默认位置或浏览器位置。
- 清除搜索后恢复提交前的地图视野，并按当前房态重新查询该范围，不突然跳到组织级全量结果。

### 房态切换

- `空置` 传 `house_status=vacant`。
- `招租` 传 `house_status=listed`。
- `全部` 不传 `house_status`。
- 切换后保留当前地图中心，更新结果和当前任务指标；存在选中详情时返回对应结果列表。

房态只决定哪些小区或楼栋进入结果。侧栏详情中的完整房态构成仍统计该楼栋全部有效房源，避免把库存汇总误解为筛选后的数量。

### 地图移动

- 拖动或缩放结束后继续使用当前防抖机制按边界刷新。
- 刷新期间保留旧标点和旧结果，只显示轻量“更新中”。
- 用户正在查看仍然符合条件的楼栋时，刷新不得自动关闭详情。
- 选中对象离开当前范围或不再符合条件时，返回结果列表并给出简短说明。

### 选中与适配

- 点击标点和点击列表项进入同一选择状态。
- 选中楼栋后，地图移动需要考虑侧栏或底部抽屉占用区域，确保标点位于有效可视区域。
- “查看全部结果”忽略当前地图边界，加载当前搜索与房态下的组织级结果并适配视野。
- 当前组织在现有搜索与房态下确实没有结果时隐藏该按钮；只有当前地图范围为空时仍保留该按钮作为恢复入口。

## URL 与浏览器历史

URL 继续保存：

- `keyword`；
- `house_status`；
- `estate_id`；
- `selected_building_id`；
- 地图中心、缩放等级。

小区钻取和楼栋详情属于明确导航状态，应产生可返回的浏览器历史。连续地图拖动和缩放只替换当前历史项，不能不断增加历史记录。浏览器后退应依次恢复楼栋列表、小区列表和钻取前视野。

从房源列表、楼栋详情或编辑位置返回时，继续通过 `return_to` 恢复上述状态。

## 响应式设计

### `>= 1000px`

- 使用左侧任务栏。
- 侧栏可展开或收起；桌面收起状态可继续使用现有 localStorage 键持久化。

### `768px - 999px`

- 任务栏改为底部抽屉。
- 默认只显示包含当前房态数量和楼栋数的摘要条。
- 展开后最高约占视口高度的 `55%`，地图仍保留当前标点区域。
- 列表、小区钻取和楼栋详情都在同一底部抽屉中切换。
- 窄屏初次进入时忽略桌面端的展开持久化状态，默认保持摘要状态。

### `< 768px`

- 沿用底部抽屉形态和管理端现有侧边导航收起行为。
- 搜索、房态和摘要允许分为两行，控件使用正常可点击尺寸。
- 本功能不为管理端新增独立移动端导航或页面。

## 数据与接口边界

首版继续使用现有接口：

- `GET /api/house/estate-map/`；
- `GET /api/house/building-map/`；
- `GET /api/house/building-map/{building_id}/`；
- 现有待定位楼栋接口。

当前可见标点继续按边界和 `page_size=500` 请求。关键词首次全局搜索返回结果超过接口上限时，显示“结果较多，请缩小范围或完善关键词”，不把截断结果声明为完整数据。

列表选中楼栋时优先使用标点已经包含的名称、地址和计数，不额外请求详情；通过深链接进入且当前结果中没有该楼栋时，继续使用楼栋地图详情接口补充状态。

## 前端组件边界

不建设通用地图框架，只对当前页面进行针对性拆分：

- 任务工具栏：搜索、房态和任务摘要；
- 任务侧栏外壳：桌面侧栏、收起入口和窄屏底部抽屉；
- 小区与楼栋结果列表；
- 楼栋任务详情；
- 地图标点内容和选择映射；
- 加载、错误和空结果状态。

现有 `EstateResultPanel` 与 `BuildingResultPanel` 共享侧栏外壳，但保留各自清晰的数据展示职责。地图实例、视野同步和查询协调继续由地图页面负责，避免抽象出与当前单页需求无关的通用状态层。

## 加载、错误与空状态

- 高德 SDK 加载失败：地图主体显示错误、原因和重试，任务侧栏不渲染不可操作内容。
- 小区或楼栋结果加载失败：保留基础地图和上一次成功结果，在侧栏局部显示重试。
- 楼栋深链接详情失败：返回结果列表并提示该楼栋暂不可用，不清除搜索和视野。
- 全局关键词搜索无结果：展示当前关键词与房态，例如“当前组织没有符合‘云岸’和‘空置’条件的楼栋”，并提供清除搜索、查看全部房态两个恢复入口。
- 地图移动后的当前范围无结果：展示“当前地图范围暂无空置楼栋”，并提供查看全部结果或切换房态的恢复入口。
- 当前位置权限被拒绝或超时：使用现有消息提示，不改变已加载结果。
- 待定位任务失败：只影响侧栏底部入口，并提供局部重试。

## 焦点与可访问性

- 侧栏结果项使用真实按钮语义和 `aria-pressed` 表达选中。
- 地图标点提供可访问名称、焦点样式和键盘触发。
- 从列表打开详情时，详情标题可被辅助技术感知；返回列表时恢复到原结果项。
- 收起入口、返回入口、清除条件和地图图标按钮都有明确可访问名称。
- 更新结果、空结果和错误状态通过可读文字表达，不只依赖颜色、标点消失或地图移动。
- 底部抽屉展开后保持合理阅读顺序，不让地图 iframe 抢占键盘焦点。

## 测试与验收

### 最小自动化测试

- 默认房态为 `vacant`，切换 `listed` 和全部时请求参数与 URL 正确。
- 搜索只在提交后生效；有结果时适配一次，无结果时保留原视野。
- 结果按当前房态数量倒序并保持稳定排序。
- 小区钻取、楼栋详情和浏览器后退恢复正确状态。
- 点击标点与点击列表项进入同一楼栋详情。
- 楼栋详情主按钮携带正确的 `building_id` 和列表筛选参数 `status`，次级入口携带 `return_to`。
- 完整楼栋信息窗不再创建。
- 加载期间保留旧结果，空结果和局部错误提供恢复操作。
- 桌面侧栏、收起摘要和窄屏底部抽屉具有正确的可访问名称。

### 浏览器验收

- 桌面宽屏验证默认空置、招租切换、全局搜索、小区钻取、楼栋详情、返回和待定位入口。
- `768px` 验证工具栏换行、底部抽屉摘要、展开高度、详情与地图同时可见。
- 验证选中标点不会被侧栏或底部抽屉遮挡。
- 验证无结果时页面不会自动跳转到其他位置。
- 验证键盘可以从工具栏进入结果、打开详情、返回列表并继续操作。

### 完成标准

- 页面只有一个完整详情和业务操作中心。
- 默认进入空置房源任务，能够一键切换招租或全部。
- 用户能够理解当前位于全部结果、小区范围还是楼栋详情。
- 用户能够从楼栋详情一键进入对应房态的房源列表。
- 无结果、局部失败和更新过程不会让用户面对无法解释的空地图。
- 桌面和 `768px` 窄屏均完成浏览器验收。
- 相关 Vitest 和 TypeScript 检查通过；不要求为本次纯前端交互调整新增后端测试。
