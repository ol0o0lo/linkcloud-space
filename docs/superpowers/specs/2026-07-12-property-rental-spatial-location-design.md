# 房源空间定位与楼栋地图整合设计

**日期：** 2026-07-12
**状态：** 设计已确认，待用户复核

## 背景与基础

`d0cb6559` 已将楼栋调整为可选绑定小区：楼栋始终属于组织，房源始终属于楼栋；小区只作为楼栋的可选归类。本设计不重做该领域关系、删除保护或组织隔离，而是在其上完成定位与地图业务闭环。

当前 `Estate` 和 `Building` 已有 `address`、`lat`、`lng` 字段及 API Schema，但没有统一的坐标校验、默认定位设置和表单选点体验。`House` 不增加坐标字段，房源位置始终继承所属楼栋。

## 目标

- 租户可在空间设置中维护地图默认定位。
- 小区和楼栋各自独立维护地址与坐标。
- 楼栋地址始终必填；楼栋可不主动选点，但在小区已定位时自动预填小区地址和坐标。
- 通过统一选点组件搜索地址、使用浏览器定位、拖动或点击地图，并在确认后回填表单。
- 在“房源租赁”中重新启用以楼栋为标点的房源地图。
- 从地图查看楼栋及其房源汇总，进入楼栋详情、房源详情和带楼栋筛选的房源列表。

## 非目标

- 不为 `House` 增加 `lat`、`lng`、独立地址或定位维护入口。
- 不在地图上为单个房源绘制标点。
- 不将小区地址或坐标的后续修改自动覆盖楼栋已保存的位置。
- 不引入服务端地理编码 Key、后台批量地理编码任务或新地图数据模型。
- 不改变楼栋可选绑定小区、资源删除检查和组织隔离的既有行为。

## 定位模型

```text
Organization
├── default_location（组织设置；仅作前端初始视图）
├── Estate（独立 address + lat/lng）
│   └── Building（独立 address + lat/lng）
└── Building（estate 为空；独立 address + lat/lng）
    └── House（继承 Building 位置）
```

### 组织默认定位

- 设置键为 `property_rental.default_location`。
- 值固定为 `{ address, lat, lng }`，存放在现有 `DefaultSetting` / `OrganizationSetting` 体系。
- 它只决定地图和选点组件无实体位置时的初始中心；不写入、不覆盖小区或楼栋。
- 用户可在“空间设置”中使用选点组件保存或清除该设置。

### 小区位置

- 小区地址表示项目整体地址，小区坐标表示项目整体展示位置。
- 小区位置非必填：允许地址和坐标均为空，也允许有地址但未定位；一旦保存坐标，地址必须非空。
- 新建或编辑小区的初始顺序为：小区已有位置 → 租户默认定位 → 浏览器当前位置 → 中国范围视图。

### 楼栋位置

- 楼栋地址始终必填，且与小区地址独立保存，二者互不覆盖。
- 楼栋坐标可为空；坐标为空表示“待定位”，不显示为地图标点。
- 新建或编辑楼栋的初始顺序为：楼栋已有位置 → 所属小区位置 → 租户默认定位 → 浏览器当前位置 → 中国范围视图。
- 新建楼栋且其所属小区已有位置时，楼栋表单预填小区地址和坐标；用户可以直接保存，也可以重新选点并修改为精确楼栋位置。
- 新建楼栋切换所属小区时，仅在用户尚未修改地址和坐标的情况下重新预填新小区位置；用户已输入地址或选过位置时不覆盖，并提示核对楼栋位置。
- 小区后续变更地址或坐标，不自动修改任何楼栋。

### 房源位置

- 房源不保存独立地址或坐标。
- 房源详情、带看、租约和地图跳转需要位置时使用 `house.building.address`、`house.building.lat`、`house.building.lng`。
- 楼栋未定位时，房源显示“楼栋待定位”，不回退为伪造位置。

## 坐标校验与选点组件

### 服务器校验

- 小区和楼栋的 `lat`、`lng` 必须成对保存：仅有一个值时返回字段级 422 错误。
- 纬度范围为 `[-90, 90]`，经度范围为 `[-180, 180]`。
- 小区有坐标时地址必须非空；小区地址和坐标均为空仍可保存。
- 楼栋创建和更新始终校验 `address` 非空；无论楼栋是否绑定小区都相同。
- 坐标字段继续使用已有列；本功能不需要 House 迁移，也不创建新的位置模型。

### `LocationPicker`

选点组件使用现有高德 JSAPI loader，以 Ant Design 悬浮弹窗承载：

- 有实体位置、所属小区位置或租户默认定位时直接使用，不主动请求浏览器权限；均不存在时才自动请求浏览器当前位置，并始终提供“定位到当前位置”按钮。
- 顶部搜索地址、POI、小区或楼栋关键词；选择候选项移动地图并更新草稿位置。
- 用户可拖动地图，或直接点击地图设置草稿点。
- 草稿点改变后使用逆地理解析展示标准地址、POI 和行政区划；解析失败仍允许以经纬度确认。
- “确定”同时回填标准地址和经纬度；地址仍可在表单中继续修改，修改地址后提示用户重新核对定位，但不自动改变坐标。最终由小区或楼栋表单的保存动作写入 API。
- “取消”不改变任何表单字段；浏览器定位被拒绝或超时时显示提示并回退到中国范围视图，不硬编码具体城市。SDK 加载失败时显示错误与重试，不渲染不可操作的地图。

## 房源地图

### 入口和状态

- 新路由为 `/property-rental/map`，菜单文案为“房源地图”。
- 原 `/geo/map` 不再作为导航入口，并重定向至 `/property-rental/map` 以兼容旧书签；模拟标点不再承载房产业务。
- URL 保存 `keyword`、`estate_id`、`house_status`、`include_inactive`、地图中心、缩放级别和 `selected_building_id`；详情页通过受限的 `return_to` 返回地图并恢复状态。

### 数据接口

- `GET /api/house/building-map/`：分页楼栋标点，支持关键词、小区、房源状态、停用状态和地图边界筛选；只返回有合法楼栋坐标的数据。房源数量和状态汇总仅统计 `House.is_active=true` 的有效房源。
- `GET /api/house/building-map-unlocated-count/`：返回当前组织中缺少楼栋坐标的数量。
- `GET /api/house/building-map/{building_id}/`：返回一个楼栋的完整摘要、状态汇总和房源列表。
- 所有接口继续以 `require_org_selected` 和 `Building.organization` 保证组织隔离。
- 地图详情中的房源按“楼层升序 → 房号自然排序 → ID”排序，例如 `2` 在 `10` 前、`A2` 在 `A10` 前。

### 页面交互

- 全屏地图显示楼栋标点，标点包含楼栋名与房源总数；零房源楼栋使用弱化视觉。
- 关键词匹配小区名、楼栋名和楼栋地址；可按小区、房源状态、启用状态筛选。
- 房态筛选只决定楼栋是否出现在结果中；标点和抽屉始终展示该楼栋全部有效房源汇总，不把数字缩减为当前房态数量。
- 停用楼栋默认隐藏，通过“包含停用楼栋”筛选显式查看；停用房源始终不进入地图汇总。
- 地图移动结束后以当前边界防抖请求标点；密集区域使用高德点聚合。
- 左上筛选面板显示结果数与待定位楼栋数量，并提供跳转到项目楼栋页补全位置的入口。
- 点击标点或搜索结果打开右侧抽屉，展示小区信息（存在时）、楼栋地址、楼层、电梯、房源状态汇总和已自然排序的房源列表。
- 抽屉链接至房源详情、`/property-rental/houses?building_id=<id>` 和 `/property-rental/buildings/<id>`。
- 楼栋详情页复用地图详情接口，不在前端重复排序。

## 错误处理

- 缺少高德 JSAPI 配置或 SDK 加载失败：显示可重试错误，不阻塞其他后台页面。
- 地图列表失败：保留当前基础地图并显示局部重试。
- 楼栋详情失败：只在抽屉显示错误，不清除地图筛选和视口。
- 没有匹配楼栋：显示空状态和清空筛选操作。
- 待定位楼栋：不显示伪造标点；从项目楼栋页面补充坐标后刷新地图显示。
- 地址搜索或逆地理失败：保留用户已选择的经纬度并允许确认；不自动修改已保存实体数据。

## 测试与验收

### 后端

- 小区与楼栋坐标成对、范围和楼栋地址必填校验。
- 组织默认定位的注册、组织覆盖、读取和清除。
- 楼栋地图关键词、小区、状态、边界、停用状态和组织隔离。
- 待定位数量、楼栋汇总、详情跨组织拒绝和自然排序。
- 已合并的楼栋可选小区、关联资源检查与删除保护回归。
- 后端 Schema 变化后同时重新生成管理端和小程序 OpenAPI 客户端，并验证两端生成类型一致。

### 前端

- 默认定位设置的保存与清除。
- 选点组件的浏览器定位、搜索、拖动、点击、确认、取消和失败回退。
- 小区和楼栋表单的小区位置预填、独立楼栋地址必填、位置独立保存与不自动覆盖。
- 地图筛选、标点、抽屉、跳转、待定位提示和 URL 状态恢复。

### 验收标准

- 租户可维护默认地图中心，但修改它不会篡改实体坐标。
- 小区和楼栋均可独立保存地址与坐标；楼栋地址必填。
- 小区已定位时，新楼栋自动获得可编辑的小区地址和坐标初始值。
- 房源不维护独立坐标，位置始终来自楼栋。
- 房源地图按楼栋准确展示当前组织数据并能查看房源汇总和详情跳转。
- 未定位楼栋不展示错误标点，补充位置并保存后可出现在地图中。
- 全部相关后端、前端测试、类型检查、Ant Design 检查和构建通过。
