# 租约列表字段拆分设计

## 背景

当前租约列表将房源、租客、项目/楼栋、租期、月租和合同归档情况聚合在“租约信息”一列中，并使用点号连接成副标题。该布局虽然列数少，但关键数据难以纵向扫读和横向比较；合同信息还与独立的“合同”列重复。

本次调整只优化管理端租约列表的信息结构，不修改接口、数据模型、筛选条件、详情抽屉或租约业务流程。

## 列结构

租约列表按以下顺序展示：

1. **房源**：第一行展示房号并保留租约预览入口；第二行以弱化文字展示“项目 / 楼栋”。
2. **租客**：第一行展示租客姓名；第二行展示脱敏手机号。缺少租客信息时沿用项目已有的空值展示模式。
3. **租期**：分两行展示起租日期和到期日期，第二行使用弱化样式并带“至”提示。
4. **月租**：使用项目已有的金额格式化方法展示。
5. **状态**：继续使用当前状态标签和枚举映射。
6. **合同**：有文件时展示合同份数；无文件时展示橙色“未归档”标签。
7. **操作**：保留编辑入口和更多操作菜单。

原“租约信息”聚合列及其点号连接副标题全部移除。合同状态只在“合同”列展示，不再重复出现在房源辅助信息中。

## 信息取舍

项目与楼栋不拆成独立列，而是作为房源单元格的辅助信息。这能保留跨项目、跨楼栋识别能力，同时避免列表宽度继续增加。

押金、付款日、签约时间、来源带看、备注等低频字段继续放在详情或编辑抽屉中，不进入列表。此次不新增排序、筛选或后端字段。

## 布局与响应式

各列设置稳定的基础宽度，表格继续使用项目现有横向滚动能力。窄屏时优先通过横向滚动保留字段完整性，不把租期、租金等关键信息压缩回单个副标题。

单元格使用现有 Ant Design 组件与项目布局工具实现，不引入新的自定义样式体系。

## 测试

更新租约列表现有测试，至少验证：

- 表头包含“房源”“租客”“租期”“月租”“状态”“合同”“操作”。
- 不再出现“租约信息”表头。
- 房号、项目/楼栋、租客姓名、脱敏手机号、租期、格式化月租、状态和合同份数均能正确展示。
- 无合同文件时仍展示“未归档”。
- 现有编辑入口、预览入口和更多操作行为不受影响。

## 完成标准

- 列表中不再渲染原聚合副标题。
- 用户可以沿列快速比较房源、租客、租期和月租。
- 当前筛选、分页、状态操作、合同任务队列和抽屉流程保持不变。
- 相关前端测试与类型检查通过。
