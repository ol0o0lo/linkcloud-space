# Frontend Admin 功能闭环设计

## 目标

把管理端审查中确认的认证与注册、邀请裂变、通知偏好、平台订阅处置、配房分享生命周期和 RBAC 导航六类断点改成真实可完成、可恢复、可回看的业务流程。

## 设计原则

- 复用现有 allauth headless、Ninja API、React Query、Ant Design 和 Umi access，不建立第二套认证或权限体系。
- 自动生成客户端保持只读；新接口先由 `src/services/manual` 提供薄适配，后续统一重新生成时再替换。
- 所有公开认证入口统一落在 `/dashboard/user/*`，同时保留旧 `/accounts/*` 的前端兼容跳转，避免历史邮件与分享链接继续 404。
- 每个流程必须同时具备加载、成功、失败、重试和权限不足状态；关闭弹窗或刷新页面后，已产生的业务状态仍能重新获取。

## 1. 认证与公开注册

### 路由

- `/user/login`：密码、邮箱验证码、Passkey、GitHub 登录入口。
- `/user/register`：真实 allauth 注册，支持手机号验证和邀请码。
- `/user/verify-phone`：完成注册或登录中待处理的手机验证并支持重发。
- `/user/password/reset`：发起密码重置邮件。
- `/user/password/reset/key/:key`：校验重置 key 并设置新密码。
- `/user/confirm-email/:key`：确认邮箱。
- `/user/social/error`：展示第三方登录错误并返回登录页。

后端 `HEADLESS_FRONTEND_URLS` 直接指向 `/dashboard/user/*`。`SPA_URLS` 改为当前管理端真实地址。登录页的“忘记密码”与“注册”使用 Umi Link，不再使用 `href="#"`。

### 数据流

注册页提交邮箱、E.164 手机号和密码到 allauth signup。若返回 `verify_phone` 待处理流，跳转手机验证页；验证成功后恢复用户与组织初始状态，再跳转安全的 `redirect`。邀请码通过当前请求 query/session 归因，不进入用户模型。

密码重置和邮箱确认均直接消费生成的 allauth API。Passkey 使用浏览器 WebAuthn API，把二进制字段做 base64url 转换后提交 generated client；GitHub 使用同步 form POST 发起 provider redirect。

## 2. 邀请裂变

- 分享地址改为 `/dashboard/user/register?invite_code=...&referral_source=link`。
- 注册页允许填写邀请码，并明确展示分享链接携带的邀请码。
- `allow_link` 控制是否返回分享链接；`allow_code` 控制手工邀请码归因；链接和手工码通过 `referral_source` 区分。
- 实名触发时，`requires_manual_review=true` 进入待审核；为 false 时自动发奖。
- 发奖同时按配置给邀请人和受邀人入账，各自使用独立幂等键；金额为 0 时不生成流水。

## 3. 通知偏好

通知设置页从 `/api/notifications/preferences/` 查询真实类别。每一行分别显示站内信和邮件开关；必选渠道保持开启并禁用。切换时只 PATCH 当前类别和渠道，失败回滚并显示错误，成功后以服务端响应更新缓存。

## 4. 平台订阅处置

新增超级管理员 `/super-admin/subscriptions` 页面，包含：

- 订单列表：组织、订单号、套餐、金额、状态、退款状态；可登记部分/全额退款及订阅保留/立即结束。
- 开票列表：组织、订单、抬头、状态；可更新处理中、已开票、驳回，并填写发票号、文件地址和备注。

后台序列化补充组织名称、组织 ID 和订单号，确保平台人员能够识别处置对象。所有动作完成后刷新当前表格，失败保留表单。

## 5. 配房分享生命周期

`HouseMatchShare` 增加 `revoked_at`、`view_count` 和 `last_accessed_at`。管理 API 增加我的分享列表、延期和失效操作；公开信息接口只在成功读取分享概览时累计一次访问。失效后的公开访问返回 410。

生成弹窗增加“历史链接”区域，可重新复制、延期和立即失效。新链接创建后进入同一历史列表，不再提示“关闭后不会保留入口”。第一版只管理当前用户在当前组织创建的链接，避免普通成员操作他人链接。

## 6. RBAC 导航

新增当前组织导航能力 API，返回角色、组织设置、团队设置、订阅、经营分析、收益分配和租户通知分发等布尔能力。`getInitialState()` 在组织上下文确定后加载一次，`src/access.ts` 把能力映射为 Umi access key，路由在渲染菜单和进入页面前共同校验。

超级管理员平台菜单仍使用 `canSuperAdmin`。没有对应权限的普通成员不再先看到菜单再收到 403。

## 错误处理与安全

- 认证跳转只接受同源相对地址，并统一通过管理端 base 归一化。
- 所有公开 token/key 页面不把密钥写入日志或消息；错误只展示可执行提示。
- 退款金额继续由后端校验，不在前端复制最终业务规则。
- 分享失效采用可审计时间字段，不物理删除记录。
- 权限 API 只返回布尔能力，不暴露角色绑定细节。

## 验收

1. allauth 配置中的每个前端 URL 都能由管理端路由承接。
2. 注册、手机验证、忘记密码、邮箱确认至少有组件测试和后端流程测试。
3. 邀请配置的四个业务字段会改变真实行为，邀请人和受邀人奖励均有幂等测试。
4. 通知开关刷新后保持，必选渠道不能关闭，失败会回滚。
5. 超级管理员能查询并处置退款/开票，普通用户路由不可见。
6. 配房链接可列表、复制、延期、失效并显示访问统计，失效链接公开访问返回 410。
7. 不具备权限的菜单在导航阶段隐藏，直接访问仍由后端拒绝。
