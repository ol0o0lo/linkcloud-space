# 房源筛选浮层滚动锁设计

## 背景与目标

公开找房页面的悬浮筛选气泡目前使用固定遮罩覆盖页面，但没有锁定页面自身的滚动。用户在气泡或遮罩区域上下滑动时，底层房源列表仍可能滚动，形成滚动穿透。

本次目标是统一约束所有房源筛选浮层：任意筛选气泡、区域/地铁抽屉或其他筛选面板打开期间，底层页面不得滚动、下拉刷新或跟随触摸手势移动；关闭浮层后恢复原滚动位置和正常交互。

## 范围

- 独立找房页 `frontend_miniprogram/src/pages-housing/search/index.vue`：附近、租金、户型、面积、区域/地铁等筛选浮层。
- 房源 Tab 页 `frontend_miniprogram/src/pages/houses/index.vue`：公开找房模式下的附近、区域/地铁及其他筛选面板。
- 已由 Wot UI `Popup` 提供 `lock-scroll` 的底部抽屉继续保留组件自身的锁定能力；页面级锁作为统一保障。
- 不改变筛选条件、视觉样式、弹出位置、确认逻辑和遮罩点击关闭行为。

## 方案

采用“页面级滚动锁 + 遮罩触摸阻断”的双重方案。

### 页面级滚动锁

每个房源筛选页面维护一个只读的“筛选浮层是否打开”状态。只要任意筛选气泡或筛选抽屉处于打开状态，页面模板首节点的 `page-meta` 就把页面样式设置为 `overflow: hidden`；所有筛选浮层关闭时恢复为可滚动状态。

锁定状态必须由现有浮层状态派生，不额外维护第二份可变布尔状态，避免关闭、确认、重置或页面卸载时出现锁未释放的问题。

### 遮罩触摸阻断

自定义气泡的全屏遮罩除保留点击关闭外，还需要阻止并终止 `touchmove`。这用于兜住部分移动端环境中固定遮罩上的触摸手势，避免事件继续传递到底层页面。

触摸阻断只放在遮罩层，不放在整个浮层容器。筛选按钮、输入框和浮层内部可滚动区域仍应正常响应操作。

### 浮层内部滚动

当前小型气泡内容在正常设备高度内无需独立滚动。如果后续筛选内容超过可视高度，应使用浮层内部的纵向 `scroll-view`，页面级锁仍保持开启。区域/地铁底部抽屉现有的内部 `scroll-view` 不受影响。

## 状态与交互流程

1. 用户打开任意房源筛选浮层。
2. 页面根据现有筛选状态立即启用 `overflow: hidden`。
3. 遮罩拦截底层触摸移动；浮层内容继续可点击、输入和内部滚动。
4. 用户点击遮罩、确认、重置或切换并关闭浮层。
5. 所有筛选浮层均关闭后，页面解除滚动锁并停留在打开浮层前的滚动位置。

多个浮层状态切换时，只要仍有一个筛选浮层打开，页面就不得短暂解除滚动锁。

## 异常与边界处理

- 定位请求、数据加载或校验失败不会单独改变滚动锁；锁定仅取决于浮层是否仍显示。
- 页面离开或组件卸载时，响应式页面状态随页面销毁，不保留全局锁定副作用。
- 地铁或区域底部抽屉继续使用 Wot UI 的 `lock-scroll`，与页面级锁同时存在时不改变关闭和滚动恢复行为。
- 打开浮层前页面已经滚动时，锁定和解锁不得把页面跳回顶部。

## 验收标准

- 在微信小程序和 H5 中，将房源列表滚动到任意位置后打开每一种筛选浮层，向上或向下滑动遮罩，底层列表位置不变。
- 在气泡内容区域滑动时，底层列表同样不移动；需要内部滚动的筛选内容可以正常滚动。
- 点击遮罩仍能关闭气泡。
- 确认、重置或关闭筛选后，页面从原位置继续滚动，不发生跳顶或残留锁定。
- 连续切换不同筛选气泡时，底层页面始终保持锁定。

## 测试策略

- 更新房源筛选结构测试，断言相关页面存在由筛选浮层状态驱动的 `page-meta` 滚动锁。
- 断言自定义筛选遮罩具有触摸移动阻断，且保留点击关闭。
- 运行小程序 ESLint、TypeScript 类型检查、相关单元测试和微信小程序生产构建。
- 在微信开发者工具与 H5 各执行一次人工滚动穿透验收，覆盖打开、切换、确认、重置和遮罩关闭。
