# 组织 SaaS 付费订阅设计（一期）

日期：2026-07-24  
状态：已确认，待实现计划

## 1. 目标与边界

为 `Organization` 提供组织级 SaaS 订阅能力：组织可试用、购买、续费、升级套餐，并在套餐有效期内获得对应配额和功能权益。管理端电脑网页与微信小程序均可完成购买，支付渠道统一为微信支付。

本设计不复用个人钱包或提现代付。它们分别处理“平台向个人出款”和“组织向平台购买服务”，资金方向、订单主体及状态机不同。

一期包含：

- 组织级免费版、14 天试用和月付/年付订阅。
- 套餐、价格、配额、功能开关的后台配置与版本化。
- 网页微信 Native 扫码支付、小程序微信 JSAPI 支付。
- 首次购买、续费、即时升级、到期回落免费版。
- 统一权益解析和成员、团队、房源数量配额校验。
- 组织开票资料及管理员线下开票申请处理。

一期不包含：

- 微信自动续费、委托代扣、余额支付和个人钱包抵扣。
- 自助退款、按量计费、优惠券、促销、积分、分账或欠费赊销。
- 付费套餐预定降级；用户只能在当前高档套餐到期后重新购买较低付费套餐。
- 电子发票服务对接和自动开票。
- 集团统一付款、一个付款主体覆盖多个组织。此类真实需求出现后再引入独立付款主体模型。

## 2. 核心决策

| 决策 | 一期规则 |
| --- | --- |
| 计费主体 | `Organization` 直接作为付费主体，不增加一对一的独立付款主体模型 |
| 套餐 | 免费版常驻；标准版、专业版、企业版支持月付和年付 |
| 试用 | 新组织可获一次专业版 14 天试用；创建人须已验证手机号，且其一生最多让 3 个组织获得试用 |
| 到期 | 试用、付费订阅到期后自动回落免费版，保留超额历史数据但禁止继续新增 |
| 支付端 | 管理端电脑网页为微信 Native 扫码支付；小程序为微信 JSAPI 支付 |
| 续费 | 手动续费，到期前通知，不做自动扣款 |
| 同套餐续费权益 | 付款成功时立即更新为该套餐当前权益配置，同时叠加有效期 |
| 升级 | 仅套餐向上升级，立即生效且保持原计费周期；按固定周期剩余天数折抵 |
| 周期切换 | 月付/年付切换仅作为下一周期续费，保留当前有效期，不做即时折算 |
| 降级 | 低档付费套餐须在当前周期结束后重新购买；到期默认回落免费版 |
| 退款 | 无自助退款；管理员可对每笔订单最多人工退款一次，金额可为部分或全额 |
| 开票 | 组织可维护资料并申请，平台管理员线下处理 |
| 存量组织 | 上线时统一使用免费版；保留超额历史数据，但后续新增遵守免费版配额 |
| 创建组织 | 全局上限由后台配置，初始为每位已验证用户 3 个；归档或转移 owner 可释放创建额度 |
| 计费时长 | 月付固定 30 天，年付固定 365 天；同一组织有效订阅最多累计 3 年 |
| 收款主体 | 平台公司统一作为微信商户和开票主体 |

## 3. 套餐目录与版本

### 3.1 初始套餐

以下数值为后台初始化的可编辑默认值。金额以人民币展示，持久化时一律使用分。

| 套餐 | 月付 | 年付 | 成员 | 团队 | 房源 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 免费版 | ¥0 | ¥0 | 3 | 1 | 50 |
| 标准版 | ¥99 | ¥999 | 10 | 3 | 500 |
| 专业版 | ¥299 | ¥2,999 | 30 | 10 | 3,000 |
| 企业版 | ¥699 | ¥6,999 | 100 | 30 | 20,000 |

功能开关以键值形式维护，首批预留：`data_export`、`business_analytics`、`batch_operations`、`advanced_access_control`、`api_integration`。权益未被具体业务实现时，不得仅凭套餐在界面上声称已提供该能力。

### 3.2 配置原则

- `Plan` 保存稳定的套餐编码、展示名称、描述、展示排序及上/下架状态。编码一旦启用不得改名或复用。
- `PlanPrice` 保存套餐的月付或年付价格版本、生效状态和展示信息。
- `PlanEntitlement` 保存套餐的数量上限和功能开关版本。
- 修改价格、配额或权益时创建新版本；不覆盖旧版本。
- 下架套餐后，不能再新购；已生效的订阅在没有新的同套餐续费或向上升级成功前，仍按当前权益快照享有权益直到到期。
- 订单和支付流水保存套餐、价格、权益快照。后台改价或改配额不会直接追溯修改现有订阅；同套餐续费或向上升级付款成功时，订阅立即刷新为当前套餐权益配置。
- 套餐向上升级直接按当前展示排序判断；后台调整排序会改变升级方向，管理页必须明确提示这一影响。
- 平台超级管理员可直接发布新的价格或权益版本，无需填写变更说明；系统仍自动记录操作者、前后版本与时间。

## 4. 领域模型

建议新建 `apps.subscriptions`，其边界是“组织购买平台服务”，不处理个人钱包、租赁经营账单或第三方出款。

数据库表统一使用 `subscriptions_` 前缀，避免与现有租赁财务账单及钱包表混淆。

为执行组织创建和试用风控，`organizations.Organization` 增加不可变的 `created_by`（可空、用户删除时置空）。从上线后创建的组织，该字段记录创建人；存量组织保持为空，不占用任何人的创建或试用额度。创建额度统计“由该用户创建、当前未归档且该用户仍为 owner”的组织数，因此归档或转移 owner 会释放创建额度；试用额度则按 `Subscription.trial_granted_to` 的历史试用记录累计，永不释放。

### 4.1 `Subscription`

订阅直接关联 `Organization`，一组织仅保存一条当前订阅记录，表示当前试用或付费服务状态及其累计有效期。

关键字段：

- `organization`（一对一）、`source_order`（最近一次生效订单；试用可为空）。
- `kind`：`trial` 或 `paid`。
- `status`：`trialing`、`active`、`ended`。
- `plan_snapshot`、`price_snapshot`、`entitlement_snapshot`。
- `billing_cycle`：`month` 或 `year`；试用为空。
- `starts_at`、`ends_at`、`ended_at`。
- `trial_started_at`、`trial_ended_at`、`trial_granted_to`：永久保留试用资格事实，即使后续已转为付费订阅也不清除。

同一组织始终只有一条当前订阅记录。试用结束后记录保留并转为 `ended`；首次付费或升级后在同一记录上更新状态、套餐/权益快照和有效期。组织是否已使用试用由 `trial_started_at` 判定；同时，创建人一生最多为 3 个组织获得试用资格。归档或转移组织 owner 可以释放创建组织额度，但不会释放已消耗的试用资格。

### 4.2 `SaaSOrder`

一笔向平台购买 SaaS 服务的不可变交易事实，直接关联组织。

关键字段：

- `organization`、全局唯一 `order_no`。
- `order_type`：`initial_purchase`、`renewal`、`upgrade`。
- `status`：`pending_payment`、`paid`、`closed`、`payment_failed`。
- `close_reason`：`timeout`、`superseded` 或 `provider_failed`，用于区分迟到支付的处理规则。
- `refund_status`：`none`、`partial`、`full`；并保存单次 `refunded_amount`、退款原因、线下退款凭证、订阅处理动作、操作者和时间。
- 目标套餐、计费周期和套餐/价格/权益快照。
- `list_amount`、`credit_amount`、`payable_amount`，均为分。
- `expires_at`、`paid_at`、`closed_at`、`created_by`。

用户提交的价格、折扣、套餐权益均不可信；服务端仅以当前可售版本和当前有效订阅计算订单。组织侧仅提供订单与支付历史的只读查询，不提供取消、修改或退款等订单操作。

### 4.3 `PaymentTransaction`

记录一次支付渠道请求及其最终事实。

关键字段：

- `order`、`provider`（一期为 `wechat`）、`payment_mode`（`native` 或 `miniprogram`）。
- 本地唯一交易号、渠道交易号、渠道状态、支付完成时间。
- 已脱敏的请求与响应摘要；确需保留的敏感原文使用加密字段。
- 回调事件标识或等效去重键。

微信渠道交易号必须唯一；同一订单的重复回调只返回已处理结果，绝不重复激活订阅。

### 4.4 开票模型

- `OrganizationInvoiceProfile`：一对一关联组织，保存类型、抬头、税号、收件邮箱及可选企业开票资料。
- `InvoiceRequest`：一对一关联已支付 `SaaSOrder`，状态为 `pending`、`processing`、`issued`、`rejected`、`cancelled`。
- 管理员线下开票后填写发票号码、开票日期、备注与电子文件/下载链接。

开票状态不影响支付、订单、订阅和权益。订单未退款时，可在财务记录保留期间申请发票；已开票订单退款不阻塞，冲红或作废由管理员线下跟进。

### 4.5 应用结构与迁移

```text
apps/subscriptions/
  models.py          # 套餐、价格/权益版本、订阅、订单、支付、开票与审计表
  constants.py       # 计费周期、订单/支付/订阅状态
  services.py        # 下单、支付回调、续费、升级、到期处理
  entitlements.py    # EntitlementService：唯一权益和配额入口
  wechat_client.py   # Native、JSAPI、查单、关单、验签与解密
  api.py             # 组织侧、平台侧、微信回调接口
  schemas.py
  tasks.py           # 订单关单、订阅到期、通知
  admin.py
```

迁移按以下顺序执行：

1. 在 `organizations` 增加 `Organization.created_by`，并创建 `subscriptions_plan`、`subscriptions_plan_price`、`subscriptions_plan_entitlement`、`subscriptions_subscription`、`subscriptions_saas_order`、`subscriptions_payment_transaction`、`subscriptions_organization_invoice_profile`、`subscriptions_invoice_request` 及审计表。
2. 通过数据迁移写入四档初始套餐、月付/年付价格和默认权益。
3. 通过访问控制迁移写入 `subscriptions.subscription_view`、`subscriptions.subscription_manage` 权限。
4. 接入组织创建 Hook：仅已验证手机号、仍有试用资格的新创建组织生成一次专业版试用订阅；创建组织全局上限使用后台配置，初始为每人 3 个。
5. 接入成员、团队、房源创建服务，在写入前调用 `EntitlementService`。

既有组织不补发试用订阅，也不创建免费订单；`EntitlementService` 在没有有效订阅时直接返回免费版权益。当前 `Organization.member_limit` 与 `team_limit` 不再作为订阅配额来源，先从组织资料 API 和设置页面移除编辑/读取，旧数据库列暂时保留但不参与业务判断。存在订阅、支付或开票记录的组织禁止物理删除，只能归档。

## 5. 权限与权益

### 5.1 权限

- 组织 owner 自动可查看和管理本组织订阅。
- 非 owner 需要 `subscriptions.subscription_view` 才能查看，需 `subscriptions.subscription_manage` 才能购买、续费、升级及维护开票信息。
- 平台超级管理员管理套餐目录、价格版本、订单异常和开票申请。
- 管理员不能手工将待支付订单直接标记为已支付；订阅开通只能由支付成功或受审计的人工异常流程触发。

### 5.2 `EntitlementService`

提供单一接口，以组织为输入，输出当前有效套餐、权益、配额、用量和到期时间：

1. 优先读取尚未到期的 `trialing` 或 `active` 订阅快照。
2. 没有有效订阅时返回免费套餐的当前权益版本。
3. 业务模块只能通过此服务判断权限和配额，禁止各自读取订阅字段或复制套餐规则。

一期接入成员、团队、房源三个“新增”入口。成员计数包含 owner 和普通成员，待接受邀请不占名额且必须在接受时再次校验。房源默认计入当前组织的全部房源，不区分空置或已租状态；其统计口径可作为权益版本配置。若当前用量已达到配额，服务端返回统一 `QUOTA_EXCEEDED`，包含当前用量、上限和升级引导所需信息。超额既有数据始终可查看、编辑和删除，只禁止增加数量。

## 6. 订单、支付与订阅状态机

### 6.1 创建与支付

1. 有权限的成员选择套餐或计费周期；一次操作只能修改其中之一。套餐仅可向上升级，升级时保持现有周期；月付/年付切换仅作为下一周期续费。
2. 服务端校验目标套餐可售、变更类型合法，并重新计算价格和可用折抵，创建 30 分钟有效的订单与支付流水。组织生成新二维码时，系统主动关闭该组织旧的待支付订单。
3. 管理端电脑网页返回微信 Native `code_url` 并展示二维码；小程序返回 JSAPI 调起参数。
4. 前端轮询订单状态。客户端调起支付的返回结果不能作为开通依据。
5. 微信回调验签、解密后，以渠道交易号和本地订单号双重幂等地推进状态。
6. 同一数据库事务内完成支付流水成功、订单已支付、订阅激活/延长/替换和权益生效。

待支付订单超过 30 分钟后由定时任务关闭，并向微信主动关单。因自然超时而关闭的订单若微信最终确认支付成功，仍自动开通；因生成新二维码而被替代关闭的订单若迟到支付成功，进入人工退款/异常处理，不自动改变订阅。

### 6.2 生效规则

- 首次购买：将组织当前订阅更新为付费状态，立即替换试用或免费权益。
- 续费：允许任意时刻购买；若当前订阅尚未到期，从当前结束时间顺延，若已到期则从支付成功时间起计算。月付固定延长 30 天，年付固定延长 365 天；同一组织累计有效期不得超过 3 年。同套餐续费支付成功后立即刷新订阅的权益快照为当前套餐版本。
- 升级：新套餐立即生效且保持原计费周期。折抵额为 `旧订阅已付金额 × 剩余天数 ÷ 原周期总天数`，向下取整，且不超过新订单原价；新订单应付金额必须大于零。
- 到期回落免费版：试用和付费订阅到期任务直接将订阅标记为 `ended`，权益服务自动返回免费版。
- 购买较低付费套餐：当前套餐到期后重新发起购买。系统不保存“低档套餐预定降级”，不产生应收账款。

### 6.3 状态约束

- `SaaSOrder` 通常从 `pending_payment` 进入 `paid`、`closed` 或 `payment_failed`。仅当 `close_reason=timeout` 且微信最终查证支付成功时，允许从 `closed` 进入 `paid`；`close_reason=superseded` 的订单迟到支付只能进入人工异常流程。
- `paid` 为支付终态；发生退款后保持支付终态，以订单的 `refund_status` 和退款字段表达部分或全额退款。管理员明确选择“保留订阅”或“立即结束订阅”，不回滚已存在的支付事实。
- `Subscription` 仅在到期或支付成功时迁移状态；无有效订阅时免费权益由计算得出，而不是创建免费订单。
- 自动任务扫描付费和试用订阅的到期时间，标记结束后触发通知。

## 7. 接口与界面

组织侧 API 分为：套餐和权益查询、当前订阅查询、创建支付订单、订单与支付历史只读查询、续费/升级、开票资料和开票申请。支付回调入口不使用用户认证。管理端二维码可由任意微信用户代付；订单创建权限仍只授予组织 owner 或订阅财务成员。小程序 JSAPI 支付要求当前发起成员已绑定微信小程序账号。

平台侧 API 分为：套餐/价格/权益版本管理、订单/支付流水查询与异常关闭、订阅查询、开票申请处理。所有列表遵循项目统一的 `page`、`page_size` 分页结构。

管理端电脑网页提供套餐对比、订单确认、扫码支付、只读支付历史、订阅与用量页、开票资料和申请页。手机端网页不单独建设 H5 收银台，提示用户前往小程序。小程序提供同等的套餐选择、JSAPI 支付、订单与订阅查看能力。

## 8. 通知、审计与安全

- 向组织 owner 及具备订阅管理权限的成员发送试用开始、试用将到期、订单待支付、支付成功、订阅将到期和回落免费版通知。
- 后台配置变更、价格版本发布、订单关闭、人工退款和开票处理均自动记录操作者、时间与前后状态；发布价格或权益不强制填写变更说明。
- 回调必须使用微信支付证书验签和资源解密；验签失败不修改任何订单、支付或订阅状态。
- 金额只在服务端计算并以分保存；订单、支付、订阅行在关键状态变更时使用事务和行锁。
- 税号、银行账号、支付报文等敏感数据按最小必要原则加密保存、脱敏显示，不进入普通日志、异常信息和通知正文。

真实收款上线前必须确认平台公司微信支付商户主体、Native 支付和 JSAPI 支付产品权限，以及商户号与小程序 AppID 的绑定关系；该外部前置不改变本设计的数据模型，但未完成前不得启用真实收款。

## 9. 定时任务与验证

Celery 定时任务负责关闭超时待支付订单、处理试用/订阅到期，以及发送订阅生命周期通知。支付回调为主，订单状态查询仅用于前端展示和异常排查。

至少覆盖以下测试：

- 手机验证创建组织、全局创建额度、试用资格上限，以及归档/转移 owner 对两类额度的影响。
- 组织级试用资格、有效订阅唯一性和免费版回落。
- 套餐/价格/权益版本变化不影响历史订单与订阅快照。
- 权限隔离、三类数量配额和超额资源保留规则。
- 网页扫码与小程序支付订单创建，前端金额篡改拒绝，以及小程序微信绑定校验。
- 微信回调验签、重复回调、自然超时迟到支付自动开通、替代订单迟到支付异常处理，以及订单超时关单。
- 首购、提前续费、固定 30/365 天周期、升级折抵、到期回落、低档套餐重新购买与 3 年累计有效期上限。
- 开票资料授权、订单唯一开票申请、人工处理状态和敏感字段脱敏。

## 10. 后续扩展

当出现明确业务需求时，可在不改变一期订单事实的前提下增加自动续费、优惠券、按量计费、退款自动化、电子发票、组织集团代付和独立付款主体模型。
