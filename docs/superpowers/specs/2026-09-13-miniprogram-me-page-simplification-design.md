# 小程序“我的”页简化设计

## 目标

减少“我的”页首屏中的静态账户信息和重复分组，让用户优先看到身份、常用账户能力及当前身份对应的服务；将资料维护、安全设置与退出登录集中到二级设置页。

## 信息架构

- 顶部资料卡保留头像、用户名称和当前身份。
- 身份切换合并进顶部资料卡，使用紧凑入口打开原有身份选择面板，不再单独展示三个身份按钮。
- 常用服务保留“我的钱包”“实名认证”“我的推广”。
- 邮箱、手机号、个人资料、账号安全移入“设置”页。
- 房东服务与组织管理继续按现有权限和身份条件展示。
- 首页底部只保留“设置”入口；退出登录放在设置页底部，并继续要求二次确认。

## 页面布局

### “我的”页

1. 紧凑资料卡：头像、名称、身份切换入口。
2. 常用服务卡片：钱包、实名认证、推广。
3. 条件服务卡片：公开店铺或组织管理中心。
4. 设置入口卡片：副文案为“资料、绑定与账号安全”。

页面不再展示“已登录”标签、邮箱、手机号和醒目的红色退出按钮，也不再为每个单项分组增加大字号标题。

### “设置”页

1. 账户资料：个人资料、邮箱、手机号。
2. 安全：账号安全。
3. 退出登录：使用低干扰的危险文字按钮，点击后沿用现有确认弹窗与退出流程。

## 行为与兼容性

- 身份切换继续复用 `AppModeSwitcher` 和现有 action sheet 行为。
- 所有页面跳转继续通过 `APP_ROUTES` 管理。
- 设置页加入受保护账户路由，未登录用户仍由现有路由守卫处理。
- 不修改后端接口、状态仓库、生成代码、多语言文件或依赖文件。

## 验证

- 运行小程序前端类型检查或项目现有快速检查。
- 检查“我的”页在普通租客、房东、组织身份下的条件入口。
- 检查身份切换、设置页跳转、手机号未验证跳转和退出登录确认流程。
