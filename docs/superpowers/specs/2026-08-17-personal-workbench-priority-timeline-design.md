# 个人工作台重点待办时间轴重构设计

## 背景

个人工作台的“重点待办”当前使用横向表格展示任务。表格列较多，在工作台卡片宽度内信息拥挤，并产生横向滚动；任务标题、截止时间与操作之间的视觉优先级不够清晰，少量任务时还会形成明显留白。

## 目标

- 将重点待办改为以截止时间为主线的纵向时间轴。
- 强化任务标题、紧急程度、状态和截止时间的层级关系。
- 移除该区域的横向滚动，改善桌面端和移动端表现。
- 保留现有接口、数据、跳转和任务操作逻辑。

## 范围

本次只重构个人工作台的“重点待办”卡片，不调整顶部待办概览、右侧任务进展与常用入口，不修改后端接口和任务排序规则。

## 布局与视觉

重点待办继续位于主内容列，保留卡片标题、说明和“查看全部”入口。卡片主体由 Ant Design `Table` 改为语义化任务列表：

- 左侧显示时间标签与时间轴节点。
- 右侧显示任务内容卡片。
- 任务标题是第一视觉层级。
- 优先级、状态、逾期标记和所属团队作为辅助信息排列在标题下方。
- 截止时间与当前可执行操作位于任务内容右侧。
- 相邻任务使用连接线建立时间顺序；逾期节点使用错误色，今日或临近截止节点使用主色或警示色，其余节点使用中性色。

视觉实现优先复用 Ant Design 主题 token 与 `antd-style`，不引入额外样式依赖。

## 时间与排序表达

有截止时间的任务继续使用后端返回的 `urgent_items` 相对顺序。前端只做一次稳定分组，将没有截止时间的任务移动到列表末尾；无截止时间任务之间仍保持后端原始顺序。

截止时间显示规则：

- 已逾期任务显示“已逾期”，并以错误色强调具体时间。
- 当天截止显示“今天”，同时显示时分。
- 次日截止显示“明天”，同时显示时分。
- 其他有截止时间的任务显示月日，必要时显示年份和时分。
- 没有截止时间的任务统一显示“未设置”，并通过稳定分组放在时间轴末尾。

## 交互

- `pending` 状态保留“接受”操作及单项加载状态。
- `in_progress` 状态保留“完成”操作及单项加载状态。
- 每个任务保留“查看”入口，跳转到带 `assignment_id` 的任务页。
- “查看全部”继续进入全部任务页。
- 操作按钮使用清晰文本或紧凑按钮，不仅依赖图标表达含义。
- 任务项支持键盘聚焦，链接与按钮保持可访问名称。

## 响应式

- 桌面端采用“时间标签 / 节点 / 任务内容”的三列结构。
- 窄屏下取消独立时间列，将时间标签收进任务内容顶部；时间轴节点与连接线保留。
- 任务操作允许换行到内容底部，避免横向滚动。
- 文本可自然换行，任务标题不做单行截断。

## 状态处理

- 加载状态继续由工作台查询驱动，使用与新版列表尺寸匹配的加载占位或 `Spin`。
- 查询失败继续使用页面顶部错误提示和“重新加载”按钮。
- 无重点待办时保留成功语义的空状态，但缩短最小高度，减少大面积空白；继续提供“查看全部任务”和“查看公告”入口。

## 组件边界

在现有工作台页面内抽出只负责单个任务展示的私有组件，接收任务记录、当前 mutation 状态和操作回调。页面组件继续负责请求、mutation、跳转与空/错/加载状态，避免展示结构和数据逻辑相互缠绕。

## 验证

- TypeScript 检查和 Biome lint 通过。
- 补充针对截止时间文案与操作可见性的最小测试；如果现有页面测试环境不适合完整渲染，则至少覆盖抽取的纯格式化函数。
- 手工确认桌面宽度和移动端宽度下无横向滚动。
- 手工确认待接受、进行中、逾期、无截止时间和空列表状态。

## 非目标

- 不修改任务 API、任务排序算法或后端模型。
- 不调整工作台其他卡片。
- 不新增筛选、批量操作、拖拽排序或动画。
