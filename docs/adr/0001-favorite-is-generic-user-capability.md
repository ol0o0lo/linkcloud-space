# 将收藏定义为普通用户通用能力

收藏归属于普通用户，而不是租户或某个具体业务域。平台使用统一的 `Favorite` 关系、服务与 `/api/users/me/favorite/` 接口维护用户和公开业务对象之间的关系，公共协议以稳定的 `target_type + target_id` 标识目标，不直接暴露 Django `ContentType`。

收藏核心只提供模型、注册表、分页解析和幂等状态切换，不导入房源、文章、商品或经营分析等具体业务，也不包含埋点事件代码。每个业务应用自行实现并注册目标适配器，负责目标 ID 规范化、公开可见性、安全业务数据以及通用 `display` 摘要；客户端通过 `/api/users/me/favorite/type/` 获取当前已注册类型，并为没有专用渲染器的类型使用通用摘要卡片。

`Favorite` 关系存在表示用户当前已收藏，取消收藏会物理删除关系。API 使用关系的 `created_at` 表示本次收藏时间；取消后再次收藏会创建新关系和新的 `created_at`。

Analytics 在自身应用中通过 `post_save` 监听 `Favorite(created=True)`，并记录 `house.favorite`。重复 `PUT` 不创建关系，因此不埋点；`DELETE` 不触发；再次收藏会创建新关系并再次记录。删除收藏关系不会删除或修改已经形成的 Analytics 历史事实。`HouseFavorite` 仅作为历史迁移兼容模型保留，新写入统一进入 `Favorite`。

相比每个业务独立建表，该方案统一了幂等、物理取消、目标下架后的保留行为和客户端缓存协议；相比由后端完全配置页面，后端只声明可用类型和通用摘要，前端业务模块仍可注册专用展示逻辑，从而同时保留动态扩展能力和业务表现力。
