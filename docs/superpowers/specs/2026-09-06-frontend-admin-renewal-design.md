# frontend_admin 手动续费闭环设计

## 目标

让当前空间的付费订阅用户能够在到期前续订同一套餐，并清楚理解续费周期、金额和生效规则；试用用户可以开通当前试用套餐的正式版本。

## 范围

- 仅修改管理端套餐页及其测试。
- 复用现有套餐订单、微信 Native 支付、订单轮询和购买记录能力。
- 不修改后端接口、生成 API 客户端、站内通知任务和待支付订单查询。

## 交互设计

### 当前套餐操作

- 免费版当前套餐继续显示“当前使用”，不可续费。
- 试用中的当前付费套餐显示“开通正式版”。
- 服务中的当前付费套餐显示“续费{套餐名}”。
- 非当前且更高档套餐仍显示“升级至{套餐名}”。
- 低档套餐仍显示“不可降级”。

所有购买、开通、续费和升级动作都调用现有的 `appsSubscriptionsApiCreateOrder`，由后端依据当前订阅自动判定 `initial_purchase`、`renewal` 或 `upgrade`。

### 临期提醒

- 当前付费订阅剩余 30 天以内时，在当前套餐摘要卡内显示 warning 提醒。
- 文案包含剩余天数、绝对到期日期，以及“续费后从当前到期日顺延”。
- 提醒提供“立即续费”按钮，滚动并聚焦当前套餐的续费按钮，避免在页面中复制计费周期选择器。

### 支付确认信息

- 扫码支付弹窗识别当前订单动作。
- 续费时标题信息显示“套餐续费”，并提示“支付成功后将从当前到期日顺延”。
- 试用转付费显示“开通正式版”。
- 升级与首次购买沿用现有信息。

## 状态与异常

- 下单中沿用现有 loading，防止重复点击。
- 下单失败沿用项目统一请求错误提示。
- 支付成功、关闭、失败和取消沿用现有轮询与反馈。
- 续费最多累计三年的限制继续由后端校验并返回明确错误。

## 测试

- 当前付费套餐显示续费按钮，点击后提交当前套餐和当前计费周期。
- 当前试用套餐显示开通正式版按钮。
- 免费版当前套餐不显示续费按钮。
- 30 天内显示临期提醒，超过 30 天不显示。
- 续费支付弹窗显示顺延说明。

## 非目标

- 自动续费或代扣。
- 站内信、短信、邮件到期提醒。
- 刷新后恢复待支付订单。
- 降级预约或到期后自动切换套餐。
