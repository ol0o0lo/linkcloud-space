# 可自定义工作台设计

## 背景

管理端当前通过 `/rental/workbench/overview` 提供统一工作台入口，并在同一页面中切换“我的工作台”和“空间工作台”。现有页面已经具备任务、公告、房源发布与成交转签能力，但主要区块集中在较大的页面文件中，布局固定，用户不能隐藏、排序或调整组件宽度。

本次改造重新设计两个工作台的全部组件与视觉层级，并加入个人级布局自定义。布局配置继续保存在现有 `UserSetting` 中，但只允许在工作台页面访问和修改，不出现在通用个人设置界面。

## 目标

- 重新设计“我的工作台”和“空间工作台”的组件布局、视觉层级与响应式表现。
- 两个工作台分别保存个人布局，互不影响。
- 用户可以控制组件显示与隐藏。
- 用户可以通过拖拽调整组件顺序。
- 用户可以在组件允许的范围内选择宽度 1、2 或 3。
- 桌面端使用三列栅格；移动端统一单列展示。
- 组件高度由内容决定，不保存或编辑高度。
- 复用现有个人设置存储，不新增数据库表或迁移。
- 保留现有任务接受、任务完成、房源发布和详情跳转等业务能力。

## 非目标

- 不支持任意像素宽度。
- 不支持用户手动调整组件高度。
- 不保存 `x`、`y`、`h` 等二维网格坐标。
- 移动端不支持拖拽或调整宽度。
- 不提供跨用户或组织级工作台模板。
- 不在个人设置中心提供工作台布局入口。

## 设计原则

### 拖拽与布局解耦

`dnd-kit` 只负责改变组件数组顺序。CSS Grid 根据数组顺序和组件宽度进行自动排版。布局状态不绑定像素坐标，因此新增、删除组件或调整响应式断点时，不需要迁移历史坐标数据。

### 组件声明自身能力

每个工作台组件通过注册表声明默认宽度、支持的宽度和默认可见性。布局容器不假设所有组件都支持 1、2、3 三种宽度。

例如：

```ts
type WorkbenchWidgetWidth = 1 | 2 | 3;

type WorkbenchWidgetDefinition = {
  id: string;
  title: string;
  component: React.ComponentType<WorkbenchWidgetProps>;
  defaultWidth: WorkbenchWidgetWidth;
  allowedWidths: readonly WorkbenchWidgetWidth[];
  defaultVisible: boolean;
};
```

组件需要根据自己声明的宽度能力提供相应的内部排版。数据表类组件可以只允许宽度 2、3；快捷入口类组件可以只允许宽度 1、2。

### 配置保持稳定

个人设置只保存组件 ID、宽度、可见性以及数组顺序：

```ts
type WorkbenchWidgetPreference = {
  id: string;
  width: 1 | 2 | 3;
  visible: boolean;
};

type WorkbenchLayoutPreference = WorkbenchWidgetPreference[];
```

不保存标题、组件名称、React 组件引用、允许宽度、坐标或高度。这些能力由当前代码中的注册表决定。

## 设置键

两个工作台分别使用独立设置键：

- `internal.workbench.mine.layout.v1`
- `internal.workbench.space.layout.v1`

版本号放在设置键中。将来如果数据结构发生不兼容变化，可以引入 `v2` 设置键，并安全回退到新版默认布局。

通用个人设置维护页面必须过滤 `internal.` 前缀。内部设置仍存储在 `UserSetting`，并继续允许通过精确 key 的个人设置 API 读取和更新。

## 页面架构

建议将当前工作台页面拆为以下边界：

```text
team-operations/workbench/
├── index.tsx
├── components/
│   ├── WorkbenchLayout.tsx
│   ├── SortableWorkbenchWidget.tsx
│   ├── WorkbenchEditToolbar.tsx
│   ├── WorkbenchCustomizeDrawer.tsx
│   └── WorkbenchWidgetFrame.tsx
├── hooks/
│   └── useWorkbenchLayoutPreference.ts
├── layout/
│   ├── model.ts
│   ├── normalize.ts
│   └── reorder.ts
├── widgets/
│   ├── mine/
│   └── space/
├── registry.ts
├── priorityTimeline.ts
├── view.ts
└── styles.ts
```

职责如下：

- `WorkbenchLayout`：根据组件数组和宽度渲染 CSS Grid，处理桌面和平板断点。
- `SortableWorkbenchWidget`：仅在编辑模式接入 `dnd-kit`，提供拖拽手柄、拖拽覆盖层和占位反馈。
- `WorkbenchWidgetFrame`：统一卡片标题、操作区、加载、错误和空状态外观。
- `WorkbenchEditToolbar`：提供恢复默认、取消和保存操作，并显示未保存状态。
- `WorkbenchCustomizeDrawer`：控制显隐和宽度，只展示组件允许的宽度。
- `useWorkbenchLayoutPreference`：读取、规范化、维护草稿并保存个人设置。
- `registry.ts`：分别导出我的工作台和空间工作台注册表与默认顺序。
- `layout/normalize.ts`：合并注册表和用户配置，清洗未知组件与非法宽度。
- `layout/reorder.ts`：纯函数实现数组排序，便于单元测试。

## 栅格与响应式规则

### 桌面端

- 使用三列 CSS Grid。
- 宽度 1 占一列。
- 宽度 2 占两列。
- 宽度 3 占整行。
- 高度由内容和组件自身样式决定。
- CSS Grid 根据数组顺序自动排布，不补写二维坐标。

### 平板端

- 使用两列布局。
- 宽度 1 占一列。
- 宽度 2、3 均占两列。
- 个人设置中的原始宽度不被修改，回到桌面端后仍按保存值展示。

### 移动端

- 所有可见组件强制占满单列。
- 保留个人设置中的组件顺序和显隐状态。
- 不显示拖拽手柄和宽度控件。
- 可以进入精简自定义模式，但组件管理面板只允许调整显隐。
- 移动端保存显隐变化时，保留原有组件顺序和桌面宽度，不允许修改这两个字段。

## 默认组件设计

所有组件都需要重新设计视觉层级、卡片框架、加载态、错误态与空状态。组件允许的具体宽度由实现阶段根据内容适配结果确定，但必须通过注册表显式声明。

### 我的工作台

默认顺序：

1. 待办概览，默认宽度 3。
2. 优先处理，默认宽度 2。
3. 任务进展，默认宽度 1。
4. 公告摘要，默认宽度 2。
5. 快捷操作，默认宽度 1。

组件职责：

- 待办概览：展示已逾期、今日到期、待接受任务、待确认公告四类汇总指标，四类指标作为一个整体组件控制。
- 优先处理：展示按截止时间与优先级排序的重点任务，保留接受、完成和查看操作。
- 任务进展：展示进行中、今日完成等进展信息，并通过简洁进度视觉强化可读性。
- 公告摘要：展示需要确认或最近发布的公告，提供进入公告详情或全部公告的入口。
- 快捷操作：提供全部任务、公告及其他与当前用户权限匹配的常用入口。

### 空间工作台

默认顺序：

1. 经营总览，默认宽度 3。
2. 发布工作区，默认宽度 2。
3. 关键风险，默认宽度 1。
4. 成交转签，默认宽度 2。
5. 空间快捷操作，默认宽度 1。

组件职责：

- 经营总览：展示在管房源、阻断发布、可发布、待补租客、待签约等关键指标。
- 发布工作区：重组当前发布表格，在宽布局使用表格或分栏列表，在较窄布局切换为紧凑任务列表，保留补资料和发布操作。
- 关键风险：从现有房源发布和转签数据中派生最需要关注的阻塞项，不单独重复请求。
- 成交转签：展示待补租客和待签约任务，保留现有跳转和处理入口。
- 空间快捷操作：提供新增房源、房源列表、租约管理、发布规则等权限相关入口。

## 编辑模式

### 进入编辑

工作台右上角提供“自定义工作台”按钮。点击后：

- 当前已保存配置复制为本地草稿。
- 页面进入编辑状态，卡片显示拖拽手柄和合法宽度选项。
- 显示编辑工具栏和组件管理抽屉入口。
- 禁用“我的工作台 / 空间工作台”视角切换。

正常浏览状态不注册拖拽传感器，不显示拖拽手柄，避免误操作和额外运行开销。

### 拖拽排序

- 使用 `dnd-kit` 的 sortable 能力。
- 只能从卡片标题区域的拖拽手柄开始拖动。
- 拖动过程中显示卡片覆盖层和目标占位反馈。
- 拖动结束只调用数组重排函数，不计算或保存坐标。
- 支持鼠标和键盘拖拽；移动端不启用拖拽。

### 调整宽度

- 卡片标题区和组件管理抽屉都可以调整宽度。
- 宽度选项显示为“窄 / 中 / 宽”，分别对应 1、2、3。
- 不在组件 `allowedWidths` 中的选项禁用或不显示。
- 宽度变化后由 CSS Grid 立即预览重新排布。

### 显示与隐藏

- 组件管理抽屉列出当前视角注册表中的全部组件。
- 关闭组件时保留它的宽度并写入 `visible: false`。
- 重新显示已经隐藏的组件时，将它移动到可见组件末尾，符合组件管理面板中的交互提示。
- 如果配置中不存在该组件，则按注册表默认顺序合并，再由用户继续拖动调整。
- 至少保留一个可见组件；全部关闭时阻止保存并给出明确提示。

### 保存、取消与恢复默认

- 保存：校验草稿后调用个人设置 PUT API，成功后更新 React Query 缓存并退出编辑模式。
- 取消：丢弃草稿并恢复已保存布局；存在变更时二次确认。
- 恢复默认：只将草稿替换为注册表默认布局，用户仍需点击保存。
- 离开页面或刷新：存在未保存更改时提示确认。

## 配置规范化

读取设置后执行以下处理：

1. 非数组值视为无效配置，回退默认布局。
2. 忽略非对象项。
3. 忽略未知组件 ID。
4. 重复 ID 只保留第一次出现的有效项。
5. `visible` 不是布尔值时使用组件默认值。
6. `width` 不在组件 `allowedWidths` 中时使用组件默认宽度。
7. 注册表中存在但配置中缺少的新组件，按注册表默认顺序合并，并使用默认宽度和可见性。
8. 规范化结果保持用户已保存组件的相对顺序。

规范化函数必须是无副作用纯函数，并返回新的数组。

## 数据流

### 布局设置

页面通过精确 key 请求个人设置：

```text
进入页面
  → GET 当前视角布局设置
  → 404：使用默认布局
  → 成功：规范化并渲染
  → 网络错误：渲染默认布局并显示重试提示，禁止保存
```

编辑保存流程：

```text
进入编辑
  → 复制当前布局为草稿
  → 拖拽 / 显隐 / 宽度调整
  → 校验草稿
  → PUT 当前视角布局设置
  → 成功：更新缓存并退出编辑
  → 失败：保留草稿并允许重试或取消
```

### 业务数据

- 我的工作台的待办概览、优先处理和任务进展继续共享每日工作台查询。
- 公告摘要只有在可见时才请求公告列表。
- 空间工作台继续共享房源、待补租客和待签约查询。
- 关键风险从空间工作台已有查询结果派生，不新增重复接口。
- 隐藏且没有其他可见组件依赖的独立数据模块不发起请求。
- 工作台业务查询继续按照当前策略每 60 秒自动刷新，后台标签不刷新。

## 错误处理

- 设置 GET 返回 404：视为用户从未保存过布局，静默使用默认值。
- 设置 GET 网络错误：显示默认布局和非阻塞提示；禁用保存，提供重试入口，避免覆盖可能存在的远端配置。
- 设置 PUT 失败：不退出编辑模式，不丢失草稿，显示错误消息并允许重试。
- 业务数据部分失败：对应组件显示局部错误态和重试操作，不阻塞其他组件。
- 业务操作失败：继续使用统一请求错误处理，不影响布局草稿。
- 配置中出现未知或非法内容：静默规范化；仅开发环境可以记录诊断信息。

## 并发与缓存

- 使用 React Query 缓存精确设置 key。
- 保存成功后直接写入对应查询缓存，避免额外闪烁。
- 我的工作台和空间工作台使用不同查询 key。
- 多标签页同时保存采用最后写入生效，不增加 ETag 或乐观锁。
- 当前视角处于编辑模式时禁用视角切换，避免跨视角草稿混淆。

## 依赖

管理端需要将以下包声明为直接依赖：

- `@dnd-kit/core`
- `@dnd-kit/sortable`
- `@dnd-kit/utilities`

这些包目前可能由 ProComponents 间接安装，但功能代码不能依赖传递依赖。管理端仍使用 npm，并同步更新 `package-lock.json`。

不采用 `react-grid-layout`，因为其二维坐标与固定行高模型不符合高度自适应和稳定配置要求。不采用原生 Drag & Drop，因为触控、键盘和可访问性需要自行补齐。

## 实施复杂度与风险

整体复杂度为中等偏高，但边界清晰，风险主要集中在前端：

- `dnd-kit` 的拖拽覆盖层和目标占位反馈。
- 不同宽度下组件内部排版的适配。
- 编辑草稿、远端配置和默认配置之间的状态切换。
- 设置加载失败时避免意外覆盖远端配置。
- 现有大页面拆分过程中保持业务操作和查询缓存行为不变。

通过将规范化、排序、布局和业务组件拆为独立模块，可以把这些风险限制在可单测的边界内。后端不需要数据库迁移，现有个人设置 API 足以支持本功能。

## 验收标准

- 用户可以分别自定义我的工作台和空间工作台。
- 用户可以隐藏和恢复组件。
- 用户可以拖动组件改变顺序，刷新后顺序保持。
- 用户只能选择组件声明支持的宽度。
- 保存数据中不存在坐标和高度字段。
- 桌面端按三列栅格展示，移动端始终单列。
- 工作台设置不出现在通用个人设置界面。
- 未保存修改可以取消，保存失败不会丢失草稿。
- 新增组件可以在旧配置上自动合并。
- 现有任务、公告、发布和成交转签操作保持可用。
