# Frontend Admin 第三轮高优先级闭环设计

## 目标

以最小改动补齐三个已确认断点：空间切换后的权限状态、认证深链上下文、订阅扫码支付的取消流程。

## 1. 空间切换权限刷新

- 组织选择接口成功后，同时重新获取团队运营能力和导航权限能力。
- 将新的组织列表、当前空间、团队运营能力、导航权限能力一次性写入 Umi 初始状态，避免菜单先后闪烁。
- 切换请求失败时不改变前端当前空间，并显示明确错误提示。
- 能力接口单独失败时仍保留已成功的空间切换，但权限按安全方式回落为空，并提示用户刷新重试。
- 保留现有空间工作台无权限时回到个人工作台的行为。

## 2. 认证深链上下文

- 在 `adminRouting` 中集中提供安全的站内 redirect 解析和认证路径构造函数，拒绝协议相对地址、跨域地址和非法值。
- 登录页的注册、忘记密码入口携带当前安全 redirect。
- 注册页、密码重置申请页、手机验证页返回登录时继续携带 redirect。
- 注册成功或手机验证成功后仍回到原始业务目标，例如空间邀请页。
- 不改变 allauth 生成的邮件重置链接格式；邮件打开的新页面仍按现有登录入口处理。

## 3. 支付取消后重新下单

- 新增组织订阅订单取消接口，只允许取消当前空间、当前仍为待支付状态的订单。
- 取消时将订单更新为 `closed`，关闭原因记为 `user_cancelled`，记录关闭时间，并在事务提交后异步关闭微信订单。
- 已支付、已关闭或支付失败的订单不能再次取消。
- 扫码弹窗移除“稍后支付”，改为“取消订单”；点击后需要二次确认。
- 取消成功后关闭弹窗、清空当前订单和二维码状态，用户可重新选择套餐下单。
- 取消失败时保留弹窗和订单状态，显示错误，不误导用户认为订单已经关闭。
- 支付轮询遇到 `closed` 或 `payment_failed` 时关闭失效二维码并给出重新下单提示。

## 测试

- 前端空间切换测试覆盖导航权限刷新、状态写回和失败提示。
- 公共认证测试覆盖登录到注册/忘记密码、注册/手机验证返回登录时的 redirect 透传，以及恶意 redirect 回退。
- 后端订阅测试覆盖待支付订单取消成功和不可取消状态。
- 前端订阅测试覆盖二次确认、取消接口调用、成功清理扫码状态，以及关闭/失败订单停止展示二维码。

## 非目标

- 本轮不处理配房分享历史缓存键。
- 不增加待支付订单恢复入口。
- 不修改生成的 OpenAPI 客户端，新增取消请求放在手写服务层。
- 不调整支付渠道、价格计算、退款或开票逻辑。
