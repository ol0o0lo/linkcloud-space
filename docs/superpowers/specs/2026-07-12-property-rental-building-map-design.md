# 房源地图业务化设计

**日期：** 2026-07-12
**状态：** 设计已确认，待实施

## 背景

管理端此前已实现独立的高德地图页面和高德 JSAPI 加载适配，但页面使用模拟标点，且作为通用“地理”页面隐藏，尚未接入房源租赁业务。

本次将地图页面重新启用为“房源租赁”下的“房源地图”。地图以楼栋为聚合单位，支持搜索和筛选、查看楼栋房源汇总、浏览按房号排序的房源，并跳转至楼栋或房源详情。对于缺少坐标的历史楼栋，系统根据完整地址调用高德地理编码并保存可靠坐标。

## 目标

- 在“房源租赁”菜单下新增独立的“房源地图”页面。
- 地图以楼栋为标点单位，不再混用楼栋和单套房源标点。
- 支持按项目、楼栋名称、楼栋地址及房源状态搜索筛选。
- 在地图中查看楼栋基本信息和房源状态汇总。
- 点击楼栋后，在不离开地图的情况下查看按自然顺序排列的房源。
- 支持进入楼栋详情、房源详情，以及带楼栋筛选的现有房源列表。
- 自动补全缺少坐标且地址可靠的楼栋，并明确呈现无法定位的楼栋。
- 沿用当前组织隔离、权限、API 和前端组件模式。

## 非目标

- 不在地图上为每套房源创建独立标点。
- 不引入手绘区域、路线规划、热力图等高级 GIS 能力。
- 不重构现有房源、项目楼栋或高德地图基础设施中与本功能无关的代码。
- 不为地址不完整或地理编码结果不可靠的楼栋写入猜测坐标。

## 方案选择

### 采用方案：楼栋聚合地图 + 右侧详情抽屉 + 独立楼栋详情路由

地图标点代表楼栋。点击标点后打开右侧抽屉，展示楼栋概况、房源状态汇总和房源列表；用户可以继续查看其他楼栋而不离开地图。需要完整业务信息时，再进入楼栋详情页或房源详情页。

该方案兼顾地图连续浏览效率与详情信息承载能力，并可以复用现有房源列表的 `building_id` URL 筛选行为。

### 未采用方案

1. **标点直接跳转详情页：** 实现较简单，但频繁离开地图，返回时需要恢复视口和筛选，连续查看效率较低。
2. **地图与完整楼栋列表固定分栏：** 适合高频调度场景，但页面信息密度和小屏适配成本较高，仍需额外详情承载方式。

## 信息架构与路由

- 在 `/property-rental` 路由分组中新增 `/property-rental/map`。
- 菜单名称为“房源地图”，放在“房源”之后、“项目楼栋”之前。
- 原 `/geo/map` 通用入口不再作为业务菜单展示；新页面复用其高德地图加载能力，并迁移或替换其模拟标点逻辑。
- 新增楼栋详情路由 `/property-rental/buildings/:id`，默认从地图抽屉和项目楼栋页面进入。
- 房源详情继续使用 `/property-rental/houses/:id`。
- “查看楼栋全部房源”跳转 `/property-rental/houses?building_id=<id>`。

## 页面布局与交互

### 地图主体

- 地图占据页面主要可视区域。
- 默认根据当前组织下已有坐标的楼栋自动适配视野；无数据时使用合理的默认城市级视图。
- 地图移动或缩放结束后，使用当前可视范围重新查询楼栋，避免一次加载全部数据。
- 楼栋密集区域启用点聚合；放大后拆分为具体楼栋标点。
- 标点显示楼栋名称与房源总数。零房源楼栋仍可显示，但使用弱化样式。
- 已停用楼栋默认隐藏，可通过筛选显式查看。

### 搜索筛选面板

左上方提供可收起的筛选面板：

- 关键词匹配项目名称、楼栋名称和楼栋地址。
- 项目筛选。
- 房源状态筛选，例如空置、已租和其他现有状态。
- 是否包含停用楼栋。
- 搜索结果以楼栋为单位显示；点击结果后地图定位并选中楼栋。
- 显示当前结果数量和待定位楼栋数量。

### 楼栋详情抽屉

点击楼栋标点或搜索结果后打开右侧抽屉，地图保持当前中心点和缩放级别。抽屉包含：

- 项目、楼栋名称、地址、楼层、电梯、建成年份和启用状态。
- 房源总数、空置数、已租数、停用数和可发布数等业务汇总。
- 房源列表，展示房号、状态、面积、租金和发布状态。
- 房源点击后进入现有房源详情页。
- “查看楼栋全部房源”进入带 `building_id` 筛选的房源列表。
- “查看楼栋详情”进入楼栋详情页。

### 楼栋详情页

- 展示楼栋完整基本信息和所属项目信息。
- 展示与地图抽屉一致的房源状态汇总。
- 展示按自然顺序排列的楼栋房源列表。
- 房源列表支持进入房源详情，并提供返回房源地图的入口。

### 地图选点组件

新增可复用的 `LocationPicker` 悬浮弹窗，用于新建/编辑楼栋和处理地图中的待定位楼栋。它是表单编辑过程的一部分，不会在用户确认前写入楼栋。

- 弹窗打开后，先请求浏览器地理定位权限，以当前位置作为地图默认中心和初始搜索范围。
- 若浏览器定位被拒绝、不可用或超时，按顺序回退到楼栋已有坐标、楼栋完整地址的搜索结果、项目坐标和默认城市视图。
- 顶部搜索框支持按地址、POI、项目或楼栋关键词检索；选择候选项后地图移动到候选点。
- 用户可拖动地图，使地图中心固定的选点标记落在目标位置；也可直接点击地图更新选点。
- 弹窗实时展示待确认的标准地址、POI 名称、行政区划和经纬度。点击“确定”后将该最小定位信息返回楼栋表单；点击“取消”不改变表单。
- 楼栋表单最终提交时，才保存地址、经纬度和定位元数据。对已有楼栋，从“待定位”或“重新定位”入口打开组件并确认后，才调用楼栋更新接口。
- 浏览器定位只用于首次居中和辅助搜索；不会自动覆盖已有楼栋坐标，也不会将用户当前位置持久化为楼栋位置。

### 状态保留

地图关键词、筛选条件、中心点、缩放级别和已选楼栋统一写入 URL 查询参数。进入楼栋/房源详情时，将当前地图 URL 编码为 `return_to`；返回地图时使用该 URL 恢复全部状态。组件内部瞬时加载状态不写入 URL。

## 后端接口设计

### 楼栋地图聚合接口

新增面向地图场景的读取接口：

```text
GET /api/house/building-map/
```

查询参数：

- `keyword`：项目名称、楼栋名称或地址关键词。
- `estate_id`：项目 ID。
- `house_status`：房源状态。
- `include_inactive`：是否包含停用楼栋。
- `west`、`south`、`east`、`north`：当前地图可视范围。

响应使用地图所需的最小数据：

- 楼栋 ID、项目摘要、楼栋名称、地址、经纬度和启用状态。
- 房源总数及各业务状态数量。
- 定位状态。

地图范围查询必须设置服务端结果上限。前端使用地图移动结束后的防抖请求，避免拖动期间产生高频调用。

### 楼栋地图详情接口

点击楼栋后按需获取详情：

```text
GET /api/house/building-map/{building_id}/
```

返回楼栋完整摘要、房源状态汇总和房源列表。首屏地图接口不携带所有房源详情，避免组织数据量增加后响应过大。

### 自然排序

楼栋内房源按以下规则稳定排序：

1. 有楼层时先按楼层数值升序。
2. 同楼层或楼层为空时，对房号做大小写不敏感的自然排序，使 `2` 排在 `10` 前、`A2` 排在 `A10` 前。
3. 排序键相同时按房源 ID 升序，保证结果稳定。

排序逻辑收敛为可单独测试的服务函数，地图详情和楼栋详情共同复用。

## 坐标补全设计

### 地址来源

地理编码地址按项目和楼栋字段拼接：

```text
项目省 + 项目市 + 项目区县 + 项目地址 + 楼栋地址或楼栋名称
```

拼接时去除空值和明显重复片段。楼栋自身有完整地址时优先使用；独栋未绑定项目时使用楼栋地址。

### 定位流程

1. 楼栋已有合法经纬度时直接使用。
2. 楼栋缺少坐标但地址足够完整时，由后端调用高德地理编码 API。
3. 仅当响应唯一且可信时保存 `lat`、`lng`。
4. 地址为空、结果为空或结果模糊时不保存坐标，记录为待定位或定位失败。
5. 保存楼栋时优先尝试定位；地图接口可触发受控的兜底补全，但不能在单次读取请求中同步阻塞大量外部调用。
6. 兜底补全应通过后台任务或限量异步调度执行，并设置幂等、超时、失败退避和调用频率保护。
7. 具备楼栋管理权限的用户可以对单个或待定位楼栋触发重新定位。

为使失败状态、退避和地址变更可追踪，在 `Building` 增加以下定位元数据：

- `geocode_status`：`pending`、`success`、`failed`，已有合法坐标的数据迁移为 `success`。
- `geocode_address`：最后一次请求使用的规范化完整地址。
- `geocode_error`：最近一次失败的简短错误分类，不保存外部响应或密钥。
- `geocode_attempted_at`：最近一次尝试时间，用于退避和重复调度保护。

当楼栋地址、名称或所属项目地址字段发生变化时，将楼栋定位状态重置为 `pending`，但不立即清空原坐标；后台定位成功后原子替换坐标。定位失败时保留旧坐标并把标点标记为“地址已变更，待重新定位”，避免暂时从地图消失。

地理编码使用服务端 Web 服务 Key；现有高德 JSAPI Key 和安全密钥仍只负责浏览器地图渲染。密钥均从环境配置读取，不写入代码或响应日志。

## 数据边界与权限

- 所有地图与详情接口沿用当前 `require_org_selected` 组织上下文，只返回当前组织数据。
- 地图读取沿用现有房源模块的登录和组织选择要求。
- 坐标回写只由服务端任务执行；手动重新定位端点沿用楼栋更新端点的认证与组织校验。
- 访问无权限楼栋、跨组织楼栋或不存在的楼栋时使用项目统一错误响应。
- 汇总查询不得绕过现有房源有效性和组织过滤规则。

## 前端组件边界

- `PropertyRentalMapPage`：管理 URL 状态、查询参数、地图视口和选中楼栋。
- `BuildingMapCanvas`：管理高德地图实例、点聚合、标点和视口事件。
- `BuildingMapFilters`：管理关键词和业务筛选。
- `BuildingMapDrawer`：展示按需加载的楼栋汇总与房源列表。
- `BuildingMapMarker` 或标点渲染工具：统一楼栋标点视觉与零房源弱化状态。
- `LocationPicker`：封装浏览器定位、地址搜索、地图拖动/点击选点与确认回传；不直接提交楼栋表单。
- 现有 `useAmap`：继续负责高德 JSAPI 配置和加载；按需要补充点聚合插件，不重复实现 SDK loader。
- 手写 API 适配优先放在 `src/services/manual`；生成 OpenAPI 文件只通过项目命令重新生成。

组件之间通过明确的数据类型和回调通信。地图实例细节限制在地图画布组件内，筛选面板和抽屉不直接操作高德对象。

## 加载与异常状态

- 高德配置缺失或 SDK 加载失败：显示明确错误、原因和重试操作。
- 地图聚合接口失败：保留基础地图，显示可重试提示。
- 楼栋详情失败：抽屉显示局部错误，不销毁地图和当前筛选。
- 空数据：显示当前范围无匹配楼栋，并提供清空筛选操作。
- 待定位：不使用默认坐标或伪造标点；筛选面板显示待定位数量。
- 地理编码超时或限流：记录可重试状态，不阻塞地图数据返回。
- 外部定位结果模糊：不自动写入，等待补充地址或人工确认。

## 验收标准

- 用户可从“房源租赁 → 房源地图”进入页面。
- 地图按当前组织展示具有可靠坐标的楼栋，并显示房源总数。
- 用户可按楼栋维度搜索和筛选，并从搜索结果定位地图标点。
- 点击楼栋后可查看汇总信息和按自然顺序排列的房源。
- 用户可进入楼栋详情、房源详情和该楼栋的房源列表。
- 返回地图后原有筛选和视口得到恢复。
