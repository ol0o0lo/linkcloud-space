# 小区与楼栋经营详情页设计

## 目标

为租赁管理端补齐小区和楼栋的正式详情页，让运营人员能从小区/楼栋管理列表持续下钻：小区 → 楼栋 → 房源。首版聚焦当前库存状态，不引入租金均价、趋势、看房或到期分析。

## 路由与导航

- 新增小区详情路由：`/property-rental/estates/:id`。
- `/property-rental/buildings/:id` 作为统一的正式楼栋详情页，替代其仅面向地图的现状；地图入口继续传递 `return_to`，保证可返回房源地图。
- 小区管理列表的名称链接到小区详情；楼栋列表的名称链接到楼栋详情。
- 小区详情中的楼栋行进入楼栋详情；楼栋详情中的房源行进入现有房源详情。
- 楼栋详情中的所属小区可返回小区详情；普通来源的返回目标为上级详情或列表，地图来源优先回地图。

## 页面结构

### 小区详情

1. 面包屑和小区标题区：名称、地址、物业类型、启停状态，以及“编辑”“新建楼栋”操作。
2. 经营概览：楼栋数、房源总数、空置、已租、装修中、封存、已发布；以数字卡片和状态分布呈现。
3. 楼栋分页列表：楼栋名、楼层、房源总数、各状态数量。行可点击下钻。
4. 无楼栋时提示“暂无楼栋，可新建”，并提供新建操作。

### 楼栋详情

1. 面包屑和楼栋标题区：所属小区、地址、楼层、电梯、定位和启停状态，以及“编辑”“登记房源”操作。
2. 经营概览：房源总数、空置、已租、装修中、封存、已发布。
3. 房源分页列表：复用现有房源列表的关键字段与状态筛选，点击房号进入房源详情。
4. 无房源时提示“暂无房源，可登记”，并提供登记操作。

## 数据与接口

- 详情汇总由后端查询提供；前端不通过拉取全量楼栋/房源自行汇总。
- 小区详情查询返回小区资料和聚合后的经营指标；楼栋列表保持独立分页查询，并为每个楼栋返回当前库存状态计数。
- 楼栋详情查询返回楼栋资料和聚合后的经营指标；房源列表继续使用现有 `building_id`、`page`、`page_size` 和状态筛选。
- 所有关联列表遵循 `{ items, total, page, page_size }` 分页约定，避免详情页随数据增长加载过多记录。
- 所有对象查询均按当前组织限定；跨组织或不存在的 ID 返回 404。

## 交互与状态

- 新建或编辑楼栋、房源后，回到当前详情页并刷新概览与关联列表。
- 首屏和列表分别显示加载态；请求失败显示可重试的统一异常状态。
- 保留地图详情入口的 `return_to` 语义，避免地图使用流程回归。

## 验收范围

- 小区 / 楼栋概览统计正确，且随数据变化刷新。
- 关联楼栋 / 房源列表可分页；楼栋详情的房源列表可按状态筛选。
- 小区、楼栋、房源三级跳转和返回符合来源上下文。
- 空列表、无效 ID、加载失败和跨组织访问均有正确表现。
- 地图进入楼栋详情后仍可返回地图。
