# 房源资产工作区完整闭环设计

## 背景

房源列表已经采用“左侧资产导航＋右侧对象工作区”的方案：选择小区后可在房源、楼栋、项目资料之间切换，选择楼栋后可在房源和楼栋资料之间切换。目前左侧仍保留“管理结构”入口，部分新增、编辑、删除和治理操作仍依赖“管理项目与楼栋”Drawer，形成两套管理方式。

本次改造将移除房源列表中的“管理结构”功能，让房源列表自身成为项目、楼栋和房源日常管理的唯一闭环入口。

## 目标

- 删除房源列表中的“管理结构”按钮和“管理项目与楼栋”Drawer。
- 删除项目资料和楼栋资料中的“完整管理”按钮。
- 原管理结构中的业务能力全部由资产导航和右侧对象工作区承接。
- 新建、编辑、删除、楼栋归属调整、图片、标签、地图位置和待完善治理均不离开房源列表。
- 保存、删除后自动刷新资产导航和房源列表，并进入可继续工作的稳定状态。
- 保留原有项目、楼栋独立详情页及其路由，不在本次改造中删除。

## 非目标

- 不重构项目、楼栋或房源的后端 API。
- 不删除 `/rental/properties/estates`、项目详情页或楼栋详情页。
- 不新增批量删除、批量迁移或新的资产层级。
- 不改变房源表格字段、筛选规则和业务状态定义。

## 信息架构

### 左侧资产导航

左侧继续承担资产定位和入口功能：

- 搜索项目或楼栋。
- 选择全部房源、项目或楼栋。
- 新建项目。
- 在指定项目下新建楼栋。
- 新建独立楼栋。
- 进入项目或楼栋编辑状态。
- 使用“待完善”筛选查看缺少项目地址、缺少楼栋地址、缺少楼栋位置或没有楼栋的项目。

移除左侧底部“管理结构”按钮。地图查看和房态同步入口保持不变。

### 右侧对象工作区

未选择项目或楼栋时继续显示全部房源列表。选择资产后显示对象工作区：

- 项目：`房源`、`楼栋`、`项目资料`。
- 楼栋：`房源`、`楼栋资料`。
- 创建项目或楼栋时：显示与对象资料同一视觉体系的创建表单，不打开管理 Drawer。

资料 Tab 同时承担查看、编辑和危险操作，不再提供“完整管理”跳转。

## 功能迁移

| 原管理结构能力 | 新承载位置 |
| --- | --- |
| 搜索项目、楼栋 | 左侧资产导航搜索 |
| 项目列表和楼栋列表定位 | 左侧分组树及搜索结果 |
| 缺项目地址 | 左侧“待完善”筛选 |
| 缺楼栋地址 | 左侧“待完善”筛选 |
| 缺楼栋位置 | 左侧“待完善”筛选 |
| 无楼栋项目 | 左侧“待完善”筛选 |
| 新建项目 | 左侧“新建项目”，右侧创建表单 |
| 新建项目楼栋 | 项目节点“＋”或项目“楼栋”Tab，右侧创建表单 |
| 新建独立楼栋 | 独立楼栋分组“新建”，右侧创建表单 |
| 编辑项目 | 项目资料 Tab |
| 编辑楼栋 | 楼栋资料 Tab |
| 修改楼栋所属项目 | 楼栋资料编辑表单 |
| 项目地图位置 | 项目资料编辑表单 |
| 楼栋地图位置 | 楼栋资料编辑表单 |
| 楼栋图片和标签 | 楼栋资料编辑表单 |
| 删除项目 | 项目资料危险操作区及影响确认弹窗 |
| 删除楼栋 | 楼栋资料危险操作区及影响确认弹窗 |
| 查看项目关联楼栋 | 项目“楼栋”Tab |
| 在楼栋下登记房源 | 楼栋“房源”Tab |

原管理结构的 ProTable 密度、列设置和分页属于旧管理界面的展示能力，不作为独立业务能力迁移；全局资产定位由左侧导航、搜索和待完善筛选完成。

## 表单设计

### 项目资料

查看态展示：

- 项目名称、展示名称、物业类型。
- 省份、城市、区域、详细地址。
- 地图位置。
- 楼栋数和房源数。

编辑态提供相同字段及地图位置选择器。名称、省份、城市和区域沿用现有校验；详细地址允许后续补齐。

### 楼栋资料

查看态展示：

- 楼栋名称、所属项目。
- 地上楼层、地下楼层、建成年份、电梯。
- 详细地址和地图位置。
- 图片和标签。
- 房源数及房态摘要。

编辑态使用上述字段的并集。所属项目允许调整为空，表示独立楼栋。创建项目楼栋时默认所属项目为当前项目；创建独立楼栋时默认无所属项目。新建楼栋未手动设置位置且所属项目已有位置时，继续沿用现有位置继承规则。

## 创建、编辑与退出

- 左侧新建或编辑操作在右侧打开表单，并通过 URL 保存当前动作及目标对象。
- 创建或编辑期间锁定左侧资产切换和其他 Tab。
- 表单有未保存修改时，刷新或关闭页面触发浏览器离开提醒。
- 取消创建后返回触发入口前的资产范围；取消编辑后返回当前对象资料查看态。
- 项目创建成功后刷新导航、选中新项目并打开项目资料。
- 楼栋创建成功后刷新导航、展开所属项目或独立楼栋分组、选中新楼栋并打开楼栋资料。
- 编辑成功后保持当前对象和资料 Tab，并刷新房源表格中相关展示字段。

## 删除闭环

- 删除入口放在资料 Tab 底部的危险操作区，避免与高频编辑按钮并列。
- 删除项目前复用现有关联楼栋影响检查和二次确认。
- 删除楼栋前复用现有关联房源影响检查和二次确认。
- 删除失败时保留当前对象和错误信息，不清空用户上下文。
- 删除成功后刷新项目、楼栋和房源查询，清除已删除对象的 URL 参数并回到全部房源。

## 待完善治理

左侧资产导航增加“待完善”筛选入口，包含：

- 项目地址待补充。
- 楼栋地址待补充。
- 楼栋位置待补充。
- 项目尚无楼栋。

选择筛选后，左侧仅展示匹配对象，并保留对应的补充操作文案。点击对象后直接进入资料编辑或楼栋创建流程，从发现问题到修复问题均在当前页面完成。清除筛选后恢复正常资产树。

## URL 与浏览器历史

继续保留 `estate_id`、`building_id` 和 `asset_tab`。新增统一的工作区动作参数，用于表达创建或编辑项目、创建或编辑楼栋及待完善筛选，替代仅服务于旧 Drawer 的状态。

要求：

- 刷新页面可恢复所选对象、Tab、治理筛选和创建/编辑上下文。
- 浏览器前进、后退可恢复稳定状态。
- 房源列表的 `keyword`、`status`、`page` 等参数不与资产治理状态互相覆盖。
- 保存、取消和删除后清理已经失效的动作参数。

## 组件边界

- `PropertyAssetNavigator`：资产搜索、树形定位、待完善筛选和创建/编辑入口。
- `PropertyAssetWorkspace`：对象标题、Tab、资料查看/编辑、创建状态和删除入口。
- 项目表单与楼栋表单：从原项目楼栋管理页面提取为可复用组件，集中维护字段、校验、位置继承、图片和标签逻辑。
- 删除影响确认：继续复用 `ResourceDeleteModal`，不复制删除规则。
- 房源列表页面：只负责 URL 状态编排、查询刷新和资产范围联动，不继续持有管理 Drawer。

原项目楼栋页面可继续复用提取后的表单组件，避免独立详情和房源列表形成两套字段规则。

## 状态与异常处理

- 加载：资料、楼栋列表和影响统计使用现有 Skeleton 或加载状态。
- 空状态：项目无楼栋时在楼栋 Tab 提供主操作“新建楼栋”；筛选无结果时提供清除筛选。
- 错误：资料、列表和提交失败均在当前工作区反馈，并提供重试。
- 无权限：沿用 API 权限结果；无操作权限时隐藏或禁用创建、编辑和删除入口，查看能力不受影响。
- 窄屏：工具栏允许换行，表单降为单列，房源和楼栋表格保持横向滚动。

## 测试与验收

最小自动化覆盖：

- 房源列表中不再出现“管理结构”“完整管理”及管理 Drawer。
- 新建项目、新建项目楼栋和新建独立楼栋均在右侧工作区打开。
- 项目、楼栋完整字段可编辑并调用正确 API。
- 楼栋归属调整、位置继承、图片和标签值正确提交。
- 项目和楼栋删除显示影响确认，成功后回到全部房源。
- 待完善筛选可定位对象并进入修复流程。
- 编辑状态锁定导航和 Tab，取消后恢复。
- URL 刷新及前进后退恢复对象、Tab 和动作状态。

视觉验收覆盖项目、楼栋、创建、编辑、待完善筛选和删除确认状态，并检查浏览器控制台无新增 warning 或 error。

## 完成标准

- 用户无需打开“管理项目与楼栋”Drawer 即可完成原有管理业务。
- 房源列表中不存在失效或重复的“管理结构”入口。
- 所有创建、编辑、删除和治理流程均能在房源列表内开始、完成并回到稳定上下文。
- 原项目和楼栋独立页面保持可用。
