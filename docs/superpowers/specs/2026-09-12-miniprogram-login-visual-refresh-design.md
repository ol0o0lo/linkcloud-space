# 小程序登录页视觉焕新设计

**日期：** 2026-09-12  
**状态：** 已确认，待实施

## 目标

美化 `frontend_miniprogram/src/pages/auth/login.vue`，在不改变现有认证接口、登录结果处理和跳转逻辑的前提下，建立更有辨识度的“云端坐标”登录体验。

核心文案为：

> 你的城市坐标，正在点亮

## 范围

- 微信小程序端以微信一键登录为唯一主操作。
- 辅助登录方式只展示“验证码登录”和“密码登录”。
- 验证码登录继续使用手机号和短信验证码。
- 密码登录使用手机号和密码。
- 保留现有加载、错误提示、登录后待办恢复和跳转逻辑。
- 不修改后端、认证接口、生成的 API 客户端、多语言文件和依赖文件。
- 不新增图片素材，主视觉由页面结构和 CSS 完成。

## 视觉方向

页面采用“轻盈云境”风格，并以坐标轨道形成品牌记忆点：

- 背景使用浅蓝到白色的纵向渐变。
- 首屏中央由两层细线圆轨道、坐标核心和少量静态光点组成主视觉。
- 主标题置于主视觉下方，使用两行排版：“你的城市坐标 / 正在点亮”。
- 辅助文案为“登录后继续收藏、预约与看房进度”。
- 底部操作区使用高透明白色卡片、较大圆角和轻阴影，形成悬浮感。
- 微信按钮使用绿色渐变，验证码和密码登录使用蓝色文字入口。
- 动效仅包含按钮按压反馈和底部卡片内容的轻量切换；轨道与光点保持静态，避免低端设备性能压力。

## 页面状态

### 默认首屏

- 顶部显示“链云空间”品牌文字。
- 中部显示坐标轨道主视觉、主标题和辅助文案。
- 底部显示微信一键登录主按钮。
- 主按钮下方并列显示“验证码登录”和“密码登录”两个文字入口。
- 底部保留简短账号服务说明。

### 验证码登录状态

- 点击“验证码登录”后，底部白色卡片在当前页面原位切换为验证码表单，不显示遮罩或弹层。
- 顶部坐标主视觉保留，并通过紧凑布局为表单留出空间。
- 初始展示区号和手机号输入框，以及“获取验证码”按钮。
- 验证码发送成功后，在同一卡片中显示验证码输入框和重新发送入口，主按钮文案切换为“登录”。
- 卡片底部可切换到密码登录或返回微信登录。

### 密码登录状态

- 点击“密码登录”后，底部白色卡片在当前页面原位切换为密码表单。
- 展示手机号和密码输入框，保留密码显隐能力。
- 主按钮文案为“登录”。
- 卡片底部可切换到验证码登录或返回微信登录。

## 组件与状态设计

- 继续复用 `wd-button` 和 `wd-input`。
- 不使用 `wd-popup`、原生弹层、遮罩或页面级 Portal。
- 页面使用一个本地登录模式状态，取值为微信登录、验证码登录或密码登录。
- 底部操作卡片根据登录模式原位渲染对应内容，切换时不清空用户已输入内容。
- 现有 `phoneCountryCode`、`phoneNationalNumber`、`phoneCode`、`password`、`codeSent`、`loading` 和 `sendingCode` 状态继续复用。
- 微信登录、发送验证码、提交验证码和密码登录的业务函数不改变职责。

## 交互与错误处理

- 所有提交继续使用现有 loading 状态防止重复操作。
- 输入缺失、验证码发送失败和登录失败继续通过 `uni.showToast` 提示。
- 登录方式切换不触发接口请求，也不清空已有输入值。
- 点击“返回微信登录”后，底部卡片恢复微信主按钮和两个辅助入口。
- 登录成功后的 pending action、手机号验证引导和目标路由保持不变。

## 平台适配

- 微信小程序使用微信主登录首屏。
- H5 不显示微信小程序登录按钮，继续以验证码和密码登录为主要入口，同时复用新的背景、主视觉和表单样式。
- 页面内容考虑顶部安全区和底部安全区，避免与微信胶囊、全面屏指示区域冲突。
- 不使用依赖 `backdrop-filter` 才能成立的效果；透明卡片需要在不支持模糊时仍保持可读。

## 验收标准

- 微信小程序首屏只存在一个高强调主按钮：微信一键登录。
- “验证码登录”和“密码登录”入口清晰可见且能够在当前页面原位展示对应表单。
- 页面不存在登录 Popup、遮罩或弹层式交互。
- 原有微信、手机验证码和手机号密码流程仍可正常完成。
- 登录成功后的待办恢复和跳转行为无变化。
- 页面在微信小程序和 H5 均无横向溢出，键盘弹起后输入与提交操作仍可到达。
- 页面主视觉使用纯 CSS，不新增远程图片或静态图片依赖。
- 前端类型检查和相关现有测试通过。
