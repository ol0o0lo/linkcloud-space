# 成交签约工作台视觉与交互重构设计

日期：2026-08-30
状态：待实施

本文定义管理端“成交签约”抽屉的第二轮视觉与交互重构。它以现有成交签约能力和 `2026-08-29-house-list-deal-signing-design.md` 为业务基线，只优化信息结构、组件边界、操作效率和界面质感，不改变后台接口、租客关联规则、租约生效语义或房态联动逻辑。

## 1. 背景与目标

当前抽屉已经能在房源列表原地完成成交签约，但表单区域仍偏平、信息层级不够细致，收益归属等低频编辑内容占用首屏空间。用户需要一个更像专业业务工作台的录入界面：高频信息一眼可读，核心字段连续填写，业务结果明确但不制造阻断感，同时通过克制的装饰提升完成度。

本轮目标：

1. 保留响应式宽抽屉和单次提交路径，不跳转页面，不叠加第二层弹窗。
2. 建立明确的房源上下文、步骤顺序和左右栏任务分工。
3. 缩短首屏表单高度，默认突出租客、租期、金额等高频字段。
4. 让收益归属、成交带看、合同与备注按使用频率渐进展开。
5. 使用主题 token、轻渐变、几何光晕、细边框和克制动效提升精细度。
6. 完整保留加载、失败、无权限、提交中、未保存离开和窄屏状态。

## 2. 非目标

- 不改变成交签约专用后台接口及请求字段。
- 不改变“提交成功后创建生效租约并将房态更新为已出租”的事务语义。
- 不让普通租约创建、编辑或状态变化自动修改房态。
- 不改变租客身份规则：仅姓名和手机号同时一致时自动关联已有租客。
- 不改变收益申请的审核流程，不把“已提交”表达为“收益已生效”。
- 不新增自动保存、草稿、二次确认、强警告、营销插画或持续动画。
- 不借本次重构改造全局设计系统、生成接口代码或其他租赁页面。

## 3. 设计原则

### 3.1 高频录入优先

用户从房源列表进入后，应沿着“核对房源 → 填租客 → 填租期金额 → 核对收益归属 → 提交”的顺序完成操作。可选信息不占据主路径，系统影响在顶部和底部各说明一次即可。

### 3.2 精致但克制

视觉方向为“专业精致工作台”，不是营销落地页。装饰仅用于建立层级：柔和蓝绿渐变、低透明几何光晕、小型图标底座、细分隔线和轻阴影。所有状态继续使用项目语义 token、`AppIcon` 和 `AppStatusTag`，不新建局部品牌色或状态体系。

### 3.3 渐进披露

默认展示完成签约所需的信息。成交带看作为轻量关联入口；收益归属先显示摘要，只有具备调整权限且主动点击“调整”时才展开详细字段；合同与备注维持底部折叠。

### 3.4 不打断正常操作

租约生效和房态变化通过结果胶囊、底部说明和主按钮文案表达，不增加阻断式确认。租客精确匹配只显示低干扰辅助文字。提交失败保留表单数据，并将可操作的错误放在相关区域。

## 4. 容器与响应式布局

继续使用共享超大抽屉宽度 `drawerWidthXl`，保证至少 12px 视口边距。抽屉标题保持简洁，不在标题栏重复房源摘要；主体由房源主视觉、双栏工作区、底部选填区和固定操作栏组成。

### 4.1 桌面端

- 顶部主视觉横跨抽屉内容区。
- 主工作区使用双栏，左栏约 47%，右栏约 53%。
- 左栏依次放置租客资料和收益归属。
- 右栏依次放置租期金额和合同备注折叠入口。
- 两栏卡片顶部对齐，内部字段保持 Ant Design `middle` 尺寸。
- 固定操作栏左侧说明提交结果，右侧为“取消”和“确认成交并生效”。

### 4.2 中等宽度和平板

- 主工作区转为单列，顺序固定为租客资料、租期金额、收益归属、合同备注。
- 房源主视觉内部可从左右结构转为上下结构，结果胶囊保持完整可读。
- 不缩小表单控件，不隐藏必填字段，不让固定操作栏遮挡表单末尾。

### 4.3 窄屏兜底

- 内容区使用 16px 或项目已有窄屏间距。
- 日期、金额和租客字段全部单列。
- 底部说明与按钮纵向排列，按钮可占满可用宽度。
- 文本缩放或键盘弹出后仍能看到当前字段和主要提交动作。

## 5. 信息架构与视觉结构

### 5.1 房源主视觉 `DealSigningHero`

主视觉负责让用户确认“正在为哪套房源签约”以及“提交会产生什么结果”。

左侧内容：

- 小型房源图标底座，使用 `AppIcon name="house"`。
- 辅助标题“本次成交房源”。
- 房源名称、楼栋房号或现有 `houseLabel()` 结果。
- 户型、挂牌月租和当前房态；户型必须复用共享格式化逻辑，遵守“单间”展示规则。

右侧内容：

- 标题“提交后立即完成”。
- 三个紧凑结果胶囊：租约生效、房态已出租、收益待审核。
- 一行次要说明：结果由成交签约接口一次完成，不需要额外确认。

视觉规范：

- 背景使用主题 token 派生的浅蓝到浅绿色柔和渐变。
- 允许 1–2 个 `aria-hidden` 的低透明圆形或环形光晕，不使用图片素材。
- 房源信息和结果区域之间使用细分隔线；中等宽度改为顶部边线。
- 卡片边框、圆角和阴影全部来自 token，不写死十六进制颜色。

### 5.2 工作区章节 `DealSigningSection`

四个业务区域使用统一章节壳层，避免每块各自实现标题和间距。章节头包含：

- 28px 左右的小型图标底座。
- 标题和一行简短说明。
- 右上角步骤编号 `01 / 02 / 03`；合同备注是选填区，不编号。

章节卡片只使用一层边框和极轻阴影，不在字段内部继续嵌套普通 Card。标题、说明、步骤号和字段之间形成稳定间距，保证快速扫读。

### 5.3 租客资料 `DealSigningTenantFields`

- 步骤编号为 `01`。
- 顶部先显示轻量“成交带看（可选）”关联行，点击后原地展开选择器；已有来源记录时显示摘要和清除动作。
- 租客模式继续使用“手动填写 / 选择已有租客”分段控件。
- 手动填写时，姓名和手机号在桌面端同排，窄屏单列。
- 姓名和手机号都输入完整后执行低频防抖查询；仅当二者同时精确一致时，手机号字段下方显示“将关联已有租客：姓名”。
- 未匹配时不显示“将创建新租客”大提示，不要求额外确认。
- 选择已有租客时保留按姓名或手机号搜索、分页加载、失败重试和禁用联系人校验。
- 切换模式继续清除另一模式不会提交的值，禁止同时提交 `tenant_id` 与 `tenant_identity`。

### 5.4 租期与金额 `DealSigningLeaseFields`

- 步骤编号为 `02`。
- 顶部保留“半年 / 1 年 / 2 年 / 自定义”快捷项。
- 起租日期、到期日期、月租、押金、付款日按业务关系分组；桌面端两列，窄屏单列。
- 月租默认带入房源报价，押金支持“无押金 / 押一月 / 自定义”。
- 自动带入或快捷项更新的字段允许出现一次 120–180ms 的浅蓝背景和边框过渡，帮助用户感知系统已更新数值。
- 高亮只在值发生自动变化时出现一次，不循环、不闪烁、不抢夺焦点，并遵守 `prefers-reduced-motion`。
- 表单仍提交明确日期和金额，不新增快捷项领域字段。

### 5.5 收益归属 `EarningAttributionFields`

- 步骤编号为 `03`。
- 默认展示紧凑摘要：受益人头像或图标、姓名、归属团队、规则说明和“调整”轻量动作。
- 无修改权限时不显示“调整”，使用锁定图标和简短说明表达默认归属。
- 有权限时点击“调整”在当前卡片内展开团队和受益人字段，不打开 Modal 或二级 Drawer。
- 多人归属、搜索、加载失败、重试和权限判断继续沿用现有能力。
- 展开后可用“收起”返回摘要；已选值必须保留。
- 文案始终说明“提交后待审核”或“按空间收益规则计算”，不能暗示收益已经结算。

### 5.6 合同与备注

- 位于右栏底部或单列流程末尾。
- 默认折叠，标题为“合同与内部备注”，辅助文案为“选填，可成交后补充”。
- 展开后复用 `MediaRefsUpload` 和现有备注字段。
- 折叠标题需要能提示内部是否已有内容，例如上传数量或“已填写备注”，避免用户收起后遗忘输入。
- 折叠区存在字段错误时自动展开，并将错误保持在对应字段附近。

## 6. 组件边界

### 6.1 `DealSigningWorkspaceDrawer`

负责：

- 抽屉开关、房源上下文加载、表单实例和未保存离开保护。
- 组合主视觉、章节组件、固定操作栏和全局提交错误。
- 调用现有成交签约接口，处理提交中、成功反馈和缓存刷新。
- 管理快捷租期、押金模式和来源带看的跨区状态。

不负责：

- 在主文件内重复实现每组字段的完整布局。
- 改变租客匹配、收益权限或后台事务规则。

### 6.2 `DealSigningHero`

纯展示组件，输入为房源、加载状态和枚举文案；输出只包含房源上下文和结果预告，不持有表单状态。

### 6.3 `DealSigningSection`

通用局部布局组件，输入标题、说明、图标、步骤号和内容。它只统一视觉结构，不包含领域判断，避免形成过度抽象的表单框架。

### 6.4 `DealSigningLeaseFields`

承载租期、日期、月租、押金和付款日控件。通过明确 props 接收表单实例、快捷模式和自动填充值；不发请求、不提交表单。

### 6.5 `DealSigningTenantFields`

继续承载租客双模式、已有租客查询和精确匹配反馈。成交带看的展开入口可以由抽屉组合在章节顶部，避免租客组件依赖带看领域。

### 6.6 `EarningAttributionFields`

增加紧凑摘要模式及原地展开能力，保留现有默认受益人、团队、成员查询、权限和错误处理。组件只输出 `team_id` 与 `beneficiary_user_ids`，不感知成交提交。

## 7. 数据流与后台契约

本轮不调整请求结构。抽屉继续将表单值转换为现有 `DealSigningCreateInput`，并调用成交签约专用接口。

```text
房源列表更多操作
  → 打开 DealSigningWorkspaceDrawer
  → 加载房源、租客选项、收益权限和可关联带看
  → 填写租客、租期金额、收益归属及可选合同备注
  → 提交现有 DealSigningCreateInput
  → 后台事务创建/关联租客、创建生效租约、更新房态、提交收益申请
  → 成功提示并刷新房源、租约和收益相关缓存
```

租客手动填写继续由后台作最终判断：规范化后的姓名与手机号都一致才关联已有联系人；同手机号不同姓名、同姓名不同手机号均不自动关联。前端查询只用于轻量预反馈，不参与最终一致性判断。

## 8. 状态、错误与权限

### 8.1 初始加载

- 房源详情加载时，主视觉使用匹配结构的 Skeleton；表单不展示错误默认值。
- 收益能力和受益人查询只锁定收益章节，不阻塞用户先填写租客和租期。
- 已有租客和带看记录加载失败只影响对应选择器，并提供局部重试。

### 8.2 无权限和不可成交

- 无成交签约权限时，入口按现有规则不可用；后台继续独立校验。
- 无收益申请权限时，收益章节显示明确但紧凑的错误说明，主按钮不可提交。
- 房源停用、已有生效租约、房东缺失或并发状态变化继续使用现有后台错误；抽屉顶部展示业务错误并保留输入。

### 8.3 提交状态

- 提交期间禁用重复提交、模式切换和可能丢失数据的关闭动作。
- 主按钮保留明确 loading 状态和原文案上下文。
- 字段错误靠近字段展示；无法归属到单字段的事务错误放在主视觉下方或工作区顶部。
- 提交失败不重置表单，不收起包含错误的章节。

### 8.4 成功状态

成功后使用轻量消息：

> 成交签约完成，租约已生效，房态已更新为已出租；收益等待审核。

随后关闭抽屉并刷新现有房源、租约、收益申请及入口依赖的统计缓存。成功反馈不增加独立结果页。

## 9. 动效与细节反馈

- 交互动效只使用背景、边框、阴影和透明度过渡，时长为 120–180ms。
- 自动带入高亮、收益区展开和轻量关联入口展开是唯一允许新增的局部动效。
- 不使用位移幅度明显的弹跳、持续呼吸、彩带、粒子或数字滚动。
- `prefers-reduced-motion: reduce` 下取消非必要过渡。
- hover 只用于可交互元素，静态卡片不制造可点击错觉。
- 固定操作栏可以使用轻微毛玻璃或半透明背景，但必须保证明暗主题下文字和边界清晰。

## 10. 无障碍与主题

- 保留 Drawer 默认焦点管理、键盘顺序和 Esc 行为；有未保存内容时继续执行现有离开确认。
- 仅图标动作必须提供 `aria-label` 和必要 Tooltip。
- 结果胶囊同时包含文字、图标和语义色，不只依赖颜色。
- 纯装饰光晕从辅助技术中隐藏，不参与点击和焦点。
- 分段控件、折叠区、展开/收起动作和搜索选择器均可用键盘操作。
- 新增颜色、背景、边框、阴影和文字全部使用 Ant Design token，并检查浅色与暗色主题。

## 11. 测试与视觉验收

### 11.1 前端行为测试

- 房源列表入口继续原地打开抽屉，不发生路由跳转。
- 主视觉展示正确房源、户型、月租、当前房态和三个提交结果。
- 租客双模式互斥，姓名和手机号同时一致时才显示关联提示。
- 成交带看默认紧凑，展开、选择、清除后提交值正确。
- 快捷租期、押金和月租默认值保持现有计算结果。
- 收益归属默认显示摘要，有权限时可原地展开并保留选择，无权限时不可调整。
- 合同备注默认折叠；已有内容或错误时能正确提示或展开。
- 提交请求体与重构前一致；提交中不重复请求，失败保留输入，成功刷新缓存。

### 11.2 静态检查

- 在 `frontend_admin/` 下先使用 Node 22。
- 运行 Biome/TypeScript 范围检查和成交签约相关 Vitest。
- 检查没有修改生成服务、多语言文件、`package.json` 或 `package-lock.json`。

### 11.3 浏览器视觉验收

至少检查桌面宽抽屉、中等宽度和平板/窄屏三种视口，并覆盖：

- 默认手动填写状态。
- 选择已有租客状态。
- 租客精确匹配提示。
- 收益摘要与展开状态。
- 合同备注展开及字段错误状态。
- 加载、局部失败、无权限、提交中和全局事务错误。
- 浅色与暗色主题。
- 键盘焦点、文本缩放和 `prefers-reduced-motion`。

临时截图必须写入项目内 `.codex/audits/deal-signing-workspace-redesign/`，不得写入项目根目录，也不纳入提交。

## 12. 验收标准

- 用户无需离开房源列表即可在一个抽屉内完成成交签约。
- 首屏能同时核对房源、提交结果、租客资料和主要租期金额字段。
- 默认界面比现状更精细，但没有大面积警告、营销装饰或多余确认。
- 收益归属、成交带看、合同备注按频率渐进展开，减少视觉负担。
- 桌面、平板和窄屏均能完成核心操作，不发生内容溢出或按钮遮挡。
- 租客关联、请求体、租约生效、房态更新和收益待审核语义与重构前完全一致。
- 加载、错误、无权限、提交中、成功和未保存离开状态均有明确反馈。
- 新增样式遵守项目 token、共享组件、状态语义、暗色主题和无障碍规则。
