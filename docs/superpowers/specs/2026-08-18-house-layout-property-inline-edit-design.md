# 房源详情户型与房源属性快捷编辑设计

## 背景

房源详情顶部当前将户型展示为“2房1厅1卫”，但点击户型编辑后只能修改房数和厅数。展示范围与编辑范围不一致，容易让用户误以为卫生间数量也能在这里修改。

详情页下方已有“房源属性”分组，厨房和阳台位于该分组但暂不支持快捷编辑，卫生间则没有独立展示。

## 目标

- 顶部“户型”只展示和编辑房数、厅数。
- 卫生间、厨房、阳台放在“房源属性”中独立展示。
- 卫生间、厨房、阳台均支持与其他详情字段一致的原位快捷编辑。
- 保持无确认按钮、失焦或 Enter 保存、编辑前后布局尽量稳定的交互原则。

## 非目标

- 不修改后端字段、接口或数据结构。
- 不调整房源列表、新增房源或其他页面的户型展示规则。
- 不重构详情页其他字段或完整“编辑资料”抽屉。
- 不改变“一房零厅显示为单间”的共享展示规则。

## 信息架构

### 顶部核心信息

“户型”仅承担主户型信息：

- 普通户型展示为 `2房1厅`。
- `bedrooms === 1` 且 `living_rooms === 0` 时继续展示为“单间”。
- 缺失字段沿用现有主户型格式化逻辑。
- 点击编辑图标后，仅出现“房”和“厅”两个整数输入框。

卫生间不再出现在顶部户型文案中，避免展示内容与编辑内容不一致。

### 房源属性

“房源属性”中的数量类字段按以下顺序排列：

1. 卫生间
2. 厨房
3. 阳台
4. 套内面积
5. 朝向
6. 装修
7. 扩展字段

数量展示格式为：

- 卫生间：`1卫`
- 厨房：`1厨`
- 阳台：`2阳台`
- 未填写：`-`

## 快捷编辑交互

卫生间、厨房和阳台分别使用独立的原位编辑字段：

- Hover 字段时显示铅笔图标。
- 只有点击铅笔图标才进入编辑。
- 编辑态在原值位置显示小尺寸数字输入框，不增加确认、取消或说明 UI。
- 数值必须是大于等于 0 的整数。
- 按 Enter、点击字段外部或切换到其他快捷编辑字段时保存。
- 值未变化时不发送请求。
- 每个字段独立提交，只发送当前字段，例如 `{ bathrooms: 2 }`。
- 保存失败时沿用现有快捷编辑错误处理，并恢复为可继续编辑的状态。

顶部户型编辑继续一次提交房、厅两个字段，例如 `{ bedrooms: 2, living_rooms: 1 }`。

## 组件与数据流

- 顶部户型展示改用共享主户型格式化逻辑，并指定“房”“厅”单位。
- 顶部户型编辑器继续复用现有 `InlineEditableField`，无需增加卫生间草稿字段。
- 在“房源属性”中为 `bathrooms`、`kitchens`、`balconies` 各增加一个 `InlineEditableField`。
- 三个字段复用现有整数校验、外部点击保存和 `saveInlinePatch` 请求流程。
- 厨房、阳台现有只读展示替换为对应的原位编辑字段；卫生间新增同类字段。

## 测试范围

- 顶部户型从“2房1厅1卫”变为“2房1厅”。
- 单间仍显示为“单间”。
- 顶部户型编辑仍只提交 `bedrooms` 和 `living_rooms`。
- 房源属性展示卫生间、厨房、阳台及正确的数量文案。
- 三个字段均只在点击各自编辑图标后进入编辑。
- 分别验证 Enter 或外部点击保存时只提交当前字段。
- 验证负数、小数等非法输入不会提交。
- 验证未修改时不会发送更新请求。

## 验收标准

- 用户在顶部看到什么，就只能在那里编辑什么：户型只包含房、厅。
- 卫生间、厨房、阳台均能在房源属性中快速找到并独立修改。
- 编辑态无多余按钮或说明，且不产生明显布局跳动。
- 修改不影响其他页面和现有后端接口。
