# 房源直接聊天与联系方式分享设计

日期：2026-10-25

状态：用户已确认并要求直接实现，已完成代码修改及本地相关测试、构建与 H5 演示账号验证。未操作 Git；未进行微信真机验证。

## 1. 用户流程

- 房源详情的联系入口改为“在线咨询”，登录后直接进入对应接待人的聊天，无需提供手机号或微信号。
- 进入聊天时展示房源上下文，不自动发送联系方式，也不自动发送首条文字消息。
- 聊天输入区上方提供“发送联系方式”快捷入口，仅在房源咨询的租客侧会话展示。
- 点击快捷入口打开底部面板；发送成功后关闭面板，在当前聊天中显示本次分享的文字消息。

## 2. 简洁分享面板

- 标题为“分享联系方式”，下方用一行显示“发给 接待人姓名 · 门店名”。
- 手机号、微信号合并成两行列表，每行包含字段名称、可编辑的值和本次发送勾选框。
- 两种联系方式可分别选择，也可同时选择；每次打开均不预选，编辑输入也不会自动勾选。
- 只展示一个主按钮，按选择显示“发送手机号”“发送微信号”或“发送联系方式”。没有选择、选中项为空或格式无效时不可发送。
- 保留关闭按钮及点击遮罩关闭，不叠加第二个确认弹窗。
- 提示语为“选中的信息会发到聊天中，对方可查看并保存”。不承诺仅单个经纪人可见，沿用现有业务权限。
- 不显示“下次自动填入”或“记住联系方式”开关，也不展示自动保存、已保存、下次无需重填等说明或成功提示；个人设置的读取和更新按约定执行。

## 3. 个人设置与发送分离

- 复用当前用户的 `UserSetting`，设置 key 沿用 `internal.house.contact.v1`，手机号和微信号使用同一份个人设置，不按房源或经纪人另存。
- 打开面板时读取已保存值；没有设置时显示空输入，不自动代入账号绑定手机号。
- 保持历史设置可读取；历史 `channels` 字段不作为本次分享授权，不据此预选或发送。
- 字段编辑完成、输入框失焦时，校验并保存修改；关闭面板时完成当前有效修改的保存。清空字段保存为空字符串。
- 自动保存只更新个人设置，不创建消息，不更新经纪人的咨询联系方式，不通知经纪人。
- 保存使用串行请求，避免同一面板中先前保存请求覆盖后续修改；切换账号后不继续提交旧账号草稿。
- 读取设置失败时明确提示重试，不能当作首次使用覆盖已有设置。校验或保存失败保留输入并提示，正常保存不打扰用户。
- 点击发送时使用本次勾选字段的最新值；先完成待保存的有效修改，保存失败则暂停本次发送，允许重试。

## 4. 后端与现有代码衔接

- 房源业务层提供不要求联系方式的会话创建或复用入口，继续依据公开房源、组织和有效接待人分配规则授权，沿用原有效咨询接待人。
- 进入聊天不从个人设置、账号手机号或既有客户档案自动复制手机号、微信号到本次咨询记录；历史业务数据保持原有权限和内容。
- 无可用接待人时返回清楚的不可用提示，不跳转空会话，不宣称已经开始聊天。
- 联系方式读取和更新复用现有个人设置 GET/PUT 接口；联系方式格式校验与现有发送校验保持一致。
- 分享必须绑定用户当前正在查看的房源咨询会话，后端核验当前用户参与资格、组织、咨询关联及可发送状态，不重新路由给其他接待人。
- 分享只将本次选中的联系方式写入当前聊天及关联咨询联系方式；不复制未选择项，不从账号或个人设置补齐未明确提交的字段。
- 沿用现有文字消息和 UUID 幂等机制；发送重试复用同一次发送标识，发送失败保留输入与选择，不重复生成消息。
- 改动集中在房源咨询业务适配、个人设置读写以及小程序/H5 会话页面，不新增消息卡片类型。

## 5. 验证范围

- 无联系方式也能从公开房源开始或继续对应接待人的聊天，进入时不会产生联系方式消息。
- 验证读取已有设置、首次为空、修改后重新打开仍读取新值、清空字段、读取失败和保存失败。
- 验证修改设置和关闭面板均不会发送消息，重新打开不会沿用上次发送勾选。
- 验证面板不展示自动保存相关开关、说明或成功提示，校验和网络错误仍能被用户感知。
- 验证分别发送手机号、微信号及两者，只发送本次勾选字段，消息与咨询归属当前会话。
- 验证重复点击、网络重试、切换账号、会话不可发送以及无接待人的边界。
