## 分工与约束

新版后端与整合由主任务负责；旧版导出、管理端、小程序端分别并行实现，文件范围互不重叠。后端测试放在 `tests/data_migration/`，不触碰现有业务数据。新旧模型 migration 由工具生成并检查；实际开发数据库迁移只在确认迁移内容后执行。

前端使用各自现有请求和组织作用域，新增手写适配器，不手改生成客户端，不新增依赖。截图放 `.codex/audits/uhome-team-migration/`。不把本地通过的检查描述为生产迁移或真实设备验收。

## 已实现入口及运行条件

- 新版管理端：`/dashboard/space/data-migration`；小程序/H5：空间管理 → 数据迁移。
- 旧版：管理员 → 数据迁移。旧后端新增 `DataMigration`，旧前端新增 `pages/adminPack/dataMigration/dataMigration.vue`。
- 新版部署执行正常的 `python manage.py migrate`，并重启 Celery worker/beat 加载新增任务。本地已应用新增迁移并检查任务注册。
- 旧版在其对应环境执行 `python manage.py migrate DataMigration` 并部署 Web 代码即可；普通导出不需要新增常驻 worker。保留的 `migration_export_worker --once` 仅作为可选维护工具。
- 新版 `DATA_MIGRATION_PRIVATE_ROOT` 默认 `.private/data-migration`；旧版 `DATA_MIGRATION_EXPORT_ROOT` 默认 `var/data-migration`。新版 Web/worker、旧版多 Web 实例分别共享各自私有持久目录，不能暴露为公开静态目录。
- `DATA_MIGRATION_ALLOWED_MEDIA_HOSTS` 配置允许读取的旧 OSS/CDN 域名。默认包含旧 Uhome OSS 域名；其他合法来源按实际导出配置。失效签名或私有来源支持修正为可读 URL、或补传文件；导出包不携带存储读取密钥。

## 旧版请求内生成的边界

创建记录和执行生成分成两个请求，生成接口显式绕过请求级事务，避免响应失败回滚任务结果。前端不因连接超时直接写“生成失败”，而是根据记录查询结果显示状态。查询不会启动重任务；未发起执行的记录可点击继续生成，超过 5 分钟无有效进度的记录可重试。Web 进程被终止时不能保证继续执行，此方案不具备独立后台队列的完成保证。

旧版打包器的本机合成数据基准：1,000 套房源及对应账单、薪资、勘察、统计和 6,001 条媒体引用耗时 0.38 秒、ZIP 0.22 MiB；10,000 套及 60,001 条媒体引用耗时 3.865 秒、ZIP 2.077 MiB。使用内存 SQLite，不包含生产 MySQL、网络和并发负载，不作为生产耗时承诺。
