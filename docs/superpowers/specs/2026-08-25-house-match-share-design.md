# 一次性配房分享设计

## 背景

项目已经具备房源、小区、楼栋、公开房源查询、房源详情、顾问账号、行为分析和带看记录等基础能力，但缺少员工按客户需求快速生成一条公开房源分享链接的能力。

本功能定位为“一次性配房分享”：员工选择固定房源或填写动态筛选条件，系统立即生成一条随机公开链接。分享内容创建后不可编辑，不提供历史列表或管理入口；需要调整时重新创建一条链接。

分享记录必须可靠存在到设定到期时间，因此使用数据库持久化，不使用 Redis 作为唯一数据源。

## 目标

- 同时支持手工配房和动态配房，两种模式在单条分享记录中互斥。
- 员工创建后立即获得可匿名访问的 H5 链接。
- 手工模式保存有序房源 ID，最多 100 套。
- 动态模式保存固定筛选规则，访问时实时查询全部匹配房源并分页展示。
- 分享页和详情页实时读取房源、组织和顾问数据，不保存展示快照。
- 支持任意未来到期时间和永不过期。
- 分享记录创建后不可编辑；不提供列表、修改、撤销、重新生成或删除接口。
- 复用现有公开房源结构、户型格式化逻辑、行为分析和 H5 技术栈。

## 非目标

- 配房历史列表或管理后台。
- 修改、撤销或重新生成已有分享记录。
- 租客联系人绑定。
- 咨询线索、跟进任务或独立咨询表。
- 逐套推荐理由、逐套备注、重点推荐或价格快照。
- Redis 缓存或 Redis 持久化。
- 自动清理过期分享记录。
- 为配房新增整租/合租、押付方式、入住日期、地铁等房源字段。
- 配房方案级统计报表。

## 方案选择

### 采用：数据库单表、不可编辑的分享记录

新增 `HouseMatchShare`，只提供创建和公开读取能力。数据库用于保证链接可靠存在，不意味着需要后台维护页面。

### 未采用：Redis 保存

Redis 重启、数据清理或内存淘汰可能导致未到期链接提前失效，不满足链接必须稳定存在到到期时间的要求。

### 未采用：签名 URL 携带全部数据

手工模式最多包含 100 个房源 ID，签名 URL 会过长；同时不利于规则版本升级、顾问删除和服务端校验。

## 模块边界

功能继续归属 `apps.house`，但拆分专用模块，避免扩大现有 `apps/house/api.py` 和 `apps/house/schemas.py`：

```text
apps/house/
├── models.py
├── match_api.py
├── match_schemas.py
└── match_services.py
```

- `models.py`：声明 `HouseMatchShare`。
- `match_schemas.py`：创建输入、创建输出、公开分享信息和顾问信息结构。
- `match_services.py`：创建校验、随机字符串生成、动态规则应用、手工房源解析和公开可用性判断。
- `match_api.py`：创建接口和匿名读取接口。

前端分别在现有管理端房源页面和 `frontend_miniprogram` H5 中实现，不新增独立管理模块。

## 数据模型

### HouseMatchShare

模型继承现有 `BaseModelMixin`，保留项目统一的 `created_at`、`updated_at`、`created_by` 和 `updated_by` 字段。业务顾问不复用审计字段，使用独立外键 `consultant`。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `organization` | FK → Organization | `PROTECT` | 创建时从当前组织上下文写入 |
| `consultant` | FK → User | `SET_NULL`，可空 | 创建配房分享的员工 |
| `share_key` | CharField | 唯一索引 | URL 安全随机字符串 |
| `title` | CharField | 必填，最大 150 | 公开分享标题 |
| `remark` | TextField | 可空 | 统一公开备注 |
| `mode` | choices | `manual` / `dynamic` | 配房模式 |
| `house_ids` | JSONField | 默认空列表 | 手工模式的有序房源 ID |
| `criteria` | JSONField | 默认空对象 | 动态模式的固定规则 |
| `criteria_version` | PositiveSmallIntegerField | 默认 `1` | 动态规则格式版本 |
| `expires_at` | DateTimeField | 可空 | 空值表示永不过期 |

### 模型不变量

- `manual` 模式必须包含 1～100 个 `house_ids`，且 `criteria` 必须为空。
- `dynamic` 模式必须包含至少一个合法筛选条件，且 `house_ids` 必须为空；只有 `sort` 不算筛选条件。
- 房源 ID 必须为正整数；保存前去重并保留首次出现的位置。
- `expires_at` 非空时必须晚于创建时间。
- `share_key` 使用密码学安全的 URL 字符串，发生唯一键碰撞时有限次数重试。
- `criteria_version` 初始为 `1`；手工模式保留默认版本值但不参与解析。
- 记录在应用层不可变：不注册 Django admin，不提供更新服务或更新接口。
- `consultant` 删除后置空，分享记录继续存在。

## 动态规则

第一版只支持现有公开房源查询已经具备的条件：

```text
keyword
province
city
district
min_rent
max_rent
min_area
max_area
bedrooms
living_rooms
decoration
has_elevator_access
tags
sort
```

不允许保存以下字段：

```text
organization
publisher_slug
status
page
page_size
房东、内部备注等内部管理条件
```

规则要求：

- 输入结构使用严格 Schema，未知字段直接拒绝。
- 动态模式至少需要一个实际筛选条件，避免误操作把组织全部招租房源公开分享；仅选择排序方式不能创建。
- 最小值不得大于最大值。
- 装修、排序等值必须在现有枚举白名单内。
- 标签沿用当前公开搜索语义：选择多个标签时，房源必须满足全部标签。
- 动态配房不保存结果快照；新增、下架或修改后符合规则的房源会实时进入或退出结果。
- 从现有公开房源 API 抽取 `apply_public_house_filters()`，公开搜索和动态配房共用同一实现，避免规则漂移。

## 手工房源解析

创建时：

- 所有 ID 必须存在。
- 所有房源必须属于当前组织。
- 所有房源必须处于 `listed` 状态。
- 任意一个 ID 不合法时整次创建失败，不静默丢弃。

访问时重新校验实时状态：

- 只返回当前仍属于分享组织、组织仍启用且状态仍为 `listed` 的房源。
- 房源不存在、下架、出租、停用或改变组织后自动跳过。
- 使用 `house_ids` 的原始顺序返回有效房源。
- 全部房源失效时返回正常空分页，不将分享记录视为异常。

## API 设计

### 创建分享

```text
POST /api/house-match-shares/
```

要求：

- 必须登录并选择组织。
- 当前用户必须仍是当前组织成员。
- `organization` 从请求上下文写入，客户端不能指定。
- `consultant` 强制写入当前用户，客户端不能指定其他员工。
- 创建成功后立即生成可访问链接。
- 提交期间由前端阻止重复点击；服务端允许两次独立提交生成两条独立记录。

输入字段：

```text
title
remark
mode
house_ids
criteria
expires_at
```

输出字段：

```text
share_key
share_url
expires_at
created_at
```

`share_url` 通过统一路由辅助函数生成，不在业务代码中手写 H5 Hash 路由细节。

### 获取公开分享信息

```text
GET /api/public/house-match-shares/{share_key}/
```

匿名访问，返回：

- 标题、统一备注、模式、创建时间和到期时间。
- 当前可公开的顾问信息。
- 不返回 `organization_id`、原始 `house_ids` 或 `criteria`。

顾问信息包含：

- 当前姓名：优先使用用户完整姓名，无完整姓名时回退到用户名。
- 当前头像 URL。
- 当前已验证手机号。

只有同时满足下列条件时才返回顾问信息：

- `consultant` 用户仍存在。
- 用户账号处于启用状态。
- 用户仍是该分享所属组织的成员。

否则返回 `consultant=null`，分享链接和房源仍可访问。

### 获取分享房源

```text
GET /api/public/house-match-shares/{share_key}/houses/
```

匿名访问，统一使用：

```text
page
page_size
```

响应保持项目最小分页结构：

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "page_size": 15
}
```

- 手工模式过滤失效房源后按保存顺序分页。
- 动态模式实时查询并按保存的 `sort` 规则分页，不限制匹配总量。
- 响应项复用 `PublicHouseListOut`，不暴露内部字段。

### 房源详情

H5 详情页使用分享上下文内的公开详情接口：

```text
GET /api/public/house-match-shares/{share_key}/houses/{house_id}/
```

接口先校验分享链接仍有效，再确认房源当前仍属于该分享：

- 手工模式要求 `house_id` 存在于 `house_ids` 且房源当前仍公开可用。
- 动态模式要求房源当前仍满足保存的 `criteria`。
- 响应结构复用 `PublicHouseDetailOut`。

这可以避免用户修改详情页 URL 后，把当前顾问信息错误关联到不属于该配房分享的其他公开房源。房源下架或不再匹配规则后返回 `404`，页面引导用户返回配房列表。

### 明确不提供的接口

- 分享记录列表。
- 分享记录内部详情。
- 更新、删除、撤销或重新生成。
- 按顾问或组织检索分享记录。

## 链接与生命周期

- 链接形式为 H5 页面地址加随机字符串，持有链接即可匿名访问。
- 默认到期时间为创建后 30 天。
- 创建时允许选择任意未来时间。
- `expires_at=null` 表示永不过期。
- 分享链接可以重复访问，不会因首次访问失效。
- 分享内容创建后不可修改；需要调整时重新创建新链接。
- 到期判断在读取时实时执行，不依赖定时任务。
- 第一版不自动删除过期记录，永不过期记录永久保留。

### 已接受的产品风险

- 永不过期链接创建后无法撤回；只要组织仍启用，链接会持续有效。
- 关闭创建成功弹窗后无法通过产品界面找回链接。
- 创建人应在选择“永不过期”前看到明确提醒，并确认链接可能长期传播。

## 公开可用性与错误处理

| 场景 | HTTP 行为 | 页面行为 |
| --- | --- | --- |
| 随机字符串不存在 | `404` | 分享链接不存在 |
| 分享已过期 | `410` | 配房链接已过期 |
| 分享所属组织停用 | `404` | 分享链接不可用 |
| 未知 `criteria_version` | `422` | 链接版本暂不支持，请重新生成 |
| 房源全部失效 | `200` 空分页 | 当前暂无可用房源 |
| 顾问删除、停用或退出组织 | `200`，`consultant=null` | 隐藏顾问卡片或显示信息暂不可用 |
| 单套房源下架或不再属于分享结果 | `404` | 提示房源已下架或不再可用并返回列表 |

公开分享和房源结果使用 `Cache-Control: no-store`，确保房态、租金和顾问信息实时更新。

## 管理端交互

不新增“配房管理”菜单。在现有房源列表增加“生成配房链接”入口。

### 手工模式

- 房源列表启用跨分页选择。
- 最多选择 100 套，达到上限后阻止继续选择。
- 只允许选择当前 `listed` 房源。
- 保留选择顺序作为公开展示顺序。

### 动态模式

- 使用独立公开筛选表单。
- 不直接序列化管理端全部筛选状态。
- 仅包含动态规则白名单中的字段。

### 公共创建字段

- 标题。
- 统一备注。
- 到期时间，默认 30 天。
- “永不过期”选项。

### 创建结果

- 成功后弹窗展示完整链接并提供复制操作。
- 明确提示“链接内容不可修改，如需调整请重新生成”。
- 关闭结果弹窗后不提供历史列表找回链接。
- 创建失败时保留表单输入和手工选择。
- 创建期间禁用重复提交。
- 不修改管理端多语言文件。

## H5 页面

在 `frontend_miniprogram` 新增两个匿名页面，并保持默认无需登录策略。

### 配房分享页

展示：

- 标题和统一备注。
- 当前可公开顾问头像、姓名和手机号。
- 存在已验证手机号时提供一键拨号。
- 房源卡片列表。
- 手工模式按保存顺序分页。
- 动态模式按规则实时分页或触底加载。

### 房源详情页

展示现有公开详情允许的内容：

- 图片和视频。
- 租金、面积、户型、朝向和装修。
- 标签、地址和地图位置。
- 同一分享上下文中的顾问信息和拨号入口。

必须复用共享户型格式化逻辑，确保一室零厅显示为“单间”。

### 页面状态

- 加载中。
- 无匹配房源。
- 链接不存在。
- 链接已过期。
- 链接所属组织停用。
- 顾问信息不可用或没有已验证手机号。
- 房源加载失败。
- 房源浏览期间下架。

## 行为分析

不新增配房分享统计表或新的分析目标。H5 复用现有事件：

- `house.exposure`
- `house.view`
- `house.phone_click`
- `house.share`

事件统一使用 `campaign=house_match`。不将完整 `share_key` 写入分析属性或结构化业务日志；基础设施访问日志仍遵循项目现有 URL 日志策略。

## 测试设计

### 模型与服务测试

- `manual` 与 `dynamic` 模式互斥。
- 手工 ID 正整数校验、去重、顺序保持和 100 套上限。
- 动态规则白名单、数值范围和枚举校验。
- 安全随机字符串生成和唯一键碰撞重试。
- 未来到期时间、已过期和永不过期判断。
- 手工房源下架或删除后的跳过行为。
- 动态结果随实时房源增加和减少。
- 跨组织隔离。
- 公开顾问仍在组织、退出组织、停用和删除的行为。
- 公开序列化不包含房东、内部备注和规则原文。

### API 测试

- 未登录用户不能创建分享。
- 未选择组织不能创建分享。
- 客户端不能伪造组织或顾问。
- 匿名用户可以读取有效分享和房源。
- `404`、`410` 和 `422` 行为正确。
- 手工与动态分页均使用 `page/page_size` 和最小响应结构。
- 不存在列表、更新和删除路由。
- 公开响应带有禁止缓存策略。

### 管理端测试

- 手工选择上限和跨分页选择。
- 动态规则请求结构。
- 到期时间和永不过期输入。
- 创建成功、失败和重复提交保护。
- 结果链接复制。
- 关闭成功弹窗后不出现历史管理入口。

### H5 测试

- 正常、空、过期、失效和加载失败状态。
- 顾问信息显示、隐藏和拨号入口。
- 手工顺序和动态分页。
- 房源详情跳转。
- 篡改详情页 `house_id` 时不能把顾问信息关联到分享范围外的房源。
- 房源下架后的返回流程。
- 单间户型展示规则。

## 实施边界

实现应限制在本功能直接需要的文件中，不进行无关的房源模块重构。唯一允许的针对性整理是从现有公开房源 API 抽取共享筛选函数，供全局公开搜索和动态配房共同使用。
