# 房表同步界面全面重构设计

**日期：** 2026-07-18

**状态：** 已确认，待实现

**目标页面：** `/dashboard/property-rental/vacancy-sync`

## 背景

当前房表同步页面已经具备粘贴房表、预览计划、处理错误行、选择歧义楼栋和确认执行同步的完整业务能力，但页面呈现仍接近表单与卡片的纵向堆叠：输入、预览统计、楼栋变更和逐行识别之间缺少稳定的空间关系；生成预览后需要在较长页面中上下移动，难以同时对照原始房表与识别结果；页面留白较多，视觉上不够像一个高频运营工具。

本次重构不改变后端协议和核心同步规则，重点把页面改造成浅色、高密度、与现有管理端一致的专业同步工作台。

## 已确认的设计选择

- 视觉体验是本次重构的第一优先级。
- 采用“专业同步工作台”方向，而不是分步向导或低密度编辑器。
- 保持现有 Ant Design 管理端的浅色风格，不改全局顶部导航和侧边栏。
- 桌面端采用左侧原始房表、右侧同步结果的双栏布局。
- 生成预览后，左侧原始房表仍可直接编辑。
- 原始房表一旦修改，旧预览保留用于参考，但立即标记为失效并禁止执行同步。
- 每栋楼的逐行识别明细默认全部展开，不使用默认折叠状态。
- 错误、楼栋歧义、预览失效和同步完成都必须有完整的页面状态，不只依赖消息提示。

## 目标

- 让用户在一个视口内同时对照原始房表与识别结果。
- 强化楼栋、房源行、资料变化和房态变化之间的视觉层级。
- 减少纵向卡片堆叠造成的空白和来回滚动。
- 明确区分“输入内容”“只读预览”“已失效预览”“实际执行结果”。
- 让阻塞问题可以快速定位、处理并自动重新预览。
- 同步成功后保留实际结果，便于复核和继续下一份房表。
- 保持现有接口、租户隔离、确认弹窗和请求失效逻辑不变。

## 非目标

- 不修改 `/api/house/vacancy-sync/` 请求或响应结构。
- 不改变房表解析、楼栋匹配、房态计算或 `plan_hash` 规则。
- 不调整管理端全局导航、主题、菜单或其他房源租赁页面。
- 不增加房表导入历史、撤销同步、文件上传或导出接口。
- 不重写生成的 OpenAPI 客户端。

## 页面信息架构

页面从上到下分为五个稳定区域。

### 1. 页面标题与快捷操作

标题区保持现有管理端的 `PageContainer` / 面包屑体系，内容包括：

- 标题“房表同步”。
- 一句简短说明：“粘贴最新空置清单，核对识别及变更结果后执行同步。”
- “使用说明”“清空”“预览 / 重新预览”操作。

“使用说明”不再长期占据一整块蓝色 `Alert`。粘贴格式和同步规则放入按钮触发的 `Popover`；页面只保留一行安全提示。

### 2. 安全状态条

标题下方显示当前工作台状态：

- 未预览：提示先粘贴并生成预览。
- 预览有效：提示当前仅为计划，尚未修改数据，并显示预览时间。
- 预览失效：提示原始内容已变化，旧结果仅供参考。
- 存在阻塞问题：显示问题数量和首个问题定位入口。
- 已执行：显示完成时间和实际结果说明。

状态条使用 Ant Design `Alert` 或语义化状态容器，颜色只辅助表达，必须同时包含文字和图标。

### 3. 汇总指标带

预览后显示六个紧凑指标：

- 涉及楼栋。
- 有效房源。
- 新建房源。
- 更新资料。
- 改为空置。
- 改为已租。

六个主指标保持稳定。存在特殊状态保留、错误行或停用冲突时，在指标带下方追加一行紧凑状态标签。指标使用轻量卡片，不使用大尺寸 `Statistic`，避免抢占垂直空间。

### 4. 双栏工作区

桌面端工作区采用约 `34% / 66%` 的左右分栏：

- 左栏：原始房表编辑器。
- 右栏：楼栋同步结果与逐行明细。

中等宽度可以调整到约 `40% / 60%`。窄屏按“输入在上、结果在下”堆叠，禁止通过极窄双栏压缩表格。

#### 左栏：原始房表编辑器

左栏包含：

- “原始房表”标题与格式状态。
- “载入示例”“粘贴格式”和快捷键提示。
- 保持可编辑的 `Input.TextArea`。
- 有效房源数量、文本大小和限制提示。
- 错误行或修改行的定位反馈。

编辑器不做脱离页面的独立滚动陷阱。在宽度不小于 1200px 的桌面布局中，左栏容器使用 `position: sticky` 固定在工作区顶部；输入框内部仍只使用已有的最大高度滚动。更窄布局取消 sticky。

#### 右栏：楼栋同步结果

每个楼栋使用一个紧凑结果卡，结构固定为：

1. 楼栋名称、地址、匹配状态和问题状态。
2. 本栋有效房源数量与变化数量。
3. 楼栋歧义选择器或段落级错误。
4. 资料更新、改为空置、改为已租、新建房源、保留特殊状态和停用冲突摘要。
5. 默认展开的逐行识别明细表。

逐行表格列包括：行号、原始内容、房号、户型、租金、标签、识别状态和必要的处理动作。表格保持紧凑尺寸，并在宽度不足时横向滚动。

### 5. 固定执行栏

页面底部使用 `position: sticky` 的执行栏，始终明确展示：

- 当前计划是否可执行。
- 将处理的楼栋和房源数量。
- 预览是否失效。
- “确认并执行同步”主操作。

执行栏不能遮挡最后一张楼栋卡，页面底部需预留等高空间。以下情况必须禁用主操作：

- 尚未生成预览。
- 预览已失效。
- `can_apply` 为 `false`。
- 缺少 `plan_hash`。
- 正在预览或执行。
- 已经执行完成。

## 关键交互

### 初始输入

- 没有预览时，右栏展示简洁空状态和粘贴格式示例，不显示空表格。
- 用户粘贴内容后可以点击“预览同步计划”，并支持 `Command/Ctrl + Enter` 快捷预览。
- 空内容继续使用现有警告提示，不发送请求。

### 生成预览

- 请求成功后保留左侧输入，右侧展示完整楼栋卡和逐行表格。
- 页面滚动到工作区顶部，而不是直接跳到某个深层表格。
- 若存在错误，首个阻塞楼栋卡置顶或自动滚动进入可见区域。
- 指标带和底部执行栏同时更新，形成稳定的页面状态反馈。

### 输入修改与预览失效

当前实现会在输入变化时直接清空 `preview`。重构后改为保留旧预览，并记录生成该预览时的输入快照。

- `rawText` 与预览输入快照不同即视为 `previewStale`。
- 右侧旧结果降低视觉权重，并覆盖“预览已失效”提示。
- 底部“确认同步”禁用，主预览按钮改为“更新预览”。
- 不自动请求，避免用户连续编辑时产生大量预览请求。
- 更新预览成功后替换输入快照并解除失效状态。

楼栋覆盖选择和错误行忽略属于对当前计划的明确修正，继续沿用“更新状态后自动重新预览”的行为。

### 错误行处理

- 左侧原文对应行使用错误背景和左侧标识定位。
- 右侧对应楼栋卡显示错误数量，错误行在逐行表格中保持可见。
- “忽略此行”与“恢复处理”继续位于行内。
- 操作完成后自动重新预览。
- 处理期间禁用重复操作并展示局部加载状态。

### 楼栋匹配歧义

- 候选楼栋选择器放在楼栋卡顶部，而不是独立弹窗。
- 候选项同时显示楼栋名称、地址和可用的辅助信息。
- 选择后自动重新预览。
- 未选择前该楼栋卡和固定执行栏明确标记为阻塞状态。

### 确认执行

- 保留二次确认弹窗。
- 弹窗突出显示楼栋数量、有效房源数量、改为空置和改为已租数量。
- 明确提示同步会直接修改房态和部分房源资料。
- 弹窗确认按钮在执行期间显示加载状态，防止重复提交。

### 同步成功

- 页面保留服务端返回的实际执行结果，不清空输入或结果。
- 顶部状态条切换为完成状态，并显示执行时间。
- 固定执行栏替换为“本次同步已完成”的摘要。
- 提供“同步下一份房表”操作；只有该操作会重置输入、忽略行、楼栋覆盖和结果。
- 提供跳转现有房源列表的次要操作，不增加新的接口。

## 组件边界

当前 `index.tsx` 同时承担请求、页面状态、列定义和全部展示逻辑。重构时按页面内职责拆分，但不建立跨页面抽象。

建议结构：

```text
vacancy-sync/
├── index.tsx
├── index.test.tsx
├── components/
│   ├── VacancySyncHeader.tsx
│   ├── VacancySyncSourcePanel.tsx
│   ├── VacancySyncSummary.tsx
│   ├── VacancySyncBuildingCard.tsx
│   ├── VacancySyncLineTable.tsx
│   └── VacancySyncActionBar.tsx
└── vacancySyncViewModel.ts
```

职责划分：

- `index.tsx`：持有请求、业务状态和页面编排。
- `VacancySyncSourcePanel`：输入、示例、格式说明和输入计数。
- `VacancySyncSummary`：把响应汇总转换成稳定的指标项。
- `VacancySyncBuildingCard`：楼栋匹配状态、变更摘要和楼栋级操作。
- `VacancySyncLineTable`：逐行识别明细与错误行处理。
- `VacancySyncActionBar`：可执行判断、计划摘要和最终操作。
- `vacancySyncViewModel.ts`：纯函数形式的显示数据转换、状态元信息和数量计算。

组件只使用本页面的类型，不修改生成服务。楼栋卡、行表格和执行栏保持独立，页面标题、状态条和汇总指标统一由 `VacancySyncHeader` 编排。

## 状态与数据流

页面继续使用现有 `useMutation` 和 `houseApi.vacancySync()`，新增明确的预览快照状态。

核心状态：

- `rawText`：当前可编辑文本。
- `ignoredLines`：当前忽略行集合。
- `buildingOverrides`：当前楼栋覆盖选择。
- `preview`：最近一次成功的预览或执行结果。
- `previewInput`：生成当前预览时使用的规范化输入快照。
- `completedAt`：前端用于展示本次成功完成时间。

派生状态：

- `hasPreview`：存在 `preview`。
- `previewStale`：当前输入与 `previewInput` 不一致，且结果尚未执行完成。
- `canConfirm`：预览有效、可执行、有 `plan_hash`、未完成且请求空闲。
- `hasBlockingIssues`：预览存在且 `can_apply` 为 `false`。

预览成功后同时保存 `preview` 和对应 `previewInput`。错误行忽略或楼栋选择会构造下一份请求并自动预览；成功后原子替换两者。执行成功后以服务端响应替换 `preview` 并进入完成状态。

## 视觉规范

- 使用现有 Ant Design 主题 token，不引入页面级深色主题。
- 主色、成功色、警告色和错误色沿用 `theme.useToken()`。
- Tailwind CSS v4 用于网格、间距、宽度和响应式布局。
- 需要基于 token 的局部状态样式时使用 `antd-style` 的 `createStyles`。
- 卡片圆角、边框和阴影保持管理端现有尺度，避免独立品牌皮肤。
- 表格、Tag 和按钮保持紧凑尺寸，但点击目标不能过小。
- 颜色不作为唯一状态信号；所有状态都有图标或文字标签。
- 不新增无必要的全局 CSS 或 Less 文件。

## 响应式与可访问性

- 宽桌面：约 `34% / 66%` 双栏。
- 中等桌面：约 `40% / 60%`，逐行表格横向滚动。
- 窄屏：输入区与结果区上下堆叠，执行栏退化为普通底部操作卡，不遮挡内容。
- 页面状态变化使用可被辅助技术感知的 `aria-live` 区域。
- 错误行处理按钮使用明确的可访问名称，不能只显示图标。
- 楼栋选择器保持表单标签和错误说明关联。
- 键盘用户可以从输入框直接触发预览，并按正常文档顺序进入结果区。
- 页面自动定位首个错误时同时转移合理焦点，避免只改变滚动位置。

## 错误与并发处理

- 普通请求错误继续由全局请求层展示，页面保留当前输入和最近结果。
- `plan_hash` 冲突时保留旧结果并标记失效，提示数据已变化，需要重新预览。
- 自动重新预览失败时，不回滚用户刚做的忽略或楼栋选择；页面保留选择并允许再次预览。
- 执行失败时关闭确认弹窗的加载状态，页面仍停留在可复核的预览结果。
- 执行成功后继续失效 `['house']` 查询，必要时补充楼栋相关查询失效，但不扩大无关缓存清理。

## 测试与验收

保留现有预览、确认、错误行忽略和楼栋覆盖测试，并补充最小用户可见行为测试：

- 输入修改后旧预览仍显示，但标记失效且确认按钮不可用。
- 重新预览成功后失效状态解除。
- 逐行识别明细默认可见。
- 存在错误或楼栋歧义时确认按钮不可用。
- 同步成功后实际结果保留，并出现“同步下一份房表”。
- “同步下一份房表”会重置所有页面状态。

视觉验收：

- 在常见桌面宽度下，原始房表和至少一张楼栋卡可以同时进入视野。
- 页面不再以大块说明卡和纵向卡片堆叠作为主要结构。
- 最后一张楼栋卡不会被固定执行栏遮挡。
- 长原始内容、长地址、多个标签和横向表格不会破坏布局。
- 错误、警告、预览失效和完成状态都有清晰且一致的视觉反馈。

实现后在 `frontend_admin/` 下先执行 `nvm use 22`，再运行相关 Vitest、TypeScript 检查和 Ant Design 用法检查。非必要的全量测试可以跳过。
