# 小程序中介 SaaS 商业闭环设计

日期：2026-09-19  
状态：已确认，待实现计划

## 1. 文档定位

本文定义 `frontend_miniprogram/` 面向中介客户的 SaaS 获客、入驻、试用激活、自助购买、支付交付、续费升级和企业销售分流闭环。

本文建立在以下既有设计与实现之上，不重做订阅、支付和组织工作台：

- `docs/superpowers/specs/2026-07-24-saas-subscription-billing-design.md`；
- `docs/superpowers/specs/2026-09-06-miniprogram-three-role-business-closure-design.md`；
- 当前 `apps.organizations`、`apps.subscriptions`、`apps.payments`、`apps.access` 后端能力；
- 当前小程序中介端房源、客户、带看、签约、租约、团队、权限、经营分析和订阅页面。

本文解决的问题不是“组织管理员能否完成支付”，而是“一个第一次接触链云空间的中介，能否在小程序内了解产品、创建门店、体验价值、完成购买并持续续费”。

## 2. 已确认产品决策

| 决策 | 规则 |
| --- | --- |
| 成交模式 | 混合成交：标准版、专业版自助购买；企业版联系销售 |
| 目标客户 | 同时覆盖独立中介和中小门店，首屏表达更偏向 1～50 人客户 |
| 主路径 | 试用优先，不在进入产品前要求用户完成复杂问卷或资质填写 |
| 试用 | 新组织满足现有资格规则时，自动获得一次 14 天专业版试用，无需绑卡 |
| 激活目标 | 首日创建房源，3 日内邀请成员并分配房源，7 日内完成一次带看或签约 |
| 到期 | 未购买则回落免费版；历史数据保留，超额资源禁止继续新增 |
| 企业版 | 公开展示企业能力和联系销售入口，不在小程序内提供普通自助购买按钮 |
| 视觉与导航 | 复用现有蓝色品牌、小程序卡片和中介端导航，不新增一套底部 Tab |

## 3. 目标与非目标

### 3.1 目标

- 给无组织用户提供明确的“我是中介”入口和公开 SaaS 介绍页；
- 让已验证手机号的新用户在约 30 秒内创建个人工作空间或中介门店；
- 创建组织后自动切换到中介端，并让符合资格的组织立即感知 14 天专业版试用；
- 用真实业务任务而非功能导览推动试用激活；
- 让套餐页能够回答“我为什么买、该买哪档、购买后得到什么”；
- 完成微信支付后的自动确认、权益交付和异常恢复；
- 建立试用转付费、升级、续费和企业销售线索漏斗；
- 不破坏现有组织 RBAC、订阅状态机、权益快照和支付幂等规则。

### 3.2 非目标

- 不重做现有组织工作台、房源、客户、带看、签约和租约领域；
- 不建设完整 CRM、销售排班、合同审批或电子合同系统；
- 不实现微信自动续费或委托代扣；
- 不提供优惠券、促销码、复杂折扣和按量计费；
- 不要求首次试用前上传营业执照；资质认证继续由需要公开经营能力的业务环节承担；
- 不在本设计中改变现有免费版、标准版和专业版价格。

## 4. 用户主链路

### 4.1 购买前

```text
中介入口
  -> SaaS 介绍页
  -> 免费试用 14 天
  -> 登录
  -> 未验证手机号时完成手机号验证
  -> 创建个人工作空间或中介门店
  -> 自动切换中介端
  -> 自动开通专业版试用或明确说明未获得试用的原因
```

入口包括：

- 无组织用户“我的”页固定入口：“我是中介，免费开通工作台”；
- SaaS 介绍页分享链接、分享卡片和销售二维码；
- 已有组织用户不展示创建入口，继续通过身份切换器进入现有组织；
- C 端找房首页不强行插入高干扰 B 端广告。

现有订阅规则要求试用创建人已验证手机号，且一生最多为 3 个组织获得试用。因此微信登录后若手机号未验证，必须先进入现有手机号验证流程；不能创建组织后才让用户发现没有试用。

### 4.2 试用激活

```text
首日：创建第一套房源
  -> 3 日内：邀请至少一名成员并完成一次房源分配
  -> 7 日内：完成一次带看或登记签约
  -> 第 10～14 日：根据用量和已使用能力推荐套餐
```

客户登记可以作为完成带看前的中间引导，但单独登记客户不算最终业务激活。

试用期间套餐页始终可访问，但系统不在用户刚创建组织时立即用全屏弹窗催促购买。主动转化提示满足以下任一条件后出现：

- 已完成至少两个激活里程碑；
- 试用进入第 10 天；
- 当前用量接近所推荐套餐的免费版权益限制。

### 4.3 成交与交付

```text
查看套餐
  -> 选择标准版或专业版
  -> 选择月付或年付
  -> 创建订单
  -> 微信 JSAPI 支付
  -> 自动查询订单状态
  -> 支付成功并开通权益
  -> 返回中介工作台 / 查看订单 / 申请发票
```

企业版路径为：

```text
查看企业版
  -> 联系销售
  -> 提交规模和需求
  -> 销售跟进演示、报价、合同和对公付款
```

企业版必须采用显式的销售辅助购买规则。套餐目录应支持 `purchase_mode` 或等价字段：

- `self_service`：标准版、专业版，可由组织管理员在线下单；
- `sales_assisted`：企业版，小程序显示联系销售，组织侧普通创建订单接口拒绝自助下单。

这样可以避免界面显示“联系销售”，但用户仍可绕过界面直接创建企业版自助订单。

`sales_assisted` 同时适用于企业版首次购买、升级和续费。已有企业版订阅在切换购买模式前需明确迁移和续费承接方案，不能让现有客户在到期时失去可用的续费路径。

### 4.4 到期、升级与续费

- 试用到期未购买时回落免费版，保留全部历史数据；
- 超出免费版配额时，允许查看、编辑和删除既有数据，只禁止继续增加数量；
- 成员、团队或房源达到套餐用量的 80% 时显示轻提醒，达到 100% 时显示明确升级路径；
- 年付订阅到期前 30 天、7 天、1 天分级提醒；月付订阅使用到期前 7 天、1 天提醒；14 天试用使用到期前 3 天、1 天提醒；
- 通知在小程序内应解析到小程序订阅页，不继续只指向 `/dashboard/...`；
- 同套餐续费、向上升级、周期切换和折抵规则继续遵循既有订阅设计。

## 5. 页面与交互设计

### 5.1 SaaS 介绍页

首屏只表达一个结果：

> 房源、客户、带看、签约，一个小程序管起来。

辅助说明：

> 适合个人中介和 50 人以内门店，14 天专业版免费试用，无需绑卡。

首屏操作：

- 主操作：“免费试用 14 天”；
- 次操作：“查看套餐与价格”；
- 已有组织用户显示“进入中介工作台”，不重复创建组织。

首屏下方只展示三组可由现有产品承接的价值：

- 房源统一管理；
- 客户、带看和签约持续跟进；
- 团队成员、职责和权限清晰。

不得在功能尚未实际接入时，仅根据套餐预留的 feature flag 宣称已经支持数据导出、API 集成或其他高级能力。

### 5.2 创建中介组织

表单保持一屏完成：

- 经营类型：个人中介、中介门店；
- 工作空间/门店名称；
- 所在城市；
- 团队规模：1 人、2～5 人、6～20 人、21～50 人、50 人以上。

现有 `Organization` 只有名称、slug 和账单邮箱等基础字段。经营类型、城市、团队规模属于 SaaS 入驻画像，不应只停留在前端表单。建议在订阅领域增加一对一的组织入驻画像，例如 `OrganizationSaaSProfile`，保存 `business_type`、`city_code`、`team_size_band` 和来源渠道。组织创建接口接收这些可选入驻字段，并在创建组织的同一事务或可靠 Hook 中写入画像。核心组织、权限和租赁业务不依赖这些画像字段。

创建成功后：

1. 调用现有组织创建接口；
2. 后端继续执行创建额度和试用资格校验；
3. 前端刷新可选身份与组织上下文；
4. 自动切换到新组织的中介模式；
5. 进入试用工作台，并展示已开通套餐和到期时间。

如果用户可创建组织但不再具备试用资格，仍允许创建组织，并明确进入免费版；不得用“创建成功”掩盖未获得试用的事实。

### 5.3 试用工作台

工作台顶部展示：

- 当前组织名称；
- “专业版试用”或“免费版”状态；
- 试用剩余天数或正式版到期日；
- 当前成员、团队、房源用量与上限。

激活任务区每次突出一个下一步：

1. 创建第一套房源；
2. 邀请同事并完成房源分配；
3. 完成一次带看或登记签约。

已完成任务保留完成状态和完成时间。任务点击直接深链到现有业务页面，不复制房源、邀请、带看和签约表单。

### 5.4 套餐选择页

套餐页需要同时展示：

- 当前订阅、试用或免费版状态；
- 月付/年付切换及年付节省金额；
- 成员、团队、房源额度；
- 已真正实现的功能差异；
- 当前用量和推荐原因；
- 首购、续费或升级后的实际变化；
- 到期、手动续费、发票和退款规则摘要。

操作规则：

- 免费版仅用于说明回落权益，不显示“购买免费版”；
- 标准版操作根据上下文显示“选择标准版”“续费标准版”或等价文案；
- 专业版试用期间显示“继续使用专业版”；
- 企业版显示“联系销售”，不显示在线购买按钮；
- 当前不可购买、不能降级或不适用的套餐必须解释原因，而不是只禁用按钮。

后台或初始化数据必须补齐真实的套餐 `description`、`display_note` 和已实现功能标签，避免套餐卡只有名称和价格。

### 5.5 支付确认与成功页

调用 `uni.requestPayment` 返回成功只代表客户端支付流程完成，不代表权益已经开通。前端应：

1. 立即查询订单；
2. 每约 2 秒查询一次，最多等待约 30 秒；
3. 订单为 `paid` 后进入成功页；
4. 超时仍未确认时显示“支付确认中”，允许手动刷新，同时由后台主动对账继续恢复；
5. 用户取消支付时保留待支付订单，展示“继续支付”和“更换套餐”。

成功页展示：

- 已开通套餐；
- 生效时间和到期时间；
- 新的成员、团队、房源额度；
- 已生效的核心功能；
- 返回中介工作台、查看订单、申请发票三个后续入口。

### 5.6 发票体验

- 电子发票文件使用“查看/下载发票”操作，不显示裸 URL；
- 企业抬头时按现有后端规则校验税号等必要资料；
- 发票申请展示处理中、已开具、已驳回等状态；
- 已驳回申请展示管理员处理说明，但不泄露内部敏感备注。

## 6. 状态模型

用户侧产品状态：

```text
visitor
  -> authenticated_without_org
  -> free | trialing
  -> pending_payment
  -> paid_active
  -> renewal_due
  -> ended_and_fallback_to_free
```

企业销售为并行分支：

```text
visitor | organization_member
  -> enterprise_lead_submitted
  -> contacting
  -> qualified
  -> won | lost
```

产品状态只用于前端组织页面和转化路径。订单、订阅、支付、权益事实继续由现有后端模型负责，前端不得自行推断订单已支付或订阅已生效。

## 7. 接口与领域边界

### 7.1 直接复用

- 登录、手机号验证和账号恢复；
- 创建组织及组织身份切换；
- 创建组织后的专业版试用 Hook；
- 当前订阅、套餐、价格、权益和组织用量；
- 创建订单、继续支付、取消订单、主动查单；
- 微信支付、支付回调和后台主动对账；
- 权益生效、到期回落和配额拦截；
- 发票资料和发票申请；
- 组织成员、团队、房源、职责分配、带看和签约现有页面及接口。

### 7.2 公开套餐接口

新增独立只读营销接口，例如：

```text
GET /api/subscriptions/public-plans/
```

要求：

- 无需组织上下文；
- 只返回当前公开上架的套餐、当前展示价格、额度、已实现功能标签、购买模式和展示说明；
- 不返回内部版本、审计、成本或管理字段；
- 不放宽现有组织内订阅接口的认证与权限要求。

### 7.3 试用激活进度接口

新增组织作用域聚合接口，例如：

```text
GET /api/subscriptions/onboarding-progress/
```

返回：

- 当前订阅或试用摘要；
- 剩余天数；
- 三个激活里程碑的完成状态和完成时间；
- 当前推荐动作和目标路由；
- 当前用量、上限和是否接近配额；
- 是否应显示主动购买提示。

里程碑以现有业务事实计算，不建立用户可手工修改的完成状态：

- 房源里程碑：组织至少存在一套房源；
- 协作里程碑：除 owner 外存在有效成员或已接受邀请，并存在一次有效房源职责/分配；
- 业务里程碑：存在已完成带看或登记签约/租约事实。

完成时间可以通过既有记录时间聚合或由内部事件记录，不参与权限判断。

### 7.4 微信身份绑定

短信或密码登录用户如果没有 `wechat_miniprogram` 社交账号，支付前必须在当前小程序内完成微信身份关联。设计要求：

- 原地提示“绑定微信后继续支付”；
- 绑定完成后恢复原订单和支付动作；
- 不强制退出当前账号，不新建重复账号；
- 账号冲突时进入明确的账号合并/人工处理路径，不自动覆盖其他绑定。

具体接口继续复用或扩展现有 allauth/账号绑定能力，不在订阅模块复制身份系统。

### 7.5 企业销售线索

在订阅领域增加最小销售线索能力，例如 `SubscriptionSalesLead`：

- `user`、可选 `organization`；
- 来源页面或渠道；
- 团队规模、房源规模、关注需求；
- 联系方式快照；
- 状态：`new`、`contacting`、`qualified`、`won`、`lost`；
- 跟进人、处理说明和时间字段。

组织用户提交时优先复用已验证手机号，允许用户明确修改销售联系号码。接口写入属于外部沟通意向，提交前页面必须清楚说明用途。

一期企业闭环以“线索成功进入可跟进队列”为终点，不在小程序内建设合同和对公收款系统。

## 8. 权限、安全与风控

- SaaS 介绍页和公开套餐允许匿名访问；
- 创建组织要求登录，并继续执行现有手机号验证、创建额度和试用资格限制；
- 查看组织订阅需要 `subscriptions.subscription_view` 或 owner 权限；
- 自助购买、续费、升级、发票资料和发票申请需要 `subscriptions.subscription_manage` 或 owner 权限；
- 企业版销售辅助规则必须由后端校验，不能只靠前端隐藏购买按钮；
- 所有金额和权益仍由服务端根据当前可售版本计算；
- 客户端支付成功不能直接修改订阅；
- 埋点不得包含手机号、订单支付报文、税号或其他敏感字段；
- 企业线索联系方式只用于明确的销售跟进，按最小权限展示。

## 9. 错误与恢复

| 场景 | 产品行为 |
| --- | --- |
| 手机号未验证 | 跳转验证，成功后恢复创建组织动作 |
| 创建额度已满 | 展示现有限制，并提供进入已有组织或处理组织所有权的路径 |
| 无试用资格 | 允许创建组织并进入免费版，明确说明原因 |
| 创建组织失败 | 保留表单内容和已选项，允许重试 |
| 未绑定微信小程序身份 | 原地完成绑定并恢复支付，不返回登录页 |
| 支付取消 | 保留订单，提供继续支付和更换套餐 |
| 支付成功但回调延迟 | 自动轮询；超时进入“支付确认中”，后台继续对账 |
| 待支付订单被新订单替代 | 明确展示旧订单已关闭，使用最新订单继续支付 |
| 试用或订阅到期 | 回落免费版，保留历史数据，超额新增受限 |
| 配额达到上限 | 展示当前用量、上限和可恢复能力的目标套餐 |
| 企业线索提交失败 | 保留填写内容并允许重试，不重复创建线索 |

## 11. 工程组织建议

小程序保持现有调用链：

```text
页面
  -> feature service/composable
  -> services/manual adapter
  -> services/openapi 生成客户端
  -> Django API/domain service
```

建议新增或调整的前端职责：

- 公开 SaaS 介绍与套餐展示页面；
- 创建中介组织向导；
- 试用工作台激活任务组件；
- 订阅套餐对比与状态展示组件；
- 支付确认和支付成功页面；
- 企业版联系销售表单；
- SaaS 漏斗事件封装。

页面和 feature 不直接导入 OpenAPI 生成客户端，不直接复制订阅、试用、配额和订单状态规则。

## 12. 交付批次

### 第一期：获客与入驻

- “我的”页中介入口；
- 公开 SaaS 介绍页和公开套餐接口；
- 登录/手机号验证后的动作恢复；
- 创建组织向导；
- 创建成功后自动切换中介端；
- 试用状态、剩余天数和激活任务工作台；
- 套餐描述、展示说明和真实功能标签补齐。

完成标志：一个没有组织的新用户可以从介绍页进入，完成手机号验证、创建组织，并看到专业版试用和第一项激活任务。

### 第二期：转化与交付

- 套餐额度、功能、用量和推荐信息；
- 免费版购买按钮修复；
- 标准版/专业版上下文 CTA；
- 企业版销售辅助购买限制；
- 微信小程序身份绑定；
- 支付状态轮询、支付确认中和支付成功页；
- 发票文件、驳回说明和必要资料体验完善。

完成标志：试用用户可选择标准版或专业版并完成支付，页面自动确认权益已经生效。

### 第三期：留存与企业销售

- 用量接近上限和到期提醒；
- 小程序订阅通知深链；
- 企业销售线索和后台跟进状态；
- SaaS 漏斗事件和转化报表；
- 续费、升级和回落免费版的移动端体验收口。

完成标志：系统可以解释用户在哪一步流失，并能分别承接自助续费和企业销售线索。

## 13. 测试与验收

### 13.1 后端

- 公开套餐只返回公开上架版本和允许展示的字段；
- 企业版销售辅助购买规则不能通过直接调用订单接口绕过；
- 手机号验证、组织创建额度和试用资格规则保持不变；
- 激活里程碑按组织隔离并从真实业务事实计算；
- 微信身份绑定冲突不产生重复账号；
- 订单轮询、支付回调、重复回调和主动对账保持幂等；
- 试用到期回落免费版并保留超额历史数据；
- 销售线索权限、幂等和敏感字段展示正确。

### 13.2 小程序

- 新用户从 SaaS 介绍页完成登录、手机验证和组织创建；
- 创建组织成功后自动进入正确组织的中介工作台；
- 三个激活任务状态、深链和完成刷新正确；
- 免费版不出现购买按钮；
- 标准版和专业版首购、续费、升级文案与后端结果一致；
- 短信或密码登录用户绑定微信后恢复原订单；
- 支付成功、支付取消、回调延迟和订单被替代均有明确恢复路径；
- 企业版只显示联系销售；
- 发票文件可直接查看或下载，驳回原因可见；
- H5 与微信小程序都完成关键状态验证，微信支付在开发者工具或真机验证。

### 13.3 端到端验收场景

至少覆盖：

1. 新中介首次打开介绍页，验证手机号，创建门店，获得试用，完成房源、协作和带看/签约任务，购买专业版；
2. 独立中介创建个人工作空间，试用后购买标准版；
3. 短信登录用户创建订单，绑定微信小程序身份后继续支付；
4. 用户微信支付成功但回调延迟，前端进入确认中，后台对账后恢复为已开通；
5. 用户取消支付后继续支付同一有效订单；
6. 试用到期未购买，组织回落免费版且历史数据保留；
7. 企业客户提交销售需求，后台能够看到并更新跟进状态；
8. 临近到期用户通过小程序通知进入续费页并完成续费。

## 14. 完成标准

本设计完成实现需同时满足：

- 陌生中介能够理解产品价值并找到免费试用入口；
- 无组织用户能够自助创建组织并进入中介端；
- 符合资格的组织能够明确感知 14 天专业版试用；
- 试用工作台推动用户完成真实业务激活，而非只浏览功能；
- 套餐页展示真实权益、用量、推荐理由和正确购买动作；
- 标准版、专业版完成小程序自助支付和权益交付闭环；
- 企业版完成销售线索交接，不允许普通自助购买；
- 支付取消、支付确认延迟、无微信绑定和到期回落都有恢复路径；
- SaaS 漏斗可以定位从曝光到续费的主要流失节点；
- 不引入第二套组织、订阅、支付、权限或租赁业务状态事实。
