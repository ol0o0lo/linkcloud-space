# 团队任务统计卡视觉细化设计

## 背景

团队任务页 `/dashboard/rental/workbench/tasks` 顶部已有四张可点击统计卡，用于展示全部任务、进行中、24 小时内到期和已逾期，并联动下方列表筛选。

当前卡片使用整圈语义色边框、左侧通高色条和较强的激活描边。功能明确，但卡片细节较少，蓝、绿、橙、红四种颜色占比过大，与页面其余白色卡片及工作台的冷静蓝灰视觉不够协调。

本次只细化统计卡的结构、颜色、装饰、交互状态和响应式表现，不改变统计口径、筛选映射、接口请求或列表行为。

## 已确认方向

- 使用浅色“冷静精细型”卡片，不采用深色仪表盘。
- 四张卡保持独立布局，不合并成一体化面板。
- 卡片增加装饰细节，但装饰保持低对比，不抢核心数字。
- 语义色只用于局部强调，不再使用整圈彩色边框。
- 不展示趋势、涨跌、百分比或进度条等现有接口无法支持的数据。
- 卡片比视觉预览稿更紧凑，桌面端最小高度为 `176px`。
- 保留整张卡片可点击并联动列表筛选的现有行为。

## 页面结构与组件边界

继续复用 `frontend_admin/src/pages/team-operations/tasks/index.tsx` 中的 `summaryMetrics` 数据和卡片遍历结构，不新增后端字段。

每个统计项仍由以下现有信息驱动：

- `key`：筛选映射和选中态判断。
- `label`：中文指标名称。
- `value`：统计数量。
- `description`：指标口径说明。
- `icon`：语义图标。
- `tone`：局部语义色。

前端仅补充固定的展示元数据，例如英文眉标、两位序号和简短操作提示。这些内容在页面局部定义，不进入接口或领域模型。

卡片仍使用原生 `button` 语义，保留 `aria-label`、`aria-pressed`、键盘焦点和现有点击处理函数。

## 卡片信息层级

单张卡片从上到下分为四层。

### 1. 顶部识别区

- 左侧为 34px 的圆角图标容器。
- 图标容器使用对应语义色的极浅背景、细描边和轻量阴影，形成克制的光晕感。
- 图标右侧显示小型英文眉标和中文状态短语，例如 `IN PROGRESS / 执行状态`。
- 右上角显示 `01`–`04` 的低对比序号，用于建立四张卡的连续节奏。

英文眉标属于装饰性辅助信息，不替代中文标签；窄屏空间不足时优先隐藏英文眉标。

### 2. 核心数据区

- 中文指标名称使用次级标题样式。
- 数量作为视觉核心，使用等宽数字外观和 34px 的粗体字号。
- 数量后增加“项”单位，字号与颜色均弱于数字。
- 数量始终显示现有统计值；加载中继续复用现有 `Statistic` 的加载表现，不先显示误导性的零值。

### 3. 口径说明区

保留一行简短说明：

- 全部任务：当前筛选条件下的全部任务。
- 进行中：当前仍在执行、尚未结束的任务。
- 即将到期：未来 24 小时到期，不包含已逾期。
- 已逾期：已超过截止时间，需要尽快处理。

说明最多两行，超出时省略，不能撑高单张卡片。

### 4. 底部交互区

- 使用细分隔线与上方内容区分。
- 未选中卡显示“筛选任务”和右箭头。
- 当前选中卡显示“当前筛选”和勾选图标。
- 底部动作只是整张卡片点击行为的视觉提示，不创建新的嵌套按钮。

## 颜色与装饰

### 基础颜色

- 卡片主体使用从白色过渡到极浅冷灰的低对比渐变。
- 默认边框使用主题的次级边框色。
- 默认阴影使用低透明度蓝灰阴影，与下方列表卡片保持同一视觉体系。
- 文字继续使用 Ant Design 主题 token，保证亮色和潜在主题切换下的可读性。

### 局部语义色

- 全部任务：主蓝。
- 进行中：低饱和青绿。
- 24 小时内到期：琥珀色。
- 已逾期：低饱和红色。

语义色只出现在：

1. 顶部渐变短色带。
2. 图标与图标浅色底。
3. 中文短语旁的小短线。
4. 底部状态圆点和箭头容器。
5. 右下角的小型点阵装饰。

不再使用整圈彩色边框或左侧通高色条，避免四张卡形成过强的彩虹分割。

### 装饰元素

- 顶部短色带位于卡片内部，两侧留白，不贯穿整张卡宽度。
- 右上角使用两圈低透明度椭圆弧线，增强空间层次。
- 右下角使用小范围点阵，只作为视觉收尾。
- 图标容器使用内描边和轻量语义色阴影。
- 装饰元素均设置为不可交互、不可读的纯视觉内容，并从无障碍树中隐藏。

装饰不能模拟图表、趋势或进度，不得让用户误以为点阵、色带长度或弧线代表业务数据。

## 交互状态

### 默认态

- 中性细边框、白色背景和轻阴影。
- 局部语义色帮助识别指标，不使整张卡染色。

### 悬停态

- 边框轻微向当前指标色靠拢。
- 阴影略增强，卡片最多上移 1px。
- 遵循 `prefers-reduced-motion` 时取消位移。

### 选中态

- 使用极浅主蓝渐变背景与主蓝细边框。
- 右上角增加小型蓝色选中角标和白色勾选。
- 底部文字改为“当前筛选”。
- 选中态统一使用主蓝表达“界面选择”，不把绿、橙、红同时当作选择色，避免状态色和交互色混淆。

### 键盘焦点

- 使用清晰的主蓝外轮廓和间距，与悬停态区分。
- 焦点轮廓不能被卡片的 `overflow` 裁切。

### 加载与错误

- 统计请求加载时保持卡片尺寸稳定，避免数字加载导致布局跳动。
- 统计请求失败继续使用页面现有警告提示；卡片区域不增加新的局部错误交互。
- 列表请求与统计请求继续保持相互独立，统计失败不能阻止列表使用。

## 尺寸与响应式

### 桌面端

- 四列网格保持不变。
- 单卡最小高度为 `176px`，不使用预览稿中的 230px 大卡尺寸。
- 内边距为 16px，卡片间距为 16px。
- 图标、弧线、点阵和序号按紧凑比例缩小。

### 中等宽度

- 1100px 以下改为两列。
- 两列时允许口径说明完整显示，但卡片高度仍保持一致。

### 手机端

- 优先使用两列紧凑布局，减少四张统计卡形成过长页面。
- 隐藏英文眉标、序号和点阵，保留图标、中文名称、数量、单位和选中态。
- 说明压缩为一行；底部交互提示可只保留箭头或勾选图标。
- 359px 以下降为单列，不产生横向滚动。

## 数据流与实施范围

数据流保持不变：

1. 当前 Tab 决定使用任务管理汇总或我的任务汇总。
2. `summaryMetrics` 将接口结果映射为四项展示数据。
3. 点击卡片调用现有 `selectManagedMetric` 或 `selectAssignmentMetric`。
4. 筛选状态更新后，统计卡选中态与下方筛选控件继续使用同一状态来源。

实施预计只涉及：

- `frontend_admin/src/pages/team-operations/tasks/index.tsx`：增加有限的展示包装和固定元数据。
- `frontend_admin/src/pages/team-operations/tasks/styles.ts`：重做统计卡视觉、状态和响应式规则。
- `frontend_admin/src/pages/team-operations/tasks/index.test.tsx`：在结构变化影响测试时更新断言，并保留点击筛选行为覆盖。

不修改：

- 后端统计接口。
- 生成 API 客户端。
- 任务筛选规则。
- 表格、弹窗和详情抽屉业务。
- 多语言文件、`package.json` 或 `package-lock.json`。

## 验证方案

- 运行团队任务页 Vitest，确认四张卡渲染、Tab 切换和点击筛选仍正常。
- 运行 Biome/Ant Design 范围检查。
- 在浏览器中检查 1440px、1024px、768px 和 390px 宽度。
- 验证默认、悬停、选中、键盘焦点、加载和统计失败状态。
- 检查全部任务、进行中、临期和逾期的颜色与文案均匹配。
- 确认装饰元素不造成横向溢出，不遮挡点击区域，也不进入无障碍名称。
- 确认当前筛选仍可通过 `aria-pressed` 被辅助技术识别。

## 成功标准

- 四张统计卡与页面的蓝灰管理端视觉一致，不再依赖粗重彩色边框。
- 卡片比视觉预览稿紧凑，同时明显比现状更有层级和装饰细节。
- 用户可以一眼区分指标含义、数量、口径和当前选中项。
- 不新增任何无法由现有接口支持的数据展示。
- 所有现有筛选、权限、加载和错误行为保持不变。
