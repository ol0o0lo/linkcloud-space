# 团队任务页面 UI 与布局升级设计

## 背景

管理端团队任务页面位于 `/dashboard/rental/workbench/tasks`。当前页面已经具备任务管理、我的任务、新建任务、详情、取消、接受、拒绝和完成等业务能力，但整体仍以单一表格为主，缺少全局统计、组合筛选、截止风险提示和清晰的成员进度表达。

本次设计参考用户提供的任务管理界面与新建任务弹窗，采用“管理端融合型”方向：保留参考界面的信息架构和操作效率，同时使用现有 Ant Design、antd-style 和项目主题 token，避免做成与其他管理端页面割裂的独立视觉系统。

## 目标

1. 为“任务管理”和“我的任务”分别提供准确的任务概况统计。
2. 支持统计卡点击后联动筛选任务列表。
3. 补齐状态、优先级、所属团队、截止状态和关键词组合筛选。
4. 强化任务说明、成员进度、截止风险和状态的视觉层级。
5. 优化新建任务弹窗的字段组织、权限表达和提交反馈。
6. 保留现有权限、任务状态推进、深链接详情和通知行为。
7. 在桌面端提升信息密度，同时保证窄屏下可用。

## 非目标

- 不新增任务编辑功能。
- 不新增“优先处理”面板或运营指挥台模块。
- 不展示“较昨日变化”等缺少历史统计依据的指标。
- 不增加真实头像字段；本期使用姓名首字或首字母头像。
- 不修改任务领域模型，不新增数据库 migration。
- 不重构团队任务以外的公告、通知或工作台模块。

## 已确认的设计决策

- 采用“管理端融合型”视觉方向。
- 顶部指标随 Tab 切换。
- “即将到期”定义为未来 24 小时内到期，且不包含已经逾期的任务。
- 统计卡可以点击并联动列表筛选。
- 允许新增只读统计接口并扩展现有列表查询参数。
- 不新增任务编辑能力。
- 页面不加入额外的“优先处理”区域。
- Tab 与“新建任务”按钮不放入 `Card title`。

## 页面整体结构

页面从上到下分为三个独立区域：

1. 页面工具栏。
2. 统计卡区域。
3. 筛选与任务表格卡片。

### 页面工具栏

- 左侧使用 `Segmented` 切换“任务管理”和“我的任务”。
- 右侧显示“新建任务”主按钮。
- 工具栏是页面内容的一部分，不使用 `Card title` 或 `Card extra`。
- 无任务管理权限时隐藏“新建任务”，并只展示“我的任务”选项。

### 统计卡区域

桌面端使用四列网格，窄屏改为两列。统计卡采用白色背景、轻边框和左侧状态色，避免参考图中过强的渐变与光晕。

“任务管理”指标：

1. 全部任务。
2. 进行中。
3. 24 小时内到期。
4. 已逾期。

“我的任务”指标：

1. 待接受。
2. 进行中。
3. 24 小时内到期。
4. 已逾期。

统计卡交互规则：

- 点击卡片后应用对应的状态与截止状态组合，并清除上一个统计卡产生的组合。
- 当前卡片使用边框和轻量背景高亮。
- 点击“全部任务”只清除统计卡产生的状态或截止条件，保留团队、优先级和关键词筛选。
- “我的任务”的“待接受”卡片应用 `pending` 状态条件。
- “进行中”卡片在任务管理中对应任务 `active` 状态，在我的任务中对应分配 `in_progress` 状态。

具体映射：

- 任务管理“全部任务”：清除 `status` 和 `dueState`。
- 任务管理“进行中”：`status=active`，清除 `dueState`。
- 任务管理“24 小时内到期”：`status=active`、`dueState=due_soon`。
- 任务管理“已逾期”：`status=active`、`dueState=overdue`。
- 我的任务“待接受”：`status=pending`，清除 `dueState`。
- 我的任务“进行中”：`status=in_progress`，清除 `dueState`。
- 我的任务“24 小时内到期”：清除 `status`、设置 `dueState=due_soon`。
- 我的任务“已逾期”：清除 `status`、设置 `dueState=overdue`。

## 筛选区

筛选区位于任务表格卡片顶部，与表格使用分隔线区分。

两个 Tab 均提供：

- 状态。
- 优先级。
- 所属团队。
- 截止状态。
- 标题或说明关键词。
- 重置。

截止状态只提供与本次需求直接相关的选项：

- 全部。
- 24 小时内到期。
- 已逾期。

筛选行为：

- 筛选条件变化后分页回到第一页。
- 两个 Tab 各自保存筛选条件和页码；切换回来后恢复原状态。
- 重置只作用于当前 Tab。
- 搜索输入和已生效关键词分离，按搜索或回车后发起查询，避免每次输入字符都请求接口。
- 统计卡与筛选控件使用同一状态来源，避免界面显示与请求参数不一致。

## 任务管理表格

任务管理面向任务创建者和具备管理权限的用户。

### 列结构

1. **任务**：标题为主文本，说明为单行省略的次级文本。
2. **团队 / 创建人**：团队名称为主文本，创建人为次级文本；组织级任务显示“组织级任务”。
3. **执行成员**：使用 `Avatar.Group` 展示姓名首字头像，附带已完成人数或当前进度摘要。
4. **优先级**：普通、重要、紧急使用语义色标签。
5. **截止时间**：展示绝对时间；24 小时内到期或已逾期时增加相对时间提示。
6. **状态**：进行中、已完成、已取消使用语义色标签；活动任务如果已逾期，展示“已逾期”风险状态。
7. **操作**：保留详情；具备权限且任务仍在进行中时提供取消操作。

创建人不单独占用一列，以减少横向宽度。成员悬停或点击后可查看姓名和各自分配状态。

### 操作规则

- “详情”打开现有详情 Drawer。
- 整行不设置点击行为，避免与链接、下拉菜单和文本选择冲突。
- “取消任务”使用二次确认。
- 不显示“编辑”入口。
- 没有任务管理权限的记录不显示管理操作。

### 默认排序

- 任务管理保持按创建时间倒序。
- 后续如需增加显式排序控件，另行设计，不纳入本次范围。

## 我的任务表格

我的任务面向任务执行成员。

### 列结构

1. **任务**：标题与说明。
2. **所属团队**：团队名称或组织级任务，并显示创建人。
3. **优先级**。
4. **截止时间**：包含剩余时间或已逾期时长。
5. **状态**：待接受、进行中、已完成、已拒绝、已取消。
6. **操作**：根据分配状态展示详情和可执行动作。

### 状态操作

- `pending`：详情、接受、拒绝。
- `in_progress`：详情、完成。
- 其他终态：仅详情。

### 默认排序

依次按以下规则排序：

1. 已逾期的未完成任务优先。
2. 截止时间升序。
3. 同一截止时间下按紧急、重要、普通排序。
4. 未设置截止时间的任务放在有截止时间的任务之后。

## 响应式设计

- 统计卡在桌面端四列，中等和窄屏两列。
- 筛选控件允许换行；搜索框优先占据较宽空间。
- 表格保留横向滚动作为兜底。
- 窄屏优先保留任务、截止时间、状态和操作，团队、创建人和成员详情可进入详情 Drawer 查看。
- 弹窗双列字段在窄屏下变为单列。
- 分页与主要操作保持可见，不依赖水平滚动才能完成核心动作。

## 新建任务弹窗

弹窗标题使用“新建任务”，副标题为“为团队下发任务，明确任务目标、执行成员与截止时间”。

### 字段顺序

1. 任务标题，全宽，必填，最大 255 字符。
2. 任务说明，全宽，选填，最大 2000 字符。
3. 优先级与截止时间，桌面端并排，窄屏单列。
4. 所属范围。
5. 下发成员。

### 优先级

- 使用三档可见选择：普通、重要、紧急。
- 默认普通。
- 使用语义色强化辨识，但保持选中态和键盘操作清晰。

### 所属范围

- 普通团队任务通过团队选择器设置 `team_id`。
- 具备组织级任务管理权限的用户额外看到“组织级任务”开关。
- 开启组织级任务后隐藏或禁用团队选择器，并提交 `team_id = null`。
- 无组织级权限时不展示该开关。
- 只有一个可用范围时自动预填，但仍向用户展示当前范围。
- 切换团队或组织级状态时清空已选成员，避免提交不属于当前范围的成员。

### 下发成员

- 使用多选控件。
- 选项显示姓名和账号，已选项可使用姓名首字头像。
- 至少选择一名成员。
- 选择团队前禁用成员选择器。
- 组织级任务从当前组织成员中选择，团队任务只展示团队成员。
- 保留说明：“每位成员都会收到独立任务，可分别接受、拒绝和完成。”

### 提交反馈

- 主按钮使用“创建并下发”。
- 提交中禁用关闭、取消和重复提交。
- 创建成功后关闭弹窗、重置表单，并刷新当前 Tab 列表与统计。
- 创建失败时保留输入内容。
- 字段校验错误就近显示；通用接口错误走项目统一错误提示。

## 后端接口设计

本次不修改模型，只新增两个只读统计端点并扩展列表查询参数。

### 任务管理统计

`GET /api/team-operations/tasks/summary/`

查询参数：

- `team_id`。
- `priority`。
- `keyword`。

响应结构：

```json
{
  "total": 128,
  "active": 45,
  "due_soon": 18,
  "overdue": 7
}
```

统计基于用户可见的 `_task_qs(request)`，继续复用现有组织和团队权限范围。

### 我的任务统计

`GET /api/team-operations/task-assignments/summary/`

查询参数：

- `team_id`。
- `priority`。
- `keyword`。

响应结构：

```json
{
  "pending": 12,
  "in_progress": 8,
  "due_soon": 3,
  "overdue": 1
}
```

统计只包含当前用户的任务分配。

### 24 小时和逾期定义

以服务端当前时间 `now` 为准：

- `due_soon`：未完成且 `now < due_at <= now + 24 hours`。
- `overdue`：未完成且 `due_at < now`。
- 两者互斥。
- 任务管理中的未完成任务指 `WorkTask.status == active`。
- 我的任务中的未完成分配指状态为 `pending` 或 `in_progress`。

### 列表参数扩展

`GET /api/team-operations/tasks/` 新增：

- `due_state=due_soon|overdue`。

保留现有：

- `team_id`。
- `status`。
- `priority`。
- `keyword`。
- `mine`。

`GET /api/team-operations/task-assignments/` 新增：

- `team_id`。
- `priority`。
- `keyword`。
- `due_state=due_soon|overdue`。

保留现有：

- `status`。
- `overdue`，用于兼容已有调用；新页面统一使用 `due_state`。

`TaskAssignmentOut` 增加只读的 `creator` 用户摘要，值来自关联任务的创建人，用于“我的任务”列表展示；不新增数据库字段。

“我的任务”默认排序调整为：逾期未完成优先、截止时间升序、优先级降序、创建时间倒序，未设置截止时间的记录放在最后。

所有分页接口继续使用 `page` 和 `page_size`，响应保持 `{ items, total, page, page_size }`。

## 前端状态与数据流

两个 Tab 分别维护独立状态：

```ts
type TaskListFilters = {
  status?: string;
  priority?: TaskPriority;
  teamId?: number;
  dueState?: 'due_soon' | 'overdue';
  keyword?: string;
};
```

每个 Tab 同时维护：

- 当前页码。
- 筛选条件。
- 搜索输入值。

React Query 行为：

- 列表查询键包含组织、Tab、页码和全部筛选条件。
- 统计查询键包含组织、Tab、团队、优先级和关键词，不包含卡片产生的状态或截止条件。
- 列表与统计并行请求。
- 点击统计卡只更新 `status` 或 `dueState`。
- 创建或状态推进成功后统一失效任务列表、任务分配、任务统计和日常工作台相关查询。
- URL 中的 `task_id` 和 `assignment_id` 深链接行为保持不变。

统计不受当前卡片状态条件影响，避免选择“已逾期”后其他卡片全部变为零；但团队、优先级和关键词会影响统计，使指标与当前业务范围一致。

## 加载、空状态和错误处理

### 加载

- 首次加载统计时显示四张统计骨架卡，避免布局跳动。
- 列表使用表格加载状态。
- 切换筛选时保留上一批数据，避免表格闪空。

### 空状态

- 没有任何任务时展示创建引导；有权限时提供“新建任务”。
- 筛选后无结果时提示调整条件，并提供“清除筛选”。
- 我的任务为空时不显示创建引导，提示当前没有分配给用户的任务。

### 错误处理

- 统计请求失败只影响统计卡，显示紧凑错误状态和重试，列表继续工作。
- 列表失败在表格区域展示错误和重试，不清空筛选。
- 单行操作仅锁定当前操作，避免阻塞整页。
- 创建失败保留表单。
- API 的 401、403、CSRF 和统一 envelope 继续交给项目请求层处理。

## 权限规则

- 继续使用 `getTeamOperationsCapabilities()` 判断组织级和团队级任务管理范围。
- 无任务管理权限时只允许查看“我的任务”。
- “新建任务”仅对具备至少一个任务管理范围的用户显示。
- 组织级开关仅对 `task_organization_manage` 为真的用户显示。
- 团队选择器只展示用户可管理的团队。
- 后端统计和列表必须继续使用现有权限查询集，前端隐藏不作为安全边界。

## 测试设计

### 后端测试

- 任务管理统计只包含用户可见范围。
- 我的任务统计只包含当前用户分配。
- 24 小时边界：恰好等于 `now + 24 hours` 计入即将到期。
- `due_at == now` 不计入即将到期；已经早于 `now` 计入逾期。
- 已完成、已取消、已拒绝的记录不计入即将到期或逾期。
- 团队、优先级和关键词正确影响统计与列表。
- `due_state` 与状态条件组合正确。
- 无权限用户不能通过统计端点看到其他团队数据。
- 分页结构保持项目约定。

### 前端测试

- 权限决定 Tab 和“新建任务”按钮可见性。
- 两个 Tab 展示正确的四个指标。
- 点击统计卡更新列表参数并回到第一页。
- “全部任务”只清除卡片筛选，不清除其他条件。
- Tab 切换保留各自筛选和页码。
- 搜索、团队、优先级和截止状态参数正确传递。
- 统计失败不阻塞列表，列表失败不清空筛选。
- 组织级开关权限、团队禁用和成员清空行为正确。
- 创建成功后刷新统计与列表。
- 详情深链接关闭后不重复打开。
- 现有取消、接受、拒绝和完成操作继续可用。

### 浏览器验证

- 桌面宽度下统计卡、筛选区和表格对齐。
- 窄屏下统计卡两列、筛选换行、弹窗单列。
- 长标题、长说明、多成员和无截止时间场景不破坏布局。
- 任务管理和我的任务均验证空状态、加载状态和接口错误状态。

## 成功标准

- 用户进入页面后可以立即判断任务总体规模、执行情况和截止风险。
- 用户可以通过统计卡或筛选控件快速定位目标任务。
- 任务管理与我的任务的操作入口符合各自角色，不出现无效或越权操作。
- 新建任务的所属范围与成员关系表达清晰，不再依赖隐含的特殊下拉选项。
- 页面视觉与公告消息及其他管理端页面保持一致。
- 现有任务流程、权限和深链接行为不回退。
