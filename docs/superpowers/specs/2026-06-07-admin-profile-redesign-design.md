# Admin 个人中心重构设计

## 背景

当前 admin 端个人中心位于 `frontend_admin/apps/web-antdv-next/src/views/_core/profile/`，已经具备基本资料、安全、密码、通知等能力，但整体更像纵向堆叠的设置页，缺少明确的“个人中心 / 个人资料管理”主轴。

本次改版目标不是继续强化“状态驾驶舱”，而是把页面重做为一个以资料展示和资料管理为核心的单页个人中心，同时保留安全和通知能力在同一页内可达。

## 设计目标

- 页面首先传达“这是我的个人中心”，而不是一组后台设置表单。
- 页面主轴是个人资料管理，安全和通知是附属管理模块。
- 默认以展示态为主，进入编辑时只在当前区块内切换，不把整页变成大表单。
- 保留现有后端接口和核心行为，优先重构布局、信息层级和区块边界。
- 视觉上保持 Vben / Ant Design 的后台气质，只借用参考图的信息组织方式。

## 非目标

- 不新增新的账户领域模型。
- 不重写 MFA、Passkey、第三方账号绑定、通知偏好的业务规则。
- 不把个人中心做成品牌主页或公开展示页。
- 不拆成多个子路由页面。

## 设计结论

采用“单页资料总览 + 分区卡片”的结构，页面顺序固定为：

1. 顶部个人名片区
2. 基本信息区
3. 账户安全区
4. 通知设置区

其中：

- 顶部个人名片区负责建立身份感和主操作。
- 基本信息区是页面第一主区块。
- 账户安全区整合原有安全能力和密码能力，密码不再作为与资料并列的独立大区块。
- 通知设置区保留在同页底部，作为次要管理区块。

## 页面结构

### 1. 顶部个人名片区

顶部区域采用后台风格的高质量信息卡，而不是营销式 hero。内容包括：

- 头像
- 显示姓名
- 用户名或账号标识
- 简短说明文案或固定副标题
- 邮箱
- 手机号与验证状态
- 时区
- 加入时间

该区域右侧只保留 1 到 2 个主操作，优先为：

- `编辑资料`
- `上传头像` 或 `查看安全设置`

顶部区域不承载复杂设置、不放大段统计、不展示大量次级按钮。

### 2. 基本信息区

基本信息区是页面视觉和功能上的第一主区块，默认展示以下内容：

- 姓名
- 邮箱
- 手机号
- 时区
- 加入时间
- 头像相关状态（如适合）

展示态采用双列信息卡或信息行，不使用伪只读表单。点击“编辑资料”后，仅该区块切换为编辑态，支持：

- 修改姓名
- 修改时区
- 上传或移除头像

编辑完成后局部刷新并回到展示态。

### 3. 账户安全区

账户安全区负责整合原有：

- 两步验证 / TOTP
- 恢复码
- Passkey
- 第三方账号绑定
- 登录密码

该区块默认展示为摘要卡集合，每张子卡只说明当前状态和下一步操作，不直接展开成长表单。建议子卡为：

- `两步验证`
- `Passkey`
- `第三方账号`
- `登录密码`

子卡可在区块内部展开、进入局部操作态，或触发已有交互组件，但不再单独占用一个与基本信息同级的大页面区块。

### 4. 通知设置区

通知设置区保留在页面底部。默认展示摘要信息，例如：

- 共有多少通知分类
- 站内信开启多少项
- 邮件开启多少项

进入编辑态后，再展开每个通知分类的站内信 / 邮件开关列表。通知区继续采用单项即时保存，不引入额外保存总按钮。

## 交互规则

### 展示态优先

页面默认应是清晰可读的展示态。用户先看到“我是谁”和“我的资料状态”，再决定是否编辑。

### 单区块编辑锁

同一时间只允许一个区块进入编辑态：

- 编辑基本信息时，安全区和通知区保持只读。
- 在安全区处理某个子卡时，基本信息区和通知区保持只读。
- 通知区进入编辑态时，其余区块保持只读。

这样可以延续当前页面已有的稳定性，避免多个区块同时改动导致状态混乱。

### 局部反馈

保存成功、失败、加载中等反馈都在当前区块内部闭环，不做整页级别的状态切换。区块外的内容应尽量保持稳定，避免操作一个模块时导致整页闪动。

## 数据与组件边界

页面仍由 `profile/index.vue` 作为装配层，负责：

- 拉取当前用户资料
- 拉取安全相关数据
- 拉取通知偏好
- 组织顶部名片与摘要展示所需的派生数据
- 协调当前处于编辑态的区块

建议组件边界调整为：

- `profile/index.vue`
  页面装配和状态协调。
- `profile/components/profile-hero.vue`
  顶部个人名片区。
- `profile/sections/profile-basic-section.vue`
  基本信息展示与编辑。
- `profile/sections/profile-security-section.vue`
  安全区及其内部子卡。
- `profile/sections/profile-notification-section.vue`
  通知摘要与编辑。

如果实现阶段不方便大幅迁移文件，也需要至少在逻辑层保持上述职责边界，避免继续把过多派生逻辑塞进页面根组件。

## 错误处理

- 基本信息保存失败：只在基本信息区显示错误，不影响其他区块。
- 安全相关操作失败：错误保留在对应安全子卡内，例如 TOTP、Passkey、第三方账号、密码。
- 通知开关保存失败：只回退当前项并提示当前项错误。
- 顶部名片区不承载高风险交互，只展示状态与主入口，降低出错面。

## 测试边界

本次重构至少覆盖以下验证点：

- 顶部个人名片区正确渲染核心资料和主操作。
- 基本信息区展示态与编辑态切换正确。
- 编辑锁规则生效，同一时间只有一个区块可编辑。
- 账户安全区正确整合两步验证、Passkey、第三方账号、密码四类入口与状态。
- 通知区摘要与编辑态切换正确，单项即时保存行为保持不变。
- 在移动端窄屏下，页面顺序、间距和按钮布局仍可用。

## 实施约束

- 优先复用现有 API 和已有行为。
- 先做页面骨架和区块重构，再做视觉细节打磨。
- 新布局必须兼容当前 admin 的设计语言，不引入过于品牌化的视觉表达。
