## 1. 背景

`frontend_miniprogram/` 已具备 uni-app、Vue 3、TypeScript、Pinia、Wot UI v2、路由拦截、请求封装和 OpenAPI 生成代码，但现有正式页面仍主要是 unibest 模板内容。当前认证代码调用模板接口，运行环境也未连接本项目 Django API，因此无法形成真实业务闭环。

后端已经提供以下基础能力：

- allauth app 端登录、会话校验、退出和手机号验证码登录；
- `wechat_miniprogram` provider token 登录；
- `X-Session-Token` 移动端认证；
- `X-Org-Slug` 组织上下文；
- 当前用户、组织切换、组织导航能力；
- 公开房源列表、详情、筛选；
- 用户收藏列表、收藏和取消收藏。

本次先完成可运行的产品外壳，再在该外壳上接通公开房源列表、详情、筛选和收藏链路。

## 2. 目标

### 2.1 产品外壳

- 模式基础设施支持游客、个人、房东和组织四种状态。
- 支持真实登录、会话恢复、退出和登录后恢复原操作。
- 本阶段开放租客、房东和组织模式切换，并记住上次有效选择；房东模式必须有仍有效的房东关系。
- 支持组织切换和组织权限能力加载。
- 使用固定五槽位 TabBar profile 生成底部导航，模块注册表负责功能入口、路由权限和分包归属。
- 提供启动失败、无权限、内容不存在和网络异常页面。
- 未完成的模块不进入正式导航，不使用空白业务页面填充产品外壳。

### 2.2 公开找房链路

- 游客可以搜索、筛选、分页查看全部公开房源。
- 游客和登录用户都可以查看公开房源详情。
- 登录用户可以收藏和取消收藏房源。
- 游客触发收藏时按需登录，登录成功后自动继续收藏。
- “我的找房”本阶段展示真实收藏列表，并正确处理已失效收藏。

## 3. 非目标

- 本阶段不实现完整的找房需求、看房记录和沟通流程。
- 本阶段不实现组织业务模块、组织待办和组织消息业务。
- 本阶段不实现订阅支付整改，但需要保证新增外壳不会继续依赖现有模板认证。
- 本阶段不新增移动端后端菜单协议，组织导航使用现有能力接口与前端模块注册表组合完成。
- 本阶段不重构无关的 uni-app 模板、图表示例和生成代码。

## 4. 已确认的产品决策

### 4.1 登录策略

- 本地存在会话时自动尝试恢复。
- 本地没有会话时保持游客，不自动创建账号。
- 游客可以直接浏览公开房源。
- 收藏、我的找房、组织工作空间等受限操作按需触发登录。
- 微信小程序使用微信登录并允许后端自动创建账号。
- H5 使用手机号验证码登录为主，邮箱密码登录为备用。
- 登录成功后恢复原页面和待执行操作。

### 4.2 模式策略

- 登录用户默认保持个人模式。
- 组织成员从“我的”或模式切换器主动进入组织工作空间。
- 上次有效模式和组织保存在本地；恢复时必须重新校验权限。
- 公开房源深链始终保持游客或个人模式，不继承组织上下文。

### 4.3 未完成模块策略

- 未完成模块保留在模块注册表中，但标记为不可用。
- 不可用模块不出现在 Tab 槽位内的业务入口、首页入口和功能列表中。
- 不为未完成业务创建“敬请期待”式正式页面。

## 5. 总体架构

采用“轻量应用内核 + 前端模块注册表”。

### 5.1 会话模块

职责：

- 保存 `X-Session-Token`；
- 执行微信小程序登录、H5 手机验证码登录和邮箱密码登录；
- 校验现有会话；
- 退出并清除本地认证状态；
- 保存和消费登录后的目标路由与待执行操作。

会话模块不负责组织选择、导航生成和房源数据。

### 5.2 应用上下文模块

职责：

- 获取公开应用配置；
- 获取当前用户；
- 获取用户可进入的组织列表；
- 获取并校验当前用户的房东账号关系；
- 保存当前模式、当前组织和当前房东联系人；
- 校验并恢复上次模式；
- 在组织或房东关系失效时回退到个人模式。

移动端启动上下文由以下数据组合，不单独依赖 `/api/app-context/` 恢复登录用户：

1. `/api/app-context/`：公开站点配置；
2. `/api/allauth/app/v1/auth/session`：allauth 会话有效性；
3. `/api/users/me/`：当前用户和员工标记；
4. `/api/organizations/switch-list/`：可用组织及当前/主组织标记；
5. `/api/house/landlord/relationships/`：当前用户有效房东关系，用于校验和预留房东模式；
6. `/api/access/navigation/`：当前组织导航能力。

### 5.3 导航模块

职责：

- 读取当前模式、认证状态和组织权限能力；
- 从模块注册表筛选当前可见模块；
- 选择当前模式的 TabBar profile，并生成首页和业务入口；
- 判断目标路由是否允许访问；
- 权限变化后重新计算导航。

### 5.4 业务页面状态

房源查询条件、分页、详情和筛选状态保留在对应页面或房源业务组合函数中，不进入全局应用上下文 Store。收藏待执行动作由会话模块保存，登录成功后只消费一次。

## 6. 请求边界

### 6.1 allauth 请求

allauth app API 返回自己的 `{ data, meta, status }` 结构，不使用 Django Ninja 的成功信封解析器。单独提供认证请求适配器，负责：

- `X-Session-Token` 请求头；
- allauth 错误数组与流程状态解析；
- 从 `meta.session_token` 保存或更新会话；
- 区分未认证、需要验证码、表单错误和服务错误。

### 6.2 Django Ninja 请求

业务 API 继续使用项目现有 `{ code, message, data }` 成功信封解析器，并作以下调整：

- 已登录请求添加 `X-Session-Token`；
- 仅组织模式添加 `X-Org-Slug`；
- 公开请求显式禁用组织上下文；
- `401` 交给会话模块处理；
- `403` 交给路由/错误状态处理；
- 网络错误不清除会话。

### 6.3 公开请求约束

以下接口始终按公开请求执行：

- `/api/public/houses/`
- `/api/public/houses/filters/`
- `/api/public/houses/{house_id}/`

公开请求可以携带会话 Token，但不得携带 `X-Org-Slug`，从而避免组织成员查看公开房源时被组织上下文污染。

## 7. 启动与会话恢复

启动状态固定为：

1. `booting`：读取本地会话和上次模式；
2. `anonymous`：没有会话或会话已失效；
3. `authenticated`：会话有效，用户资料已加载；
4. `ready`：模式、当前上下文和导航均已校验；
5. `failed`：网络或服务错误导致初始化无法完成。

启动流程：

1. 获取公开应用配置；
2. 读取本地 `session_token`；
3. 没有 Token 时进入游客模式；
4. 有 Token 时调用 allauth session 端点；
5. 会话有效后并行获取当前用户、组织切换列表和房东关系列表；
6. 校验上次模式；
7. 组织模式下校验组织仍存在，并加载组织导航能力；
8. 根据模块注册表生成导航；
9. 恢复目标路由。

会话校验返回 `401` 时清除本地 Token 并进入游客模式。网络错误时进入可重试的启动失败状态，不把用户误判为退出登录。

## 8. 登录流程

### 8.1 微信小程序

1. 调用 `uni.login({ provider: 'weixin' })` 获取 code；
2. POST `/api/allauth/app/v1/auth/provider/token`；
3. provider 使用 `wechat_miniprogram`；
4. `token.id_token` 使用微信 code；
5. 从返回 `meta.session_token` 保存会话；
6. 重新执行启动上下文加载；
7. 恢复目标页面并消费待执行操作。

### 8.2 H5 手机验证码

1. 用户输入国家区号和手机号；
2. POST `/api/users/auth/app/code/request/` 请求验证码；
3. 保存流程返回的 `meta.session_token`；
4. POST `/api/allauth/app/v1/auth/code/confirm` 并携带流程 Token；
5. 登录成功后刷新会话上下文；
6. 恢复目标页面和待执行操作。

### 8.3 H5 邮箱密码

1. POST `/api/allauth/app/v1/auth/login`；
2. 从返回 `meta.session_token` 保存会话；
3. 处理普通表单错误和 allauth 后续流程；
4. 本阶段若账号要求尚未实现的 MFA 或额外验证，显示明确提示并停止恢复动作，不伪装为登录成功。

### 8.4 登录后恢复

待恢复信息包含：

- 目标路由；
- 路由参数；
- 可选动作类型；
- 动作载荷；
- 创建时间。

本阶段支持的动作类型只有 `favorite-house`。待执行动作登录成功后最多执行一次；成功、明确失败或超时后都从本地移除。

## 9. 模式与工作空间

模式类型：

- `visitor`：未登录用户；
- `personal`：已登录的个人模式；
- `landlord`：已选择有效房东账号关系；本阶段尚未开放生产入口；
- `organization`：已选择有效组织；

恢复规则：

- 未登录时强制为 `visitor`；
- 登录且没有有效持久化模式时为 `personal`；
- 持久化房东模式只有在对应房东关系仍有效时恢复；
- 持久化组织模式只有在组织仍存在时恢复；
- 无效模式统一回退到 `personal`；
- 公开房源深链临时按 `personal/visitor` 展示，不改写用户保存的上次工作空间。

组织切换后需要：

1. 更新当前组织 slug；
2. 重新请求组织导航能力；
3. 重新生成导航；
4. 当前路由失权时进入组织工作台或无权限页。

## 10. 模块注册表

每个业务模块至少声明：

- `key`：稳定模块键；
- `title`：显示名称；
- `route`：入口路由；
- `modes`：允许出现的模式；
- `requiresAuth`：是否要求登录；
- `enabled`：本阶段是否已实现；
- `capability`：组织模式需要的导航能力；
- `order`：显示顺序。

TabBar 不再由业务模块拼接。构建期固定声明首页、业务、动态、消息和我的五个主包槽位，运行时按模式切换显示语义。

本阶段启用业务模块：

- 公共/个人：首页、找房、我的找房、我的；
- 组织：工作台、我的；

本阶段注册但不启用：

- 公共/个人：消息；
- 房东：概览、房源、租约、消息和我的；
- 组织：业务、待办、消息及具体组织业务模块；

组织工作台属于产品外壳页面，展示真实当前空间、用户身份和已启用入口，不展示虚构业务统计。

## 11. 页面与路由

### 11.1 公共/个人页面

- 首页：模式摘要、找房入口和最新公开房源入口；
- 找房：搜索、筛选、排序和分页列表；
- 房源详情：媒体、价格、户型、位置、标签、发布方和收藏；
- 我的找房：收藏列表；
- 我的：用户资料、登录入口、模式切换、组织切换和退出。

### 11.2 组织页面

- 工作台：当前组织、成员身份和根据能力开放的模块入口；
- 我的：复用统一“我的”页面，并显示当前组织与切换入口。

### 11.3 系统页面

- 登录；
- 手机验证码确认；
- 模式/工作空间选择；
- 启动失败；
- 无权限；
- 内容不存在。

路由元数据至少包含 `moduleKey`、`modes`、`requiresAuth` 和 `publicContext`。路由拦截器不再只使用静态黑白名单判断。

## 12. 动态导航

底部导航从 TabBar profile 计算，业务入口从模块注册表计算，两者不在页面内重复维护。

由于 uni-app 的 TabBar 页面必须在 `pages.json` 中静态声明且微信最多允许五项，生成配置固定为五个主包槽位；运行时自定义 TabBar 只替换标题、图标和模式语义。普通详情、登录和错误页继续使用非 TabBar 路由。未启用模块不生成槽位内业务入口，也不进入路由权限判断。

最终启用的 TabBar：

- 游客：`首页、找房、我的`；
- 租客：`首页、找房、我的找房、消息、我的`；
- 房东：`概览、房源、租约、消息、我的`；
- 组织管理：`工作台、业务、待办、消息、我的`；

规则：

- 游客进入“我的找房”时触发登录；
- 组织模块根据 `/api/access/navigation/` 能力筛选；
- 当前模式变化后重建 TabBar，并跳转到第一个稳定槽位；
- 当前路由不属于新模式时不得继续停留；
- 未启用模块不进入导航。

## 13. 错误与空状态

### 13.1 启动失败

- 显示简短错误原因；
- 提供重新加载；
- 不清除可能仍有效的会话；
- 连续失败仍停留在可恢复页面。

### 13.2 未认证

- 保存目标路由和可选动作；
- 跳转登录；
- 登录成功后恢复；
- 用户取消登录时返回原公开页面，不执行动作。

### 13.3 无权限

- 显示当前空间无权访问；
- 提供返回、切换组织和回到个人模式；
- 不暴露后端权限键和内部错误详情。

### 13.4 内容不存在

- 房源不存在或已下架时显示内容不存在；
- 提供返回找房列表；
- 从收藏进入时允许返回我的找房。

### 13.5 网络异常

- 列表保留当前筛选条件；
- 详情保留已加载数据；
- 收藏操作失败时回滚本地收藏状态；
- 提供重试，不自动退出登录。

### 13.6 空列表

空列表属于正常业务状态，不跳错误页。找房空结果提供清除筛选；收藏为空提供前往找房入口。

## 14. 公开房源列表

列表接口：`GET /api/public/houses/`。

支持参数：

- `keyword`
- `province`
- `city`
- `district`
- `min_rent`
- `max_rent`
- `min_area`
- `max_area`
- `bedrooms`
- `living_rooms`
- `decoration`
- `has_elevator_access`
- `tags`
- `publisher_slug`
- `sort`
- `page`
- `page_size`

页面行为：

- 关键词由用户确认或防抖后请求；
- 筛选面板确认后从第一页重新加载；
- 排序变化从第一页重新加载；
- 只发送有值的可选参数，不发送 `null`；
- 新请求返回前保留当前列表；
- 旧请求晚于新请求返回时不得覆盖新筛选结果；
- 分页响应使用 `{ items, total, page, page_size }`。

## 15. 公开房源筛选

筛选项接口：`GET /api/public/houses/filters/`。

筛选页面包含：

- 地区；
- 租金区间；
- 面积区间；
- 户型；
- 标签；
- 电梯；
- 装修；
- 排序。

后端筛选项当前直接提供省、市、区数组，不包含级联关系。本阶段按独立选择展示，不在前端推断不存在的行政区级联关系。

## 16. 房源展示规则

列表、详情和收藏统一使用共享格式化函数：

- `bedrooms === 1 && living_rooms === 0`：显示“单间”；
- `bedrooms === 1 && living_rooms === 1`：显示“一室一厅”；
- 其他户型按现有中文室厅格式展示；
- 缺失值不拼接错误的“零室零厅”。

媒体展示优先使用后端解析后的公开 URL。没有图片时使用统一房源占位视觉，不使用远程第三方占位图。

## 17. 房源详情与收藏

详情接口：`GET /api/public/houses/{house_id}/`。

详情页展示：

- 图片和视频入口；
- 月租、押金、面积和户型；
- 楼栋、小区和地址；
- 朝向、装修、电梯和楼层；
- 标签和公开描述；
- 发布组织信息；
- 收藏状态与操作。

收藏状态查询：

`GET /api/users/me/favorite/?target_type=house&target_id={house_id}`。

收藏：

`PUT /api/users/me/favorite/?target_type=house&target_id={house_id}`。

取消收藏：

`DELETE /api/users/me/favorite/?target_type=house&target_id={house_id}`。

游客点击收藏时不先改变本地收藏状态。登录成功并收到收藏接口成功响应后再显示已收藏。

## 18. 我的找房

本阶段使用收藏列表接口：

`GET /api/users/me/favorite/?target_type=house&page={page}&page_size={page_size}`。

展示优先使用收藏响应中的 `display`：

- `title`
- `subtitle`
- `cover_url`
- `description`
- `tags`
- `facts`

`available === false` 或 `target === null` 时显示“房源已下架或不可用”，不允许进入详情，但允许取消收藏。

## 19. 状态与并发规则

- 模式切换操作串行执行，防止重复加载不同组织能力。
- 会话恢复只允许一个进行中的初始化任务。
- 收藏操作对同一房源加进行中锁，防止重复点击。
- 找房查询为每次条件生成请求序号，仅最新请求可以更新页面状态。
- 待执行登录动作只能消费一次。
- 本地持久化数据只保存 Token、模式、组织 slug 和待恢复动作，不持久化权限能力和房源列表。

## 20. 测试设计

核心状态逻辑拆成纯 TypeScript 模块，测试遵循先失败、再实现、再重构。

需要覆盖：

- 无会话解析为游客模式；
- 无有效持久化模式时登录用户解析为个人模式；
- 有效组织模式可以恢复；
- 已移除组织回退个人模式；
- 公开路由不附加 `X-Org-Slug`；
- 组织业务请求附加当前组织 slug；
- 未启用模块不进入导航；
- 组织能力为假时对应模块不可见；
- 登录后待收藏动作只执行一次；
- 房源空筛选字段不进入请求参数；
- 新查询结果不会被旧请求覆盖；
- 单间和一室一厅展示规则正确；
- 已失效收藏不可进入详情但可以取消收藏。

不新增大型测试框架。优先使用 Node 22 内置测试能力验证纯 TypeScript 逻辑；页面和跨端行为通过类型检查、构建及浏览器验收覆盖。
