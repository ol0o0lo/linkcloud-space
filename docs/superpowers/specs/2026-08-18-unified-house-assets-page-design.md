# 房源资产统一管理页设计

## 背景

管理端当前将“房源列表”和“项目楼栋”作为房源资产菜单下的两个平级页面。用户维护房源时，需要在房源、项目、楼栋之间频繁跳转；房源列表虽然字段完整并支持行内编辑，但项目与楼栋只作为普通筛选项存在，没有形成稳定的资产上下文。

本设计将两者整合为一个“房源资产”页面：项目和楼栋负责定位管理范围，房源宽表负责完成日常维护。地图查看和房态同步继续作为独立能力，但从统一页面保留当前范围跳转。

## 目标

- 使用一个页面承接房源、项目和楼栋的日常管理，减少平级页面跳转。
- 以房源列表为高频工作区，项目和楼栋作为左侧资产导航器。
- 支持项目数量较多时的服务端分页、搜索和滚动加载。
- 展开单个项目时一次呈现该项目全部楼栋，不向用户暴露楼栋分页。
- 保留房源字段的独立列、横向滚动、列设置、服务端排序和行内快捷编辑。
- 支持从侧栏快速新建、编辑项目、楼栋和房源。
- 保持筛选、分页、排序和当前项目/楼栋范围可刷新、可前进后退、可分享链接。
- 尽量复用现有 API、表格、表单、媒体弹窗、实体预览和删除检查能力。

## 非目标

- 不修改房源、项目或楼栋的数据模型关系。
- 不将房态、租金、户型等业务筛选放入资产侧栏。
- 不把地图和房态同步完整嵌入主表格。
- 不把 `extra` 扩展字段铺成通用列表列；扩展字段继续在完整资料编辑中维护。
- 不取消项目详情、楼栋详情和房源详情路由。
- 不在本次设计中引入拖拽调整项目或楼栋归属。

## 核心决策

采用“资产导航器 + 房源宽表”结构：

- 左侧侧栏选择全部房源、项目、楼栋或独立楼栋。
- 右侧始终展示当前范围内的房源列表。
- 项目和楼栋的完整资料维护放进同页管理抽屉。
- 房源字段尽量保持独立列，通过横向滚动解决宽度问题，不将业务字段过度合并。
- 房源列固定在左侧，房态和操作列固定在右侧。
- 点击右侧编辑图标后，当前房源整行进入快捷编辑状态。

## 路由与菜单

### 主路由

统一页面继续使用现有房源列表路径：

```text
/rental/properties/list
```

房源资产菜单只保留一个主入口“房源资产”。原“项目楼栋”菜单项移除，旧路径：

```text
/rental/properties/estates
```

重定向到：

```text
/rental/properties/list?manage=structures
```

这样旧书签和已有入口仍可到达完整项目楼栋管理能力。

### URL 状态

统一页面使用以下 query parameters：

- `estate_id`：当前项目范围。
- `building_id`：当前楼栋范围；存在时优先于 `estate_id`。
- `keyword`：房源表关键词。
- `status`：房态筛选。
- `ordering`：服务端排序。
- `page`：房源页码。
- `manage=structures`：打开项目楼栋管理抽屉。
- 现有实体预览和编辑抽屉参数继续沿用各自约定。

切换项目或楼栋时将房源页码重置为第 1 页。浏览器前进、后退和刷新均从 URL 恢复状态。

## 页面结构

页面由四个明确模块组成：

1. `HouseAssetsPage`：页面编排、租户选择保护和 URL 状态。
2. `AssetNavigator`：项目、楼栋和独立楼栋导航。
3. `HouseAssetTable`：房源宽表、筛选、排序、分页和快捷编辑。
4. `StructureManagementDrawer`：完整项目楼栋管理。

侧栏和房源表分别维护自己的请求状态；局部加载或失败不遮挡另一个模块。

## 资产导航侧栏

### 基本结构

侧栏按以下顺序展示：

1. 搜索项目或楼栋。
2. 全部房源。
3. 最近使用和星标固定范围。
4. 项目与楼栋树。
5. 独立楼栋。
6. 管理结构、地图查看、房态同步入口。

侧栏只决定“在哪个资产范围工作”。房态、租金、户型、房东等筛选继续放在房源表工具栏。

### 项目加载

- 项目列表固定使用 `page_size=30`。
- 项目列表滚动到底后请求下一页，不显示传统页码。
- 项目搜索由服务端完成，不把全部项目加载到浏览器后过滤。
- 项目响应需要直接包含楼栋数量和房源状态汇总，禁止通过前端一次拉取全部楼栋计算项目数量。

### 楼栋加载

- 展开项目时才请求该项目楼栋。
- 单个项目固定使用 `page_size=500` 加载楼栋。
- 如果项目楼栋总数超过单次上限，前端静默请求后续页并合并；用户始终看到一个完整楼栋列表，不感知分页。
- 楼栋结果按项目缓存；重复展开不重新请求。
- 新建、编辑或删除楼栋后，只刷新受影响项目的楼栋缓存和数量。

### 独立楼栋

未绑定项目的楼栋归入“独立楼栋”，不称为“未归属房源”。独立楼栋区支持查看全部独立楼栋、新建独立楼栋以及选择具体楼栋。

### 点击规则

- 展开箭头只负责展开或收起。
- 点击项目名称选择项目范围，右侧展示该项目全部房源。
- 点击楼栋名称选择楼栋范围，右侧展示该楼栋房源。
- 点击搜索结果时自动定位、展开必要父节点并选择目标范围。

### 最近使用和星标

- 自动记录最近访问的 5 个项目或楼栋范围。
- 用户可以把常用范围固定为星标。
- 清除最近记录不删除星标。
- 删除项目或楼栋后自动清理对应记录。

### 行级快捷操作

平时显示楼栋数或房源数，鼠标悬停后显示操作按钮：

- 项目：新建楼栋、编辑项目、更多。
- 楼栋：新建房源、编辑楼栋、更多。
- 更多菜单承接查看详情、地图定位和删除检查等低频操作。

在项目行新建楼栋时自动预选该项目；在楼栋行新建房源时自动预选该楼栋。

### 状态保持

记住以下用户状态：

- 侧栏宽度，允许在 240～360px 之间调整。
- 侧栏是否收起。
- 已展开项目。
- 侧栏滚动位置。
- 星标范围和最近访问。

从房源详情返回统一页面时恢复原资产范围、房源页码和侧栏位置。

### 收起与窄屏

- 桌面端允许完全收起侧栏。
- 收起后在页面标题区域提供项目/楼栋范围选择器。
- 视口宽度不低于 1200px 时侧栏常驻；768～1199px 时默认收起并通过按钮打开；低于 768px 时使用全宽临时 Drawer。
- 房源表继续横向滚动，房源列和操作列保持可见。

## 房源宽表

### 字段策略

房源字段尽量独立展示，允许横向滚动。默认字段按二级表头分组，但不合并业务字段。

#### 固定列

- 左侧：复选框、房源。
- 右侧：房态、操作。

#### 位置归属

- 所属项目：从楼栋项目关系派生，只读。
- 所属楼栋：实际可编辑字段。

更换楼栋后，所属项目自动更新，避免项目与楼栋不一致。

#### 户型与空间

- 户型。
- 卫生间。
- 厨房。
- 阳台。
- 建筑面积。
- 套内面积。
- 楼层。
- 朝向。
- 装修。

房型展示继续复用共享格式化逻辑：`bedrooms === 1` 且 `living_rooms === 0` 时显示“单间”。

#### 通行条件

- 楼栋电梯：从楼栋派生，只读，房源是否有电梯统一以该字段为准。

#### 租赁信息

- 挂牌租金。
- 押金。
- 房东。

#### 发布与管理资料

- 图片视频。
- 标签。
- 对外描述。
- 内部备注。

`public_description` 已存在于 `HouseOut`，但当前房源列表未展示。新版将其作为默认显示的独立列，与内部备注保持不同语义。

#### 状态与操作

- 房态。
- 操作。

### 列设置

- 所有字段均可在列设置中显示、隐藏、调整顺序和固定。
- 新版首次进入时默认显示上述全部独立字段，允许用户自行隐藏低频列。
- 用户偏好继续使用现有用户级表格列持久化机制。
- 新页面使用新的偏好版本键，避免旧页面列顺序直接污染新的二级表头结构。
- 列密度继续使用 ProTable/EditableProTable 现有能力。

### 排序

沿用现有服务端排序契约和 URL 同步：

- 房源。
- 户型。
- 所属楼栋。
- 挂牌租金。
- 押金。
- 房东。
- 房态。

媒体、标签、对外描述、内部备注和操作列不提供排序。

## 房源快捷编辑

### 进入编辑

- 操作列固定在右侧。
- 点击铅笔图标后当前行进入编辑状态。
- 延续现有多行独立编辑能力；每行分别保存或取消。
- 编辑行使用轻量背景高亮，行高尽量稳定。

### 字段编辑

- 短文本、数字和枚举字段直接在单元格内编辑。
- 户型继续使用房、厅组合编辑器。
- 楼栋和房东使用服务端搜索、分页加载的 Select。
- 标签使用可创建标签的选择器。
- 楼栋电梯和所属项目保持只读。

### 图片视频

- 图片视频单元格显示图片和视频数量。
- 点击后打开现有媒体编辑弹窗。
- 弹窗修改写入当前行草稿，不立即单独提交。
- 点击当前行“保存”后与其他字段统一提交。
- 取消该行编辑时同时丢弃媒体草稿。

### 长文本

对外描述和内部备注保持独立列：

- 浏览态单行截断并提供完整内容提示。
- 编辑态点击单元格后使用较宽的 Popover/TextArea。
- 文本编辑不撑高整行。

### 编辑保护

存在未保存行时：

- 暂停项目/楼栋切换。
- 禁用房源筛选、排序和分页。
- 提示用户先保存或取消当前编辑。

保存成功后：

- 更新当前行。
- 保持当前分页、选择范围和横向滚动位置。
- 刷新房源列表和受影响的项目/楼栋数量。

保存失败时：

- 保留全部草稿。
- 保留横向滚动位置。
- 在当前行显示错误并允许重试。

## 项目楼栋管理抽屉

“管理结构”打开同页全高大尺寸 Drawer，并将 `manage=structures` 写入 URL。

抽屉复用当前项目楼栋页面能力：

- 项目列表和楼栋列表支持搜索与分页。
- 新建、编辑项目。
- 新建、编辑楼栋。
- 地址和地图位置维护。
- 图片、标签维护。
- 删除检查和关联资源提示。

侧栏的快捷编辑直接打开相同表单组件，不复制另一套表单实现。当前 `estates/index.tsx` 中的列表、表单和删除逻辑应按职责拆成可复用组件，再由管理抽屉编排。

关闭抽屉时移除 `manage` 参数，但保留房源范围、筛选和分页状态。

## 底部跨功能入口

### 地图查看

从侧栏进入地图时携带当前范围：

- 项目范围携带 `estate_id`。
- 楼栋范围携带 `building_id`。
- 返回统一页面时恢复原 URL。

### 房态同步

进入房态同步时携带当前项目或楼栋上下文。同步完成后返回统一页面，并刷新当前范围的房源和数量。

## API 与数据流

### 复用接口

- `GET /api/house/estates/`：项目分页和关键词搜索。
- `GET /api/house/buildings/`：按项目加载楼栋和楼栋搜索。
- `GET /api/house/houses/`：按 `estate_id`、`building_id`、房态、关键词和排序查询房源。
- 项目、楼栋、房源现有创建、更新、详情和删除检查接口。

### 必要调整

1. 项目列表响应改为 `list[EstateInventoryOut]`，其中 `EstateInventoryOut` 在 `EstateOut` 基础上补充：
   - `building_count`。
   - `counts.total`。
   - `counts.vacant`。
   - `counts.listed`。
   - `counts.rented`。
   - `counts.renovating`。

   列表查询直接通过数据库注解返回，避免前端 N+1 查询或全量拉取楼栋。

2. 楼栋列表增加确定的独立楼栋过滤参数：

   ```text
   without_estate=true
   ```

   `without_estate=true` 与 `estate_id` 互斥。

3. 项目/楼栋搜索可以并行请求现有两个列表接口，由前端按“项目、楼栋”分组展示，不额外增加统一搜索接口。

4. 房源列表前端增加 `estate_id` 状态和请求参数；后端现有接口已经支持。

5. 房源表增加对 `public_description` 的展示和快捷编辑；后端现有 `HouseOut` 与 `HousePatchIn` 已支持。

### 查询缓存

查询键按以下边界组织：

```text
['house', 'asset-navigator', 'estates', org, page, keyword]
['house', 'asset-navigator', 'buildings', org, estateId]
['house', 'asset-navigator', 'independent-buildings', org]
['house', 'houses', org, page, keyword, status, estateId, buildingId, ordering]
```

项目或楼栋变更后只失效对应范围和房源列表，不清空整个房源域缓存。

## 加载、空状态与错误处理

### 加载

- 项目列表首次加载显示侧栏骨架。
- 展开项目只在该节点下显示局部加载状态。
- 房源表保持独立 loading 状态。
- 已有房源结果在翻页或切换排序时保留到新请求返回，减少闪烁。

### 空状态

- 无项目：提示新建项目或独立楼栋。
- 项目无楼栋：在项目节点下提供“新建楼栋”。
- 楼栋无房源：右侧提供“新建房源”，自动预选当前楼栋。
- 搜索无结果：分别提供新建项目或楼栋入口。

### 错误

- 项目列表失败：侧栏显示重试，不遮挡房源表。
- 单个项目楼栋加载失败：错误和重试只显示在该项目节点下。
- 房源列表失败：沿用统一请求错误处理和表格重试。
- 无效或无权限的 `estate_id`、`building_id`：清除无效范围并回到全部房源。
- 媒体弹窗上传失败：保留已成功的草稿，不提交当前行。

## 组件边界

组件按以下职责拆分：

```text
rental/houses/
  index.tsx                         页面编排
  HouseAssetTable.tsx               房源宽表
  HouseQuickEditCells.tsx           快捷编辑单元格
  HouseMediaInlineEditorModal.tsx   现有媒体弹窗复用或迁移
  useHouseAssetUrlState.ts           URL 状态

rental/assets/
  AssetNavigator.tsx                侧栏外壳
  AssetTree.tsx                     项目/楼栋树
  AssetSearch.tsx                   服务端搜索结果
  StructureManagementDrawer.tsx    管理抽屉
  EstateFormDrawer.tsx              项目表单
  BuildingFormDrawer.tsx            楼栋表单
```

实现使用上述目录与组件边界：导航器不负责房源业务筛选，房源表不负责项目楼栋 CRUD，表单组件不依赖具体入口页面。

## 测试范围

### 后端

- 项目列表分页、关键词搜索和库存汇总正确。
- 项目列表不会对每个项目产生独立统计查询。
- 楼栋列表按 `estate_id` 过滤。
- `without_estate=true` 只返回独立楼栋。
- `without_estate` 与 `estate_id` 同时传入时返回校验错误。
- 房源列表按 `estate_id`、`building_id` 与现有筛选组合工作。
- `public_description` 快捷更新正确。

### 前端单元测试

- 项目滚动加载下一页。
- 展开项目后加载并缓存全部楼栋。
- 超过单页上限时静默续页合并。
- 点击箭头只展开，点击名称才切换范围。
- 搜索结果按项目和楼栋分组，并能定位父节点。
- 独立楼栋正确加载。
- URL 正确同步项目、楼栋、筛选、排序和分页。
- 旧项目楼栋路径重定向并打开管理抽屉。
- 房源宽表包含独立字段、二级表头和固定操作列。
- 点击编辑图标进入整行编辑。
- 图片视频弹窗修改写入行草稿，保存或取消行为正确。
- 对外描述和内部备注使用独立编辑入口。
- 存在未保存行时禁止切换范围、筛选、排序和分页。

### 端到端验收

- 从全部房源选择项目、展开楼栋并进入指定楼栋房源。
- 从楼栋行快捷新建房源，楼栋自动预选。
- 编辑房源多个字段和媒体后保存，列表保持当前位置。
- 从侧栏打开项目或楼栋编辑，保存后数量和名称及时刷新。
- 从旧项目楼栋链接进入统一页面管理抽屉。
- 从地图或房态同步返回后恢复原资产范围。

## 验收标准

- 用户无需离开房源资产页面即可定位项目、楼栋并维护房源。
- 项目数量较多时首屏不会加载全部项目和楼栋。
- 展开单个项目后可以一次看到其全部楼栋，不出现楼栋分页器。
- 房源字段保持独立，表格可以横向滚动，首尾关键列始终可见。
- 点击右侧编辑图标可以快捷编辑当前房源字段，图片视频通过弹窗编辑。
- 项目、楼栋和房源的快捷新增会继承当前上下文。
- 项目楼栋完整管理能力通过同页抽屉提供，原路由保持兼容。
- 页面刷新、返回和链接分享不会丢失当前资产范围、筛选、排序和分页。
